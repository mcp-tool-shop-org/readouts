### Faucet / test-network helpers (fundWallet) · `service` · · n/a ✓
Built-in helpers in the official SDKs that auto-fund a wallet with test XRP on public test networks. In xrpl.js, Client.fundWallet() creates or funds a wallet (typically ~1000 XRP) and auto-detects the correct faucet server for testnet/devnet/AMM-devnet/Hooks testnet; xrpl-py exposes generate_faucet_wallet(). They make spinning up a working dev account a one-liner, with custom faucet host/path options for non-default networks.
- **Chain:** xrpl-mainnet · **Maturity:** stable · **Use:** recommended
- **Key fields / API:** {"install": "Provided by xrpl.js / xrpl-py", "current_version": "xrpl.js 5.0.0 fundWallet / xrpl-py 5.0.0 generate_faucet_wallet", "key_apis": "const {wallet} = await client.fundWallet(); client.fundWallet(existingWallet, {faucetHost, faucetPath}); xrpl.wallet.generate_faucet_wallet(client)", "default_faucet": "faucet.altnet.rippletest.net/accounts (testnet) — auto-detected for known networks"}
- **Gotchas:** Faucets are test-only — there is NO mainnet faucet; calling fundWallet against a mainnet client will fail. Faucets are rate-limited and best-effort, so do not rely on them in CI loops without backoff. On custom/non-standard networks you must pass faucetHost/faucetPath explicitly because auto-detection only covers the well-known public networks.

### XRPL Wallet & seed handling (Wallet class) · `concept` · · n/a ✓
The wallet/seed abstraction exposed by the official SDKs (Wallet in xrpl.js and xrpl-py, Seed/KeyPair in xrpl4j) that turns a seed/secret into a signing identity: it holds the keypair, derives the classic address, and signs transactions. As of the 2026 5.0 releases the default signing algorithm is inferred from the seed prefix (ed25519 seeds start with sEd; secp256k1 otherwise), a breaking change builders must understand to derive the correct address.
- **Chain:** xrpl-mainnet · **Maturity:** stable · **Use:** recommended
- **Key fields / API:** {"install": "Provided by xrpl.js / xrpl-py / xrpl4j (no separate package)", "current_version": "xrpl.js 5.0.0 Wallet / xrpl-py 5.0.0 Wallet", "key_apis": "Wallet.generate(), Wallet.fromSeed(seed, {algorithm}), Wallet.fromSecret, wallet.sign(tx), wallet.classicAddress; xrpl-py xrpl.wallet.Wallet / generate_faucet_wallet", "secret_formats": "family seed (s...), ed25519 seed (sEd...), mnemonic/secret-numbers (separate helpers)"}
- **Gotchas:** Breaking in the 5.0 line: the default algorithm is now seed-prefix-inferred — a seed previously decoded as secp256k1 by default may now derive a different address if you don't pass the algorithm explicitly. Never hard-code or commit seeds/secrets; treat them like private keys. The fundWallet/generate_faucet_wallet flow only applies to test networks. For high-value or regulated use, prefer external signing/HSM over in-process seeds.
