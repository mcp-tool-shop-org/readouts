## The new lanes

### `structured-output` — make the local LLM-crew reliable
The constrained-decoding layer is **CPU-side** (an Earley/FSM logits processor computes a token bitmask each step), so **Blackwell-readiness flows from the inference engine, not the grammar lib** — pick your serving engine first, then bolt on the backend. Stack for this rig: **XGrammar** (`pip install xgrammar`, Apache-2.0, native Windows wheel) — the default backend baked into vLLM/SGLang/TensorRT-LLM/MLC-LLM, <40µs/token, and XGrammar-2's cross-grammar cache is the win for an agent crew doing many short tool-call grammars; **llama.cpp GBNF + `format:` JSON-schema** for pure-local Ollama/llama.cpp (zero install, fully native); **Instructor + Pydantic** as the app-layer wrapper (retry+validate around any provider, composes on top). **The takeaway maps onto our own EXTERNAL_VERIFIER standard:** constrained decoding guarantees a *grammatically* valid artifact, never a *semantically correct* one — a 100%-valid-JSON tool-call can still call the wrong tool. Grammar (XGrammar/GBNF) = deterministic floor; Pydantic validators = cheap second check; a different-family model verifies semantics on top. (Jsonformer is deprecated — no commits since 2023.) [catalog/structured-output.md](../../catalog/structured-output.md)

### `speech-engines` — game VO/audio (the runtime layer, not the models)
**The C/C++/ONNX/GGML engines are the Blackwell happy path** — native Windows, no PyTorch, no sm_120 wheel roulette: **whisper.cpp** (ASR default, builds clean with `-DGGML_CUDA=1 -DCMAKE_CUDA_ARCHITECTURES=120`), **sherpa-onnx** (one C++ engine for ASR+TTS+VAD+diarization, ships Windows CUDA + DirectML binaries — the in-engine integration backbone for Godot/UE5), **Piper** (tiny real-time TTS, GPLv3 → keep as a separate process), **Kokoro-82M** (Apache-2.0, #1 TTS Arena, the shippable-VO pick). **Load-bearing catch: faster-whisper's default `int8_float16` CRASHES on the 5090** (CUBLAS_STATUS_NOT_SUPPORTED, CTranslate2 INT8 padding bug) — run `compute_type="float16"`. **License gate:** XTTS-v2 weights are **non-commercial** (previz/temp VO only); ship with Kokoro/Piper. The PyTorch stack (WhisperX, NeMo/Parakeet, XTTS, Kyutai) inherits the whole Blackwell tax (cu128 nightlies + often a Hopper `get_device_capability()→(9,0)` spoof). [catalog/speech-engines.md](../../catalog/speech-engines.md)

### `profiling-bench` — the measurement layer (and the recipe-proving foundation)
Install order on this rig: **nvitop** (live VRAM/util, NVML-only, native Windows) → **llama-bench** (ships in every CUDA llama.cpp build; pp512/tg128 JSON) + **AIPerf** (NVIDIA's supported GenAI-Perf successor) for OpenAI-server TTFT/ITL → **Nsight Systems 2026.3 + Nsight Compute** (native Windows, sm_120 — but you MUST enable *Control Panel → Developer → Manage GPU Performance Counters → Allow all users* or every read fails ERR_NVGPUCTRPERM) → **torch.profiler** + **py-spy** → **Arize Phoenix / OpenLLMetry / Langfuse** for agent/RAG traces. **Takeaway: DCGM is Linux-only** — there is no native-Windows datacenter-telemetry path, so the Prometheus/Grafana fleet pattern doesn't apply; **Nsight Systems is the only way to turn "this recipe is faster" into a measured fact** on the 5090 (CUDA-graphs 8× shows as kernel-launch-gap collapse on the timeline; the CUDA-13 MMQ regression shows as slower GEMM kernels). This lane is what makes a future recipe-proving wave possible. [catalog/profiling-bench.md](../../catalog/profiling-bench.md)

## The deepen lanes — and wave 3's sharpest finding

### `attention-kernels` (+4): sm_120 is a *third* ISA, proven
The wave-1/2 "sm_120 ≠ datacenter Blackwell" warning is now demonstrated hard: **FlashMLA, DeepGEMM, TLX Block Attention, and trtllm-gen FMHA all HARD-FAIL on the 5090** — they emit `tcgen05`/`wgmma` instructions that exist only on **SM100 (B200) and SM90 (Hopper)**; sm_120 (desktop Blackwell) needs its own kernels nobody has shipped. **The only way to run DeepSeek-V3.2/V4 MLA on a 5090 today is FlashInfer's XQA backend** (auto-selected on sm_120, ~20 tok/s decode — not FlashMLA's 410 TFLOPS). For diffusion (the studio's day-job), **SageAttention via the prebuilt Blackwell wheel + ComfyUI-KJNodes "Patch Sage Attention" node** is the win; SA3 FP4 needs PR patches to compile on Windows. Net rule: **"Blackwell support" is worthless unless it says sm_120.** [catalog/attention-kernels.md](../../catalog/attention-kernels.md)

### `training` (+5): ms-swift is the new install-first
**ms-swift** (Apache-2.0, v4.2.3, Windows-native) runs GRPO/DPO/SFT single-GPU with `--use_vllm --vllm_mode colocate`, reusing the vLLM engines already in the KB — the alignment ceiling to Unsloth's QLoRA-speed floor. **open-instruct** and **SkyRL** are research-grade RLVR but WSL2-only (Ray+vLLM Linux-first). **Skip NeMo-Aligner for new work** — archived Nov 2025, superseded by NeMo-RL (wave 2). Every framework inherits PyTorch's Blackwell support, so the move is unchanged: pin a cu128 nightly FIRST, install with `--no-build-isolation`/`--no-deps`. [catalog/training.md](../../catalog/training.md)
