## Findings (the de-risking payload)

1. **Mechanic validated** end-to-end: captions read, TE LoRA trains, token learned, LoRA loads+applies, A/B measured.
2. **The #151 caption bug**, root-caused: kohya's default `caption_extension` is `.caption`, so #151 silently ignored its `.txt` captions and trained on the folder class-token — its `fronttrav` trigger never trained. **Fix: `--caption_extension .txt` and verify the log prints `read caption: N/N`.**
3. **TE training is ~free** on it/s (v1 even edged the unet-only 1.40); **regularization costs ~20–25%** (1.66 → 1.25).
4. **Gating needs contrast.** Single-style dataset + trigger-in-every-caption + no counter-examples → style learned **unconditionally** (trigger correlates, can't gate). v1 weak, v2 lost it. **Reg images restore gating** (v3) — crisp on ship/portrait, weak on the strongly-colored locomotive.
5. **The base bounds the style.** SDXL base 1.0 resists deep-blue monochrome; heavier optimization drifts to the base-expressible **grayscale engraving** and loses the cyanotype **blue**. Tension: gating (reg + steps) vs color fidelity (lighter training / stronger base). For a sellable game palette, train on a stronger commercial-safe base, not SDXL base 1.0.

## Blue-fidelity follow-up (v4–v5) — definitive

Took a run at recovering the lost blue. **Diagnostic:** v3 at LoRA strength 1.4 (vs 1.0) brings out only *slightly* more blue and stays grayscale-engraving → blue is weakly-present, not strength-recoverable → recipe, not inference. Then two runs spanning the recipe space (both dim32, 217.9 MB):

- **v4** (dim32, alpha16 = 0.5 scaling, reg `prior_loss_weight 0.5`, 600 steps): softening *both* scaling and reg to protect color **overcorrected** — color kept, but style barely imposes and gating collapses (B≈C).
- **v5** (dim32, alpha32 = 1.0 scaling = v3's scaling, **only the rank doubled** vs v3, reg pw1.0, 700 steps): ≈ v3 — strong engraving, crisply gated, **still no blue**. Doubling the LoRA rank did **not** recover the blue.

**Conclusion (5 configs v1–v5):** on SDXL base 1.0 you cannot get strong-blue + strong-style + gating at once. Low scaling (0.5: v1, v4) keeps a tint but weak style/gating; high scaling (1.0: v3, v5) gives strong style/gating but collapses to grayscale engraving; **rank is irrelevant to the blue.** The binding constraint is **SDXL base 1.0's color prior**, not the kohya recipe.

**Actionable fix:** (a) a game house-style LoRA usually needs **no gating** — train **light like v1** (alpha8/dim16, ~300 steps, no reg), keep the blue, apply via LoRA strength; (b) for a saturated palette **with** gating, **swap the base** → **Z-Image-Turbo** (it generated the cyanotype set, Apache-2.0) via kohya's **`lumina_train_network.py`** (Lumina2 arch) — the wave-8 candidate.
