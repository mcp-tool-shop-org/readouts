### llama.cpp server (llama-server) · `recommended` · production
The de-facto native-Windows LLM server and the realistic heavy-model path on this rig without WSL2. Ships official prebuilt Windows CUDA binaries (b9196 supports CUDA 13.1 / Vulkan / HIP / SYCL) so there is no compile step required, though a from-source build for sm_120 with upgraded cuBLAS avoids PTX JIT. `llama-server` exposes an OpenAI-compatible API (/v1/chat/completions, /v1/completions, /v1/embeddings, /v1/rerank). The decisive feature for 32 GB VRAM + 64 GB RAM is GGUF partial offload: set `--n-gpu-layers` to push as many layers to the 5090 as fit and let the rest run on CPU/RAM, so a model a bit over 32 GB still loads. Continuous batching exists (`--cont-batching`, `--parallel N`) but is weaker than vLLM/SGLang paged-KV under heavy concurrency. Blackwell gotcha: the CUDA-toolkit version matters — CUDA 12.8 is the proven sweet spot; CUDA 13.x MMQ kernels have crashed and can cost ~5x. Best deployed as the upstream that llama-swap launches.
- **Dev:** ggml-org (Georgi Gerganov) + community · **Type:** inference-server · **Lang:** C/C++ · **Version:** rolling (Windows CUDA prebuilt e.g. b9196, May 2026) · **Released:** 2026-05-18
- **Platforms:** windows, linux, macos · **Accelerators:** cuda, rocm, metal, vulkan, sycl, cpu · **Formats:** gguf (loads); produces nothing — consumes quantized GGUF
- **Blackwell/Win-ready:** yes · **Optimizes for:** memory · **Multi-GPU:** tensor-parallel (--split-mode, --tensor-split across GPUs); single-GPU on this rig · **Fit:** rig 5/5 · studio 5/5
- **License:** MIT — commercial: **yes**. MIT — no restrictions.

- **Speed/notes:** On RTX 5090 expect ~110+ tok/s on a 14B-class model; the load-bearing gotcha is the CUDA-toolkit trap — building/running with CUDA 13.x MMQ can crash or cost up to 5x; CUDA 12.8 + MMQ (or -DGGML_CUDA_FORCE_CUBLAS=ON on early Blackwell) is the safe Blackwell path. ### TabbyAPI (ExLlamaV3 / EXL3) · `recommended` · stable
The OpenAI-compatible server for the EXL2/EXL3 ecosystem and the throughput champion for single-GPU INT4 on this rig. start.bat auto-detects the CUDA version and installs matching ExLlamaV2/V3 + FlashAttention wheels — a genuine native-Windows path with no WSL2 required, which is rare in this lane. EXL3 (a streamlined QTIP variant from Cornell RelaxML) gives the best perplexity-per-bit available locally; the config exposes cache_mode for quantized KV (FP16/Q8/Q6/Q4 on ExLlamaV2; per-tensor k_bits,v_bits 2-8 on ExLlamaV3), draft_model_* for speculative decoding, and tensor_parallel/gpu_split for multi-GPU. Caveat: AGPL + a self-described 'hobby project, not for production servers' — perfect for a single-user local studio, but read the license before shipping it inside a product. backend: exllamav3 selects the newer kernels; EXL2/GPTQ are deprecated.

### llama-server Router Mode (llama.cpp) · `recommended` · stable
llama.cpp's built-in answer to llama-swap: a router that exposes /models, /models/load, /models/unload and forwards each request to the right model instance based on the OpenAI `model` field — no external proxy process. Point it at a folder with --models-dir (or let it auto-discover from LLAMA_CACHE), cap concurrent residents with --models-max (default 4, LRU eviction), or require explicit loads with --no-models-autoload. Per-model overrides live in a --models-preset config.ini (ctx-size, temp, etc.); global flags after the binary apply to every model. Because it is the same llama-server binary, it gets the full Blackwell story for free — build with -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=120, run with -fa and quantized KV (--cache-type-k q8_0), and you have a native-Windows multi-model router with CPU/RAM MoE offload (--n-cpu-moe) usable on the 64 GB system RAM. This is the in-lane alternative to the wave-1 llama-swap proxy and to a degree to Ollama's model management, with zero added moving parts.

### llama-swap · `recommended` · stable
A single-binary Go reverse proxy that puts ONE OpenAI/Anthropic-compatible endpoint in front of many local inference servers and hot-swaps the upstream based on the requested `model` field — load-on-demand, unload-on-idle. This is the one engine in this lane that is BOTH genuinely native-Windows (prebuilt binary + WinGet, with explicit Windows shutdown/nvidia-smi fixes in v217/v222) AND solves the real single-workstation problem: 32 GB VRAM can't hold many models at once, so you swap. Config is one YAML file mapping model names to launch commands; key knobs are `ttl` (seconds before an idle model unloads to free VRAM), `cmd`/`cmdStop` per model, and `groups` to keep a set of small models co-resident. Speaks llama.cpp's full surface including `/v1/embeddings` and `/v1/rerank|/v1/reranking|/rerank`, plus stable-diffusion.cpp and whisper.cpp endpoints, so it can front your whole local stack. Blackwell-ready because it runs nothing itself — it just launches a Blackwell-capable upstream (native llama-server, or a WSL2 vLLM). No batching/observability beyond what the upstream provides; pair with llama.cpp for native-Windows heavy lifting.
- **Dev:** mostlygeek (Benson Wong) + community · **Type:** serving-layer · **Lang:** Go · **Version:** v222 · **Released:** 2026-06-01
- **Platforms:** windows, linux, macos, freebsd · **Accelerators:** agnostic (delegates to upstream; cuda/rocm/metal/cpu/vulkan all work via the backend it launches) · **Formats:** agnostic — routes to upstreams that load gguf, safetensors, gptq, awq, exl2/exl3, etc.; itself loads nothing

### Infinity · `runner-up` · stable
A high-throughput, low-latency REST server for text embeddings, rerankers, CLIP, CLAP and ColPali — the multi-modal-retrieval alternative to TEI, MIT-licensed and cross-platform (CUDA/ROCm/CPU/Inf2/Apple-MPS). Its edge over TEI is breadth: it orchestrates multiple models at once and covers CLIP/ColPali for image-text retrieval, which is relevant to a visual-asset studio doing canon/sprite search. Built on PyTorch + optimum (ONNX/TensorRT) + CTranslate2 with dynamic batching and worker-thread tokenization. Runs on Windows via Docker/WSL2 (no first-class native build). The caveat to weigh against TEI: its last tagged release (0.0.77) was August 2025 and the cadence has slowed, whereas TEI shipped v1.9.3 in March 2026 with explicit Blackwell images — so for pure text embed/rerank prefer TEI, and reach for Infinity when you specifically need CLIP/ColPali multimodal retrieval in one server.
