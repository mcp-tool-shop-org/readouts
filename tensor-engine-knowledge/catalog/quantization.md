### NVIDIA ModelOpt (TensorRT Model Optimizer) · `recommended` · production
The production-grade PTQ/QAT front-end for NVIDIA's FP4 stack, rebranded from 'TensorRT Model Optimizer' to 'Model Optimizer' in Dec 2025. Implements SmoothQuant, AWQ, SVDQuant, double-quant and native NVFP4 (E2M1, block-16, FP8 scales) and FP8 calibration, then exports unified HF checkpoints deployable in TensorRT-LLM, TensorRT, vLLM and SGLang without re-conversion. On this rig it is the canonical way to LOCALLY produce NVFP4/FP8 weights — `pip install -U nvidia-modelopt[hf]` then `python hf_ptq.py --pyt_ckpt_path <model> --qformat nvfp4 --export_path out` — closing the loop so the 5090 isn't dependent on third-party FP4 uploads. Default calibration mixes cnn_dailymail + nemotron-post-training-dataset-v2 (128-512 samples). Accuracy-tuned variants (nvfp4_mlp_only / nvfp4_experts_only) recover quality on sensitive layers.

### llama.cpp (GGUF + llama-quantize, k-quants / i-quants / imatrix) · `recommended` · production
The universal local-inference engine and the de-facto quantizer of the open ecosystem; GGUF is the single most widely-consumed format and llama.cpp is its native runtime. Quality ladder: k-quants (Q4_K_M is the default daily driver, Q5_K_M/Q6_K when a model fully fits 32 GB) use super-blocks with per-block scales; i-quants (IQ2…IQ4_XS) push lower bit-rates by pairing codebook reconstruction with an importance matrix (imatrix) computed by llama-imatrix over a calibration corpus — IQ4_XS+imatrix is the tightest-VRAM 4-bit worth running. On the 5090 it runs native on sm_120 today; FP4 is partly here (NVFP4 core kernels merged Mar–Apr 2026, but the Blackwell tensor-core dispatch PR #22196 was still open, so stock builds get FP4 memory savings without full speedup). Windows gotchas: build for arch 120 on CUDA 12.8 (else 5x PTX-JIT penalty), pass --no-mmap to force weights into VRAM, and split with -ngl / --n-cpu-moe to spill MoE experts to the 64 GB system RAM.
- **Dev:** ggml-org (Georgi Gerganov et al.) · **Type:** runtime + quant-tool + quant-format · **Lang:** C/C++ (CUDA) · **Version:** rolling master, b89xx-series builds (NVFP4 native PR #22196 still open at writing); release tags ~daily · **Released:** 2026-05 (rolling; FP4 PRs merged Mar–Apr 2026)
- **Platforms:** windows, linux, macos (Metal), also Vulkan/SYCL/ROCm · **Accelerators:** cuda, rocm, metal, vulkan, sycl, cpu · **Formats:** GGUF (Q2_K…Q8_0 k-quants; IQ1_S…IQ4_XS i-quants w/ imatrix; legacy Q4_0/Q8_0; MXFP4 for gpt-oss-style; experimental NVFP4); converts safetensors/HF -> GGUF via convert_hf_to_gguf.py + llama-quantize
- **Blackwell/Win-ready:** yes · **Optimizes for:** portability · **Multi-GPU:** pipeline-parallel (layer split) + tensor-split; not true tensor-parallel · **Fit:** rig 5/5 · studio 5/5

### ExLlamaV3 (EXL3 format) · `recommended` · stable
An optimized quantizer+runtime that targets the single-consumer-GPU sweet spot this rig lives in. EXL3 is a streamlined variant of Cornell's QTIP using a fused Viterbi decode kernel, giving the best perplexity-per-byte available for local inference — ~3.5–4.0 bpw matches BF16 on many models, and it stays coherent at extreme low bit-rates (Llama-3.1-70B coherent at 1.6 bpw in under 16 GB). Reach for it when you have one strong GPU and want maximum capability per VRAM, with long context via quantized KV-cache; serve it through TabbyAPI for an OpenAI-compatible endpoint. Conversion needs only the HF model + a target bitrate (no separate calibration dataset wrangling like GPTQ). Windows is first-class here — the repo ships prebuilt Windows wheels and points to triton-windows; CUDA 12.4+ covers sm_120. Caveats: it consumes ONLY EXL3 (no GGUF/GPTQ interchange), the EXL3 model selection on HuggingFace is smaller than GGUF, and it is NVIDIA-only (no ROCm yet).
- **Dev:** turboderp-org (turboderp) · **Type:** runtime + quant-tool + quant-format · **Lang:** Python + CUDA · **Version:** 0.0.39 · **Released:** 2026-05-31
- **Platforms:** windows, linux · **Accelerators:** cuda · **Formats:** EXL3 (QTIP/Viterbi-coded, 2–8 bpw mixed precision); converts from HF safetensors with only an input model + target bitrate; does NOT load GGUF/GPTQ/AWQ
- **Blackwell/Win-ready:** yes · **Optimizes for:** memory · **Multi-GPU:** tensor-parallel + pipeline (auto split across GPUs) · **Fit:** rig 5/5 · studio 5/5
- **License:** MIT — commercial: **yes**. MIT — permissive; EXL3 derives from QTIP (Cornell RelaxML), also permissively licensed. No commercial restriction.
- **Best for:** Max quality-per-VRAM on a single RTX 5090 (nvidia, fit 5) ; Running a 32B at high quality with long context in 32 GB (local, fit 5) ; Fast, calibration-light quantization of HF models (local, fit 4) ; OpenAI-compatible local serving (via TabbyAPI) (server, fit 4)
- **Speed/notes:** Best quality-per-bit on a single 5090. ~3.5–4.0 bpw rivals BF16 quality; fused KV-cache quantization frees VRAM for long context. CUDA 12.4+; prebuilt Windows wheels + triton-windows. Coherent down to ~1.6 bpw on 70B in <16 GB.

### torchao (pytorch/ao) · `recommended` · stable
PyTorch's native quantization+sparsity library and the load-bearing upstream for the INT4/FP8/NVFP4 paths in vLLM, SGLang and especially Diffusers. Uses tensor subclasses so `quantize_(model, Int4WeightOnlyConfig())` swaps in low-bit kernels in place. Latest v0.17.0 (2026-03-30, BSD-3); NVFP4 QAT landed in v0.14.1 (Blackwell-only, CUDA 12.8+), with v0.15-0.17 adding MXFP8 MoE training (1.2x e2e vs bf16, identical convergence), CuteDSL MXFP8 3D-expert kernels, and per-head FP8 low-precision attention. For this rig the standout is the Diffusers integration: the official PyTorch 'Faster Diffusion on Blackwell' workflow uses torchao MXFP8/NVFP4 to accelerate image generation ~1.3-1.7x — directly relevant to a local diffusion/ComfyUI game-art pipeline. Install per CUDA: `pip install torchao --index-url https://download.pytorch.org/whl/cu128`.

- **Platforms:** Linux (manylinux wheels, primary). CUDA wheels for cu126 / cu128 / cu129. Windows support is weak/undocumented on PyPI — WSL2 is the reliable path on this rig. PyPI: torchao. · **Accelerators:** NVIDIA CUDA (incl. Blackwell sm_120), with NVFP4/MXFP8 kernels gated to Blackwell. The upstream mechanism behind quantization in vLLM, SGLang, and Diffusers.

### AutoRound (Intel low-bit PTQ) · `situational` · stable
Intel's accuracy-first PTQ algorithm: it optimizes weight rounding with signed gradient descent (the SignRound method) to hit high accuracy at ultra-low bit-widths (2–4 bit) with minimal tuning, and added block-wise FP8 (Mar 2026) and model-free RTN (May 2026). Reach for it when you want the best quality at 2–4 bit and are willing to pay more calibration time than GPTQ — its output is compatible with vLLM/SGLang/Transformers and it now feeds llm-compressor directly. For this rig it's a producer-side tool that scores like the others whose consumer is vLLM: useful when you specifically need a very-low-bit checkpoint with maximum recovered quality, but for the local Windows loop the EXL3/GGUF+imatrix paths cover most needs without the calibration overhead. Cross-platform (CUDA/Intel XPU/CPU), Apache-licensed.
