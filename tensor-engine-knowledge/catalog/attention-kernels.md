## Detail

### FlexAttention (PyTorch) · `recommended` · production
PyTorch's built-in API for arbitrary attention variants: you write the mask/bias as a Python score_mod or block_mask function and torch.compile fuses it into a single block-sparse FlashAttention-class Triton kernel that materializes no extra memory. It's the right tool on this rig precisely when cuDNN SDPA can't help — non-standard masks like sliding-window, ALiBi, document/packed-sequence, or causal+prefix-LM — without writing CUDA. Reach for it for custom-attention research and any game-AI model with an unusual context structure. Knobs: build a BlockMask once and reuse it; mark dynamic shapes for torch.compile; on Windows you need triton-windows for the lowering. Blackwell gotcha: on the 5090 (sm_120) it lowers to FA2-class kernels (the FA4 backend it can target only exists on datacenter sm_100/sm_103 B200/B300), so don't expect FA4 numbers here — but for custom masks it's still the best no-CUDA option and runs fine.

- **Platforms:** linux, windows, macos · **Accelerators:** cuda, rocm, cpu, xpu · **Formats:** n/a (attention API on torch tensors)
- **Blackwell/Win-ready:** yes · **Optimizes for:** flexibility · **Multi-GPU:** none (composes with the engine's parallelism) · **Fit:** rig 4/5 · studio 4/5
- **License:** BSD-3-Clause (PyTorch license) — commercial: **yes**. BSD-3-Clause as part of PyTorch — fully permissive for commercial/closed-source shipping.
- **Best for:** Custom attention masks (sliding-window, ALiBi, document, prefix-LM) without CUDA (local, fit 5) ; Attention-variant research / prototyping on the 5090 (reference, fit 5) ; Block-sparse long-context attention on Windows (via triton-windows) (windows, fit 4) ; Training custom-attention models with autograd (training, fit 4)
- **Speed/notes:** Performance competitive with handwritten FlashAttention via torch.compile fusion (1.2-3.2x over naive); on sm_120 it lowers to FA2-class block-sparse Triton kernels (no FA3/FA4 on the 5090). On datacenter Blackwell it can use the FA4 backend, but not on this rig.

### SageAttention (1 / 2 / 2++ / 3) · `recommended` · production
A quantized, plug-and-play drop-in attention kernel that is THE reason to go past plain SDPA on this rig for diffusion. SageAttention2++ (v2.2.0) quantizes QK to INT8 with outlier smoothing and PV to FP8 with two-level accumulation, delivering 2-3x over FA2 with no quality loss; SageAttention3 adds microscaling FP4 to exploit the RTX 5090's FP4 tensor cores for ~5x. It is verified on exactly the workloads this studio runs — Flux, SD3.5, HunyuanVideo, CogVideoX, Mochi, Wan — and integrates into ComfyUI via the --use-sage-attention flag or KJNodes' 'Patch Sage Attention' node. Knobs: pick the backend (sageattn_qk_int8_pv_fp16_cuda is the reliable one on Windows; sageattn3_blackwell(q,k,v,is_causal) for FP4); SA3 recommends a hybrid that uses SA2++ on first/last diffusion timesteps to protect quality. Blackwell/Windows gotchas: needs CUDA >= 12.8 and Triton (so install triton-windows first); SA3 wants python>=3.13 + torch>=2.8; native source build patches PyTorch headers, so prefer Kijai's precompiled wheels or the DazzleML installer; AVOID --use-sage-attention on Qwen/Wan in some configs (reported black output) — use the KJNodes patch node instead.

### cuDNN Fused Attention (SDPA backend) · `recommended` · production
NVIDIA's closed-source fused scaled-dot-product-attention kernels, surfaced to you for free through PyTorch's torch.nn.functional.scaled_dot_product_attention (and torch SDPA auto-selects it on Hopper+ / Blackwell). On the RTX 5090 (sm_120) it is the single fastest attention path available and it ships in stock PyTorch with zero build steps, full autograd, and torch.compile support — making it the correct default floor for both local-LLM inference and LoRA/style fine-tuning on this rig. Reach for it whenever you DON'T need a custom mask pattern; for custom masks use FlexAttention, for diffusion speed stack SageAttention on top. Blackwell gotcha: you only get it if torch picks cuDNN — install a cu128+ PyTorch build (stable cu128 or nightly cu130 for NVFP4) so the sm_120 kernels are present; verify with torch.backends.cuda.flash_sdp/cudnn_sdp flags. It supports fp16/bf16/fp8/mxfp8 on Blackwell.

### triton-windows (woct0rdho fork) · `recommended` · stable
A Windows-native fork of Triton that is the load-bearing enabling layer for this entire lane on Windows: SageAttention, FlexAttention, and any torch.compile-fused attention kernel are Triton-compiled, and stock Triton has poor Windows support. It officially supports Blackwell sm_120 (requires Triton >= 3.3, PyTorch >= 2.7, CUDA >= 12.8) and bundles a minimal CUDA toolchain + TinyCC in the wheel so you don't hand-install MSVC/CUDA build deps. Install it FIRST, before SageAttention. Knobs: pin the version to your torch (e.g. `pip install -U "triton-windows<3.7"` for torch 2.7-2.9; 3.6 needs torch>=2.10, 3.7 tracks newer) — a mismatched Triton/torch pair is the most common build failure. Blackwell/Windows gotcha: this is the correct replacement for the xformers build path; combined with torch.compile + SDPA + SageAttention it is the modern Windows Blackwell stack. ComfyUI embedded-Python users get specific install guidance in the repo.

### FlashAttention 2 · `runner-up` · mature
The classic IO-aware exact-attention kernel and the ONLY FlashAttention tier the RTX 5090 can run — FA3 and FA4 require the TMEM/UTCHMMA hardware that sm_120 (GB202) physically lacks, so on this card 'flash-attention' means FA2. It's the memory-efficient O(N) attention many libraries import by name. On this rig you rarely install it standalone because cuDNN SDPA is faster and SageAttention is much faster for diffusion; you mostly need it when a specific library hard-imports flash_attn. ### PagedAttention (vLLM) · `situational` · production
Not a standalone install — PagedAttention is the virtual-memory-style KV-cache paging algorithm at the heart of vLLM that eliminates KV fragmentation and enables high-throughput continuous batching. On Blackwell the core inference path (PagedAttention + CUDA graphs + FP8) works on the RTX 5090 with a cu128 build (torch 2.9.0+cu128), and the 5090 has dedicated FP8 tensor cores it can use via --dtype fp8 / fp8 KV cache. For this rig it's situational for two reasons: (1) its throughput advantage shows up under MANY concurrent requests, not the single-user/low-concurrency pattern of a one-human studio, and (2) vLLM has ~13 Windows-platform blockers in its orchestration layer, so you run it via WSL2/Docker, not natively. Reach for it when you want to stand up a local OpenAI-compatible endpoint to serve your LLM crew with real batching; for casual single-stream local chat, llama.cpp/Ollama or an LM-server with cuDNN SDPA is simpler on Windows.

On THIS rig it is the canonical Blackwell trap and the reason this lane has a load-bearing warning: do NOT pip install xformers into ComfyUI's embedded Python. Two failure modes: (1) there's no official sm_120 wheel, so memory_efficient_attention_forward errors out requiring capability <= (9,0) while the 5090 reports (12,0); and (2) far worse, xformers resolves its own torch dependency and SILENTLY force-downgrades your cu128/cu130 nightly to a stable/older build, breaking the whole environment — the single biggest hidden trap on Windows Blackwell. The correct replacement on this rig is triton-windows + torch.compile + SDPA (cuDNN), with SageAttention for the speed that xformers used to provide. A community fork (xiangxin2025cn) compiles xformers 0.0.32 for sm_120 with CUTLASS 4.0, but there is no reason to take that risk when SDPA+SageAttention are faster and Windows-native.
