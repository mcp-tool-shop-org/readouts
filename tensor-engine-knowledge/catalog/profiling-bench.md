### NVIDIA Nsight Systems · `recommended` · production
The system-level timeline profiler and the single most valuable verification tool in this lane for the 5090. It captures a correlated CPU+GPU timeline: every CUDA API call, kernel, memcpy, and (with NVTX) your own annotated ranges, plus optional GPU metrics sampling (SM occupancy, Tensor-Core activity, DRAM bandwidth, PCIe throughput). This is how you visually confirm the wave-1/2 laws: eager execution shows the GPU idle between many tiny kernel launches; CUDA graphs collapse those gaps into a tight stream (the ~8x story made visible). It runs NATIVELY on Windows (host GUI + `nsys` CLI) and profiles Windows-native CUDA apps (llama.cpp, ComfyUI, PyTorch) directly — no WSL2 needed for the common case. Latest line is 2026.3.x; supports GeForce Blackwell sm_120. GPU metrics sampling and any HW-counter feature require the perf-counter permission toggle (Control Panel -> Developer -> Manage GPU Performance Counters -> all users) or admin, identical to the Nsight Compute requirement. Trace capture is low-overhead; you typically `nsys profile -t cuda,nvtx -o run.nsys-rep <cmd>` and open the report in the GUI.

### PyTorch Profiler (torch.profiler) + Holistic Trace Analysis · `recommended` · production
The in-framework profiler for everything you run through PyTorch — diffusion (ComfyUI/Diffusers SDXL/Flux) and any local fine-tune/LoRA on the 5090. `torch.profiler.profile(activities=[CPU,CUDA], record_shapes=True, with_stack=True)` records op-level CPU + CUDA-kernel time, memory timeline, and FLOPs, exports a chrome trace (`export_chrome_trace`) viewable in chrome://tracing or Perfetto, and feeds TensorBoard. It uses Kineto/CUPTI under the hood so it sees the same kernels Nsight does, but attributed to PyTorch ops — far easier than raw Nsight for 'which layer is slow.' Holistic Trace Analysis (HTA, facebookresearch/HolisticTraceAnalysis, docs now 'TraceInsight 0.6.1') consumes those Kineto traces and computes higher-level views: GPU idle-time breakdown, most-frequent kernels, compute/communication overlap, trace-diff between two runs, and experimental CUPTI counter analysis. On a single 5090 the HTA distributed features are overkill, but its idle-time and kernel-pattern analyses are still useful. Works natively on Windows with a CUDA PyTorch build (use cu128/cu130 wheels per the rig's CUDA-12.8 law).

### llama-bench (llama.cpp) · `recommended` · production
The authoritative micro-benchmark for GGUF inference and the tool that turns wave-1/2 config laws into numbers. It lives in `tools/llama-bench/` inside the llama.cpp build you already compiled with CUDA — so it is the FREE, zero-install way to validate a recipe. It reports prompt-processing throughput (pp, e.g. pp512) and generation throughput (tg, e.g. tg128) as separate tok/s figures with stddev over N repetitions, deliberately excluding tokenization/sampling so you measure the kernels. Critically for this rig: it does cartesian sweeps — pass `-ngl 0,99 -fa 0,1 -b 256,512` and it runs every combination, which is exactly how you prove 'flash-attention on' and 'all layers offloaded' wins, or detect the CUDA-13.x MMQ slowdown (run the same model on a 12.8 build vs a 13.x build and compare pp). ### nvidia-smi / gpustat (NVML CLIs) · `recommended` · production
The always-present baseline and the honest answer to 'how do I monitor the GPU on Windows without DCGM.' nvidia-smi ships with the driver — no install — and beyond the default snapshot it has `dmon` (streaming util/power/clocks/mem/temp), `--query-gpu ... --format=csv -lms 500` (CSV polling you can log to a file), and `pmon` (per-process). gpustat (MIT, Python, native Windows) wraps NVML into a compact one-line-per-GPU view with `--watch` and `--json`, which is the easy way to script GPU checks into your benchmark harness or a CI gate.
