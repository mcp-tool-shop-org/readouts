### Piper (OHF-Voice / piper1-gpl) · `recommended` · production
The TTS workhorse for high-volume placeholder and NPC voiceover. A fast, fully-local VITS-based neural TTS that synthesizes faster than real-time on CPU alone, with hundreds of prebuilt voices across 30+ languages — ideal for generating thousands of NPC barks and temp dialogue lines cheaply. Development moved from the original MIT-licensed rhasspy/piper to OHF-Voice/piper1-gpl under the Open Home Foundation, which RELICENSED the engine to GPLv3 — important for a commercial studio: run Piper as a standalone process to produce WAV files (those outputs are unencumbered and shippable), but don't statically link libpiper into closed-source game binaries. Voice models carry their own (mostly CC-BY/MIT) licenses, checkable per voice card. Consumes ONNX voice + JSON config files. A CUDA path exists (install onnxruntime-gpu, pass --cuda) and runs fine on sm_120 through the ONNXRuntime CUDA EP, but Piper is so light that the CPU path on this 64 GB rig is the sensible default. For better single-voice quality on shippable VO, step up to Kokoro.

### faster-whisper (CTranslate2) · `recommended` · production
The fastest and most ergonomic Python ASR runtime — a reimplementation of Whisper on CTranslate2 (a quantizing C++ Transformer engine) that is up to 4x faster than reference Whisper at equal accuracy and adds batched inference for another ~4x, plus word timestamps and VAD. THE LOAD-BEARING BLACKWELL CAVEAT for this rig: the default `int8_float16` compute type crashes immediately on the RTX 5090 with CUBLAS_STATUS_NOT_SUPPORTED because CTranslate2's INT8 tensor-core path lacks the sm_120 padding (upstream fix PR #1982 is merged, but the 4.7.2 PyPI wheel does not yet officially target sm_120). The fix is one line: `WhisperModel(..., compute_type='float16')` runs flawlessly and is plenty fast on a 5090 — you only lose INT8's VRAM savings, which is irrelevant at 32 GB. Requires cuBLAS + cuDNN 9 for CUDA 12 (CTranslate2 >=4.5 needs CUDA >=12.3, so 12.8 is fine). No FFmpeg needed (uses PyAV). Use this over whisper.cpp when you want batched throughput, programmatic Python integration, or distil-large-v3.5.
- **Dev:** SYSTRAN (engine: OpenNMT/CTranslate2) · **Type:** runtime · **Lang:** Python (CTranslate2 C++ inference engine) · **Version:** faster-whisper 1.2.1 / CTranslate2 4.7.2 · **Released:** 2025-10-31 (FW 1.2.1); 2026-05-19 (CT2 4.7.2)
- **Platforms:** Windows (native pip), Linux, macOS (CPU); GPU on Win/Linux · **Accelerators:** NVIDIA CUDA 12 via CTranslate2 (needs cuBLAS + cuDNN 9); CPU with INT8 · **Formats:** CTranslate2 converted format (convert from HF Whisper / distil-whisper); not GGUF/ONNX
- **Blackwell/Win-ready:** yes · **Optimizes for:** Highest-throughput batched transcription + word timestamps; 8-bit quant on CPU/GPU · **Multi-GPU:** Single device per model instance; scale by running N instances pinned to devices (no tensor-parallel) · **Fit:** rig 4/5 · studio 5/5

### sherpa-onnx · `recommended` · production
The Swiss-army speech runtime — a single Apache-2.0 C++/ONNXRuntime engine that does ASR, TTS, VAD, speaker diarization, speaker ID, and source separation, with 12 language bindings and a built-in websocket server/client. This is the integration backbone if you want ONE engine driving both live transcription and in-game TTS (callable from C#/C++/Go for Godot/UE5). It runs an enormous model zoo as ONNX: ASR via Whisper, NVIDIA Parakeet/Canary exports, Zipformer, Paraformer, SenseVoice, Qwen3-ASR, Cohere Transcribe; TTS via Kokoro, Piper-style VITS, Matcha, Supertonic, KittenTTS. Two GPU paths on Windows: prebuilt CUDA 12.x + cuDNN 9 binaries (download from releases, no build needed), or the DirectML provider (runs on any DX12 GPU with zero CUDA toolchain). Because it rides ONNXRuntime's CUDA EP rather than PyTorch, it sidesteps the sm_120 PyTorch-wheel problem entirely. Slightly more setup to pick the right model than whisper.cpp/Piper, but unmatched as a do-everything local speech server.
- **Dev:** k2-fsa (Next-gen Kaldi) · **Type:** inference-server · **Lang:** C++ core (ONNXRuntime) with 12 language bindings (Python/C/C#/Go/JS/Swift/Kotlin/...) · **Version:** v1.13.2 · **Released:** 2026-05-13

### whisper.cpp · `recommended` · production
The no-drama ASR default for this rig. Pure C/C++ port of Whisper on ggml — builds natively on Windows with `cmake -B build -DGGML_CUDA=1` and runs large-v3 entirely on the 5090 via cuBLAS + custom CUDA kernels, with no PyTorch, no CTranslate2, and therefore none of the sm_120 wheel roulette that plagues the Python ASR stack. Because ggml/llama.cpp already target Blackwell sm_120, adding `-DCMAKE_CUDA_ARCHITECTURES=120` under CUDA 12.8 produces a clean build. Consumes GGML/GGUF model files (quantized q5/q8 variants available to shrink VRAM further). Ships a `whisper-server` (OpenAI-compatible endpoint), CLI, and bindings. Vulkan backend gives a vendor-neutral fallback. The trade-off vs faster-whisper is no batched multi-stream throughput, so for bulk parallel transcription faster-whisper wins — but for reliability-first single-stream offline transcription and live capture on Windows, this is the engine to start with.
- **Dev:** ggml-org (Georgi Gerganov / ggml community) · **Type:** runtime · **Lang:** C/C++ (ggml) · **Version:** v1.8.6 · **Released:** 2026-06-02

- **Blackwell/Win-ready:** yes · **Optimizes for:** Offline + streaming ASR with zero Python/PyTorch dependency; lowest-friction CUDA path on Windows · **Multi-GPU:** Single-GPU oriented; no built-in multi-GPU sharding for a single transcription (not needed at 32 GB for any Whisper model) · **Fit:** rig 5/5 · studio 5/5
- **License:** MIT — commercial: **yes**. MIT on the engine. Model weights (OpenAI Whisper) are also MIT. Fully commercial-clean for game audio pipelines.

### Kokoro TTS runtime (kokoro-onnx / via sherpa-onnx) · `recommended` · stable
The best quality-per-byte TTS you can actually ship. Kokoro-82M is an 82-million-parameter model (~300 MB) that hit #1 on the TTS Arena in January 2026, beating models 10-100x its size, and crucially it is Apache-2.0 — fully commercial-clean, unlike XTTS's non-commercial weights. Run it via the MIT-licensed kokoro-onnx runtime (Python/JS/Rust) or inside sherpa-onnx for a unified C++ engine. It produces remarkably natural English speech at near real-time on CPU and ~36x real-time on GPU while using under 2 GB of VRAM — on a 32 GB 5090 you can run dozens of concurrent voices. Because it rides ONNXRuntime, the CUDA EP works on sm_120 with no PyTorch-wheel headache; install onnxruntime-gpu and go. Slightly narrower voice/language coverage than Piper and no zero-shot cloning, but for shippable, license-safe, high-quality narration and named-character VO in English, this is the recommended TTS. Pair with Piper for bulk/multilingual and reserve XTTS for non-shipping cloned previz.
- **Dev:** hexgrad (model) + thewh1teagle (kokoro-onnx runtime) + k2-fsa (sherpa-onnx integration) · **Type:** runtime · **Lang:** Python / JS / Rust (ONNXRuntime); also runs inside sherpa-onnx C++ · **Version:** Kokoro-82M (model) + kokoro-onnx (active 2026) · **Released:** 2026 (Kokoro hit #1 TTS Arena Jan 2026)
