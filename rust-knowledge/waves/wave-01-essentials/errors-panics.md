# errors-panics — Errors, panics & arithmetic safety (wave 1, essentials)

**Q1. How should a library crate model errors, and when is a panic right?** One error enum per failure mode (thiserror 2 derives it), `?` through `From`, and `Result` by default. Panic only on a broken invariant or contract, via `expect("... should ...")` naming why it cannot fail.

**Q2. What happens on overflow and on a panic under the solver's release profile?** With `overflow-checks = false`, `+ - *`, negation and `abs` wrap, and shift amounts are masked (`1u64 << 64 == 1`); `/ %` by zero, `MIN / -1` and bad indexes still panic. With `panic = "abort"` (already the wasm32 default) the hook runs, nothing unwinds or drops, and the abort is a trap.

1. **`?` returns `Err(From::from(e))`; `core::error::Error` has been stable since 1.81.** Rust Project 2026 (Reference: Operator expressions, https://doc.rust-lang.org/stable/reference/expressions/operator-expr.html). Implication: give the law's refusals a `core`-only `Refusal` enum. It costs nothing on wasm.
2. **thiserror generates the impls you would write by hand and stays out of your API; anyhow is for applications.** dtolnay 2026 (thiserror README at 2.0.21, https://raw.githubusercontent.com/dtolnay/thiserror/2.0.21/README.md). Implication: keep both out of `solver/`. Use thiserror for a future host-binding crate and anyhow for Rust tools.
3. **`Result` is `#[must_use]`; `Option<()>`, `bool` and `u32` are not, and dropping them compiles silently (checked).** Rust Project 2026 (Reference: Diagnostic attributes, https://doc.rust-lang.org/stable/reference/attributes/diagnostics.html). Implication: `ensure`, `integrate`, `write_body` and `rebuild_snapshot` return bare `bool`s. Move them to `Result<(), Refusal>` or add `#[must_use]`.
4. **Under abort the panic hook runs, no `Drop` runs, and `catch_unwind` catches nothing.** Rust Project 2026 (std::panic::catch_unwind, https://doc.rust-lang.org/stable/std/panic/fn.catch_unwind.html). Implication: node reports `RuntimeError: unreachable`, and the instance stays callable with its statics possibly half-written (measured). Re-instantiate after any trap.
5. **Tests ignore the profile's `panic` setting and inherit dev's `overflow-checks = true`.** Rust Project 2026 (Cargo Book: Profiles, https://doc.rust-lang.org/stable/cargo/reference/profiles.html). Implication: native tests unwind and panic where the wasm aborts and wraps. Spell intended wrapping as `wrapping_*`, as `mix_u64` already does.
6. **With checks off, `/` and `%` on `MIN, -1` still panic, and constant overflow is a deny-by-default lint.** Rust Project 2026 (Reference: Operator expressions, URL above). Implication: `signature()`'s `1u64 << i` masks need `const _: () = assert!(MAX_BODIES <= 64);` because a 65th body would alias bit 0.
7. **`strict_*` arithmetic (stable since 1.91.0) panics on overflow in every build.** Rust Project 2025 (Announcing Rust 1.91.0, https://blog.rust-lang.org/2025/10/30/Rust-1.91.0/). Implication: inside exports, prefer `checked_*` feeding a refusal, because a strict panic is a trap.
8. **`debug_assert!` is compiled out in release; `assert!` never is.** Rust Project 2026 (std::debug_assert!, https://doc.rust-lang.org/stable/std/macro.debug_assert.html). Implication: an invariant the golden hash depends on must be an `assert!` or a refusal, never a `debug_assert!`.
9. **Since 1.81 an unwind out of `extern "C"` aborts, even under the caller's `catch_unwind`.** Rust Project 2024 (Announcing Rust 1.81.0, https://blog.rust-lang.org/2024/09/05/Rust-1.81.0/). Implication: map an internal `Result` chain to 1/0 in one `match` per export. A native Godot or Unreal build cannot rely on catching the panic.

**Correction to the dispatch.** The `continue` in `rebuild_snapshot` after a failed `canon_quat` existed at `c64f67a`. `6a33297` made it `return false`, and `e5fbcb9` keeps that. The `continue` that remains skips carried bodies by design. What is left is compiler enforcement (3, 9) and the one `.unwrap()` in `integrate`.

**Thin evidence.** The trap's JS surface (the message, and that the instance stays callable) was measured in node only; the JS API spec names `RuntimeError` and is silent on reuse. Two checks assert this Windows host's abort status, 0xC0000409; on Unix it would be SIGABRT. The rustc book lists `-C panic=immediate-abort`, but 1.98.1 rejects it on stable (measured outside the oracle, whose flag allowlist refuses it).
