# Native audio and MIDI host — generator packet

Written by `kimi-k2.6:cloud` through `scripts/openrouter_lane.py`; unverified until the wave's verification record says otherwise.

A native Windows host pushes committed events from the main thread into a wait-free SPSC ring buffer (rtrb or ringbuf). The cpal WASAPI output callback pops events and renders them into the pre-silenced &mut [f32] buffer. No allocation or locking occurs inside the callback; assert_no_alloc guards prove this. Midir’s WinMM backend delivers input timestamps in microseconds since midiInStart, while cpal WASAPI StreamInstant is driven by QueryPerformanceCounter. Because the two clocks are independent, the host samples both at a common anchor event (e.g., the first callback after play()), converts MIDI time to sample frames with integer arithmetic, and re-anchors periodically to correct drift. Findings: (1) cpal WASAPI always opens shared-mode streams; BufferSize::Fixed requests a frame count but the host may round it. (2) OutputCallbackInfo exposes callback and playback StreamInstants; playback time is derived from IAudioClock, buffered frames, and stream latency. (3) The error callback receives ErrorKind::Xrun on discontinuity and DeviceNotAvailable/StreamInvalidated on device changes. (4) rtrb and ringbuf provide lock-free SPSC queues that allocate only on construction. (5) assert_no_alloc wraps the callback to detect forbidden allocations. (6) Midir input callbacks receive u64 microseconds; WinMM converts dwTimestamp (ms) by multiplying by 1000. (7) Mapping requires an anchor between midir microseconds and cpal StreamInstant, then integer conversion to samples. (8) Midir port enumeration on Windows uses midiInGetNumDevs and midiInGetDevCapsW. (9) The oscillator callback reads events from the SPSC queue and writes samples without blocking. (10) cpal ranks F32 highest for real-time output streams.
