# Performance & profiling — wave 2 packet

**Q1. What does each release-profile knob do to speed, size and the pinned bytes?** Every knob moved the pinned bytes. Only opt-level moved V8 speed materially: `s` was 1.69× slower, `z` 2.73×, `0` 30×. Size ranged from −12% (`strip = "symbols"`) to +634% (`debug = "line-tables-only"`). No knob changed the scene's results.

**Q2. How is Rust code measured and profiled on Windows and Linux?** Benchmark with criterion or divan plus `std::hint::black_box`; sample natively with samply (Windows, Linux, macOS), perf (Linux), VTune or Superluminal (Windows), or Tracy; profile the shipped wasm with `node --cpu-prof`.

Evidence is one rig and one scene; speed figures carry ±10% noise (one outlier round +41%).

1. **Fifteen profile variants of a scratch solver copy changed the code section, yet all gave byte-identical results over 400 quanta of both laws.** Rust Project 2026 (The Cargo Book: Profiles, https://doc.rust-lang.org/cargo/reference/profiles.html). Implication: any profile edit, even `lto = false` → `"off"` (it changes every crate's `-C metadata`), means re-pinning `fixtures/solver.sha256` and rerunning the golden suite. That metadata is how bytes move is inferred, not traced.
2. **`lto = false` is thin-local LTO, which does nothing at codegen-units 1, and wasm32-unknown-unknown already compiles with `-Cpanic=abort`.** Rust Project 2026 (rustc Book: wasm32-unknown-unknown, https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html). Implication: the solver's `lto` and `panic` lines cost nothing and affect only a native host build.
3. **Results move only through semantics: overflow checks, debug assertions, cfg(target_feature) paths, NaN bit patterns, and transcendentals of unspecified precision.** Rust Project 2023 (RFC 3514 Float semantics, https://rust-lang.github.io/rfcs/3514-float-semantics.html). Implication: keep `overflow-checks` and `debug-assertions` off in the artifact and keep NaN refused before hashing.
4. **One early `n_bodies > MAX_BODIES` return removes all 30 bounds checks from `step`. A storing loop otherwise keeps one check per iteration, and `chunks_exact_mut` / `as_chunks_mut` leave none.** N. Nethercote et al. 2026 (Rust Performance Book: Bounds Checks, https://nnethercote.github.io/perf-book/bounds-checks.html). Implication: put that guard first in every export, including T2's `solver_restore`.
5. **In V8, the software `sqrt` from libm 0.2.16 plus the `__multi3` it calls took 22% of wasm samples. The allocator took 0.7%, and the law's own code 4.0%.** libm crate 2026 (libm 0.2.16 src/math/sqrt.rs, https://docs.rs/crate/libm/0.2.16/source/src/math/sqrt.rs). Implication: buffer reuse is tidiness, not speed; the sqrt route comes with `enhanced-determinism`, which the float-determinism lane owns.
6. **A native build replayed the scene with identical result bytes and ran 1.9× faster, but on x86_64 libm uses hardware `sqrtsd`.** V8 2026 (WebAssembly compilation pipeline, https://v8.dev/docs/wasm-compilation-pipeline). Implication: rank hot spots natively, then confirm in V8 after warm-up, because V8 tiers up from Liftoff to TurboFan.
7. **The 182,205-byte `name` section (12% of the artifact) is what gives `node --cpu-prof` Rust frame names; without it V8 shows `wasm-function[N]`.** WebAssembly spec 2026 (Core spec, custom sections, https://webassembly.github.io/spec/core/appendix/custom.html). Implication: keep the name section in the pinned build; it does not affect semantics.
8. **With `+simd128`, LLVM vectorizes elementwise f64 loops but keeps float sums sequential. The solver gained nothing measurable (0.95×, within noise) and got a new digest.** Rust Project 2026 (core::arch::wasm32, https://doc.rust-lang.org/stable/core/arch/wasm32/index.html). Implication: SIMD is not a lever today, and relaxed-SIMD stays off.
9. **On this host `target-cpu=native` enables 38 target features instead of 5, which flips cfg-gated paths such as wide 1.7.1's fused `mul_add`. For wasm32, rustc ignores it. PGO cannot instrument wasm32 (E0463, `profiler_builtins`).** Rust Project 2026 (rustc Book: Codegen options, https://doc.rust-lang.org/rustc/codegen-options/index.html). Implication: native Godot/Unreal bindings must pin the CPU baseline and match the wasm golden; whether PGO/BOLT preserve results is untested.
10. **Stable Rust has no bench harness (`#[bench]` gives E0554), and criterion 0.8.2 deprecates its own `black_box`.** Rust Project 2026 (std::hint::black_box, https://doc.rust-lang.org/stable/std/hint/fn.black_box.html). Implication: bench `solver_step` through an `rlib` build; `black_box` is best-effort.
