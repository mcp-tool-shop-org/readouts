# unsafe-ffi — Unsafe Rust, UB & FFI (wave 2, advanced)

**Q1. What is UB, and how is an unsafe block proved sound?** UB is the Reference's list (data races, dangling or misaligned access, aliasing violations, mutating immutable bytes, wrong ABI or unwinding, invalid values) plus each std function's stated preconditions. There is no formal model, so soundness is argued, not compiled: write a `// SAFETY:` line per operation against those preconditions, then execute it under Miri with both aliasing models. rustc proves only what const evaluation and its lints see.

**Q2. static mut, exports and the C ABI under edition 2024?** Never reference a `static mut`: export pointers from `&raw mut` and make one short-lived reference per call. Write `#[unsafe(no_mangle)] pub extern "C" fn` and `unsafe extern` imports. A panic escaping `"C"` aborts. All of it compiles under 2021 today.

1. **`static_mut_refs` is deny in 2024 and `cargo fix` will not rewrite it.** Rust Edition Guide 2026 (Disallow references to static mut, https://doc.rust-lang.org/edition-guide/rust-2024/static-mut-references.html). Implication: `bodies_ptr`, `colliders_ptr`, `heights_ptr` become `(&raw mut X).cast::<f64>()`, with no unsafe needed since 1.82. `step` and `snapshot_ptr`/`_len` borrow through `&raw` under a SAFETY line.
2. **`solver_clear_warmstart` is UB, and the compiler cannot see it.** rustc book 2026 (Deny-by-default lints, https://doc.rust-lang.org/rustc/lints/listing/deny-by-default.html). `invalid_reference_casting` rejects the one-expression `&T`→`&mut T` cast. It misses a field write through the cast and the solver's Vec-of-pointers form. Implication: the fix is a `&mut` path from the owner, never a cast. rapier3d-f64 0.35.3 has none (`contact_pairs_mut` is E0599).
3. **Permission travels with the pointer, not the owner.** Villani, Hostert, Dreyer, Jung 2025 (Tree Borrows, https://iris-project.org/pdfs/2025-pldi-treeborrows.pdf). Shared references start Frozen, and a local write through one is UB. Stacked Borrows makes every new `&mut` immediately Unique. Implication: run Miri under both models. Evidence is thin here: my reading, which Miri has not checked, is that Tree Borrows may pass the solver's heap-only writes, and a pass would not make them sound.
4. **Bare `no_mangle`, `export_name`, `link_section` and unmarked `extern` blocks are hard errors in 2024.** Rust Edition Guide 2026 (Unsafe attributes, https://doc.rust-lang.org/edition-guide/rust-2024/unsafe-attributes.html). Implication: switch all ten exports to `#[unsafe(no_mangle)]` now. Every edition accepts it since 1.82.
5. **Since 1.81 a panic escaping `extern "C"` aborts.** Rust 2024 (Announcing Rust 1.81.0, https://blog.rust-lang.org/2024/09/05/Rust-1.81.0/). Implication: keep `"C"`. The solver is `panic = "abort"` and wasm32-unknown-unknown defaults to panic=abort (measured), so `"C-unwind"` adds nothing. Refusals stay u32 status codes.
6. **Const evaluation rejects invalid values with E0080; runtime code does not.** Rust Reference 2026 (Behavior considered undefined, https://doc.rust-lang.org/stable/reference/behavior-considered-undefined.html). Implication: f64 slots have no invalid bit patterns, so JS cannot hand Rust an invalid value. Any future bool or enum field is decoded with a `match`, never a transmute.
7. **Debug builds assert the preconditions of std's pointer functions; `&raw` (1.82) and strict provenance (1.84) remove intermediate references and integer casts.** Rust 2024 (Announcing Rust 1.78.0, https://blog.rust-lang.org/2024/05/02/Rust-1.78.0/). Implication: T2's restore parser reads values with `f64::from_le_bytes`, never a misaligned `*const f64`.
8. **Edition 2024 warns `unsafe_op_in_unsafe_fn`; clippy's SAFETY lints are opt-in.** Rust Edition Guide 2026 (https://doc.rust-lang.org/edition-guide/rust-2024/unsafe-op-in-unsafe-fn.html). Implication: none of the solver's 15 unsafe blocks has a SAFETY line. Add them and gate them with `undocumented_unsafe_blocks`. Clippy is not installed here, so it was not run.
9. **Miri covers tier-1 targets; on other OSes it may fail before `main`, and wasm is never mentioned.** rust-lang/miri 2026 (README, https://github.com/rust-lang/miri). Implication: test the law natively (`canon_quat`, `mix_f64`, `js_min`/`js_max`, one world calling `solver_clear_warmstart`) on a pinned nightly.
10. **Only repr(C) types, scalars and raw pointers cross the C ABI.** Rustonomicon 2026 (FFI, https://doc.rust-lang.org/nomicon/ffi.html). Implication: today's exports are FFI-safe. For a C-header host, cbindgen parses unsafe attributes from 0.28.0. That older versions skip them is inference.
