# traits-advanced: Advanced traits & the type system (wave 2)

**Q1. What makes a trait dyn-compatible, and what changed in upcasting and impl-Trait capture?** Dyn-compatible supertraits, no `Sized` supertrait, no associated consts or GATs, and every method dispatchable (no type parameters, `Self` only as receiver, no `async fn`/RPIT) or fenced by `where Self: Sized`. E0038 now reads "not dyn compatible" (rust-lang/rust#133372, milestone 1.86.0). Upcasting is stable since 1.86. `use<..>` arrived in 1.82 and reached traits in 1.87; edition 2024 (1.85) captures all lifetimes by default.

**Q2. Which type-system tools encode invariants at zero runtime cost?** ZST typestate markers, `PhantomData`-typed handles, sealed traits, associated-const asserts, invariant brands and monomorphized generics. On 1.98.1 each adds 0 bytes or fails the build (E0599, E0308, E0080, E0277).

1. **One impl per type with an associated type; an associated-const assert fails the build (E0080) only where an instantiated path references it.** Rust Reference 2026 (Associated items, https://doc.rust-lang.org/stable/reference/items/associated-items.html). Implication: a future Law trait carries strides as `const STRIDE` plus an assert-const; buffers stay concrete (`[f64; L::STRIDE]` is not stable).
2. **Generic methods, associated consts, GATs, async fn and RPIT break dyn compatibility unless fenced by `where Self: Sized`; a `&dyn` is two words (8 bytes on wasm32).** Rust Reference 2026 (Traits, https://doc.rust-lang.org/stable/reference/items/traits.html). Implication: the solver's only trait objects are Rapier's `&dyn PhysicsHooks`/`&dyn EventHandler`, passed `&()`; keep `step`/`resolve_pair` free of `dyn`.
3. **The orphan rule is positional: the first local type precedes every uncovered type parameter; `&`/`Box`/`Pin` of a local type is local; coherence assumes upstream may add impls.** RFC 2451, 2018, restated by the 2026 Reference (https://rust-lang.github.io/rfcs/2451-re-rebalancing-coherence.html). Implication: convert stride-17 records to Rapier's `Vector` (glam `DVec3`) via a local `BodyRecord`; `From<[f64; 17]> for Vector` is E0117.
4. **Auto traits follow fields; `PhantomData<fn() -> T>` keeps handles Send + Sync; a Drop impl, not a phantom, tightens drop check.** Rustonomicon 2026 (PhantomData, https://doc.rust-lang.org/nomicon/phantom-data.html). Implication: rapier 0.35.3's `EventHandler: MaybeSync` (= `Sync` without `unsync-callbacks`) makes a solver event log use `AtomicU32`, not `RefCell` (E0277).
5. **`&mut T`, `Cell<T>`, `*mut T` are invariant, `fn(T)` contravariant; structs inherit from fields.** Rust Reference 2026 (Subtyping and Variance, https://doc.rust-lang.org/stable/reference/subtyping.html). Implication: rustc's "is invariant over the parameter" note names the culprit; read it first.
6. **`for<'a>` is needed when the function creates the borrow; elided `Fn(&T)` bounds already are higher-ranked.** Rust Reference 2026 (Trait and lifetime bounds, https://doc.rust-lang.org/stable/reference/trait-bounds.html). Implication: generic helpers over body collections take `where for<'a> &'a C: IntoIterator<Item = &'a f64>`.
7. **Upcasting (1.86) reaches `dyn Any` for downcasting.** Rust project 2025 (Announcing Rust 1.86.0, https://blog.rust-lang.org/2025/04/03/Rust-1.86.0/). Implication: no `as_any` boilerplate; `Box<dyn Any>::type_id()` is the Box's id, use `(&*boxed).type_id()`.
8. **Edition 2024 RPIT captures every in-scope lifetime; `use<..>` narrows it; RPITIT/async fn in traits capture everything and are not dyn compatible.** Edition Guide 2026 (RPIT lifetime capture rules, https://doc.rust-lang.org/edition-guide/rust-2024/rpit-lifetime-capture.html). Implication: the solver is edition 2021; a bump changes borrows at `-> impl Iterator` call sites, so migrate with `cargo fix --edition` and let golden hash and digest decide.
9. **ZST typestate makes order errors E0599 at zero bytes but cannot cross `extern "C"`.** Rust Book 2026 (ch. 18.3, https://doc.rust-lang.org/stable/book/ch18-03-oo-design-patterns.html). Implication: keep the `Option<Loaded>` checks at the exports; T2's `solver_restore` builds a complete `Loaded` and swaps it in only after every refusal check.
10. **Generics dispatch statically, but generic `#[no_mangle]` items are linted (`no_mangle_generic_items`).** rustc book 2026 (Warn-by-default lints, https://doc.rust-lang.org/rustc/lints/listing/warn-by-default.html). Implication: a Law trait over the box and product laws is ceremony until Rust code drives both; exports stay concrete shims.

**Thin evidence.** "Ceremony" in 10 is judgment. The rename date rests on a PR milestone. Std docs say PhantomData's drop-check role may change.
