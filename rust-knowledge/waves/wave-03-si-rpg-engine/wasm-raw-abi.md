# wasm-raw-abi: Rust to WebAssembly without bindgen (wave 3, si-rpg-engine)

**Q1. What is the complete contract of a raw `extern "C"` wasm module that JS drives through shared linear memory?** The module imports nothing and exports `memory` plus its `#[unsafe(no_mangle)]` functions. Values cross as i32/i64/f32/f64 (`u32` comes back signed, `u64` as a BigInt). Pointers are byte offsets into little-endian memory, with the stack below 1 MiB and statics above it. Every refusal is a status code, because a panic is an `unreachable` trap. JS builds new views after any call that can allocate.

**Q2. Which build choices change the module's bytes, imports, exports, memory and failure modes?** The target, `-C target-feature` (a typo only warns), `-C panic` (only abort builds on stable), link arguments (`--import-memory`, `-zstack-size`, `--export=`), `#[link(wasm_import_module)]`, the strip level (1,629,285, then 366, then 74 bytes), a `link_section` stamp, and any wasm-opt pass.

## Findings

1. **std here is stubs, and nothing fails until it is called.** Measured: `fs` returns `Unsupported`, clocks and `thread::spawn` trap, and the module has zero imports. Rust Project 2026 (wasm32-unknown-unknown, https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html). Implication: the law takes time and inputs only as arguments.
2. **dlmalloc grows memory on its first allocation.** It ignored 63,200 free bytes past `__heap_base`; `solver_load` grew the local build from 18 to 19 pages. Rust Project 2026 (std sys/alloc/wasm.rs at 1.98.1, https://github.com/rust-lang/rust/blob/1.98.1/library/std/src/sys/alloc/wasm.rs). Implication: T3's fixed-memory lint must plan for this growth (binary-and-limits owns the fix).
3. **`no_mangle` decides exports, and since 1.96 an undeclared extern fails to link.** `__heap_base` and `__data_end` are not exported on 1.98.1. Rust Blog 2026 (Changes to WebAssembly targets and handling undefined symbols, https://blog.rust-lang.org/2026/04/04/changes-to-webassembly-targets-and-handling-undefined-symbols/). Implication: moving to edition 2024 means rewriting ten attributes as `#[unsafe(no_mangle)]`.
4. **JS coerces every argument silently.** `u32::MAX` arrives as -1, and NaN passed to a `u32` becomes 0. WebAssembly CG 2026 (JS API ToJSValue/ToWebAssemblyValue, https://raw.githubusercontent.com/WebAssembly/spec/main/document/js-api/index.bs). Implication: `restoreSolver` must check for integers before calling `solver_restore`.
5. **A panic is a `RuntimeError` trap that keeps half-written state.** V8 and SpiderMonkey word the message differently, and a `RefCell` or `Mutex` held at the trap makes later calls trap. WebAssembly CG 2026 (JS API, https://webassembly.github.io/spec/js-api/). Implication: on a trap, drop build.mjs's `cached` instance and restore from the last snapshot.
6. **rustc places a 1 MiB stack first, then statics.** Rust Project 2026 (rustc_target base/wasm.rs at 1.98.1, https://github.com/rust-lang/rust/blob/1.98.1/compiler/rustc_target/src/spec/base/wasm.rs). Implication: `bodies_ptr` (1101432) sits above the stack, and `--import-memory` would break build.mjs's import-free instantiation.
7. **Growth silently detaches existing views.** A stale view reads `undefined` and drops writes. WebAssembly CG 2026 (JS API, refresh the memory buffer, https://webassembly.github.io/spec/js-api/). Implication: keep per-call views; `stepBodies` is safe only because the box step never allocates.
8. **f64 is 8-aligned on wasm32 (measured), but a misaligned whole-buffer index writes nothing.** Rust Reference 2026 (Type layout, https://doc.rust-lang.org/reference/type-layout.html). Implication: T2 decodes snapshots with `from_le_bytes` and gives `restore_ptr` an exported capacity.
9. **The pinned solver cannot use wasm32v1-none.** `enhanced-determinism` pulls in `indexmap` with its default `std`. docs.rs 2026 (parry3d-f64 0.30.2 Cargo.toml, https://docs.rs/crate/parry3d-f64/0.30.2/source/Cargo.toml). Implication: T3's binary lint is the gate, not a target switch.
10. **Post-processing changes bytes and meaning.** wasm-opt's `-tnh` assumes no trap is reached, `-ffm` drops NaN and signed-zero cases, and omitting `-g` drops the name section. Binaryen 2026 (optimization-options.h at version_133, https://github.com/WebAssembly/binaryen/blob/version_133/src/tools/optimization-options.h). Implication: no wasm-opt in build.mjs; stamp the law version in an `si_law` custom section.

**Thin evidence.** Traps were measured in V8 and SpiderMonkey 156 only, not JavaScriptCore. wasm-tools, twiggy and wasm-opt were not run (not installed here); the claims about them come from their own docs.
