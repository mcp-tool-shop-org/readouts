# Floating point & cross-platform determinism (wave 3, si-rpg-engine)

**Q1: which results are bit-identical?** f64 `+ - * /` and `sqrt` (and `mul_add`, which always rounds once), subnormals included, on any IEEE CPU, in every wasm engine and in rustc's const evaluator. Not bit-identical: NaN bits, std transcendentals, min/max zero ties, relaxed-SIMD results, HashMap iteration order.

**Q2: what to avoid, pin or canonicalize?** Keep std transcendentals, `algebraic_*`, relaxed SIMD and HashMap order off hashed paths; pin both rust-toolchain.toml and Cargo.lock, because the solver links two libm copies; canonicalize -0.0 and refuse or map NaN before `to_bits()`; gate every bump on goldens plus a libm canary.

1. **The basic operations are correctly rounded and never contracted.** Rust project 2023 (RFC 3514: Float semantics, https://rust-lang.github.io/rfcs/3514-float-semantics.html). Implication: build hashed math from those five operations. A 100 000-step chain with subnormals digests identically on x86-64 (-O0 and -O) and in wasm32. `a*b+c` stays unfused even with `+fma`.
2. **std transcendentals have unspecified precision.** Rust project 2026 (primitive f64, https://doc.rust-lang.org/stable/std/primitive.f64.html). Implication: call the `libm` crate. Over the same sweep, wasm32's `f64::sin` matches libm 0.2.16, but its `f64::hypot` does not, because the toolchain carries a CORE-MATH port.
3. **In wasm, float results vary only in NaN bits and relaxed SIMD.** WebAssembly CG 2026 (Core Specification 3.0: Numerics, https://webassembly.github.io/spec/core/exec/numerics.html). Implication: refuse NaN, or map it to 0x7ff8000000000000, before hashing. V8 on this x86-64 rig returns 0xfff8000000000000 for 0/0. `push_contact` hashes impulses without `bad()`.
4. **enhanced-determinism routes math to libm and maps to IndexMap, but does not disable SIMD.** Dimforge 2026 (parry3d-f64 0.30.2 src/lib.rs, https://docs.rs/crate/parry3d-f64/0.30.2/source/src/lib.rs). Implication: the 4-lane `wide` types remain in use. Correct any "SIMD off" note. A native aarch64 build would fuse `simd_mul_add`.
5. **Inherent method calls escape `libm_force`.** Rust project 2026 (Reference: Method-call expressions, https://doc.rust-lang.org/stable/reference/expressions/method-call-expr.html). Implication: a scratch build of solver/ at e5fbcb9 links compiler-builtins' `sin`, `cos`, `acos` and `log2`. `log2` is reached from `solver_step` through parry's BVH optimizer. Treat a toolchain bump like a libm bump.
6. **min/max may return either zero on a tie.** Rust project 2026 (primitive f64, same URL). Implication: in one -O binary, the same `n.max(p)` returned +0 in one place and -0 in another. Canonicalize: `write_body` and `push_f64` do, but `signature()` hashes raw collider bits.
7. **`f64::minimum`/`maximum` are still unstable on 1.98.1.** Rust project 2026 (core f64.rs at 1.98.1, https://raw.githubusercontent.com/rust-lang/rust/1.98.1/library/core/src/num/f64.rs). Implication: keep the explicit zero rule in `js_min`/`js_max`. Their NaN handling is asymmetric and differs from Math.min.
8. **Const eval uses a host-independent soft-float.** Rust project 2026 (rustc_apfloat docs, https://docs.rs/rustc_apfloat/latest/rustc_apfloat/). Implication: CLIMB_ANGLE and SLIDE_ANGLE have the same bits as a wasm run-time computation. A transcendental in a const is E0015.
9. **A fixed hasher does not fix HashMap order across targets.** Rust project 2026 (HashMap, https://doc.rust-lang.org/stable/std/collections/struct.HashMap.html). Implication: the measured x86-64 and wasm32 order digests differ. Use BTreeMap or IndexMap on hashed paths.
10. **Fixed-point buys exact, associative sums, but the law would have to leave Rapier.** fixed crate 2026 (fixed 1.31.0, https://docs.rs/fixed/1.31.0/fixed/). Implication: reserve it for new integer-exact subsystems. The physics law stays f64 with pins and gates.

**Where the evidence is thin.** The ARM64 NaN sign was not measured here. Whether the toolchain's `log2`, `acos` or `cos` can move the golden is unmeasured. The UCRT comparisons and the x86 NaN sign are host-specific checks pinned to this rig. The claim that two libm copies are linked rests on one scratch build of solver/ (name section plus call graph), not on the pinned Linux artifact.
