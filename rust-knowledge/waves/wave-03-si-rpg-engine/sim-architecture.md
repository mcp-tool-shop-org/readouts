# sim-architecture: Deterministic simulation architecture in Rust (wave 3)

**Q1. How do Rust simulation and rollback libraries structure state so it can be saved, hashed, restored and replayed bit-exactly?** As plain data behind one save/load pair, stepped on integer quanta with tick-stamped inputs, proven by restore-and-resimulate: GGRS 0.13.0's `SyncTestSession` rolls back `check_distance` (default 2) frames every frame and compares the checksums the game saves.

**Q2. Which hashing and encoding choices stay stable across Rust versions, platforms and processes?** A named function (FNV-1a per RFC 9923, xxh3, BLAKE3) over bytes the law writes with `to_le_bytes` in a fixed order, sorted, version-tagged. Never `#[derive(Hash)]` streams, `DefaultHasher`, or JSON text.

1. **1/64 s is exact; 1/60 drifts, and an f64 accumulator ran 63 quanta per second at 60, 120 and 144 Hz.** Bevy 2026 (bevy_time 0.19.1 `Fixed`, https://docs.rs/bevy_time/0.19.1/bevy_time/struct.Fixed.html). Implication: the law counts `u64` ticks, the host accumulates integer nanoseconds, the render alpha stays in presentation.
2. **One restore point can pass vacuously; an every-quantum sync test cannot.** GGRS 2026 (`SyncTestSession`, https://docs.rs/ggrs/0.13.0/ggrs/struct.SyncTestSession.html). Implication: T2 restores at several points or runs a distance-2 sync test per fixture. GGRS compares `Option<u128>`, so a `None` checksum checks nothing.
3. **A snapshot is bytes the law defines, never a memory image.** Rust Reference 2026 (Type layout, https://doc.rust-lang.org/stable/reference/type-layout.html). Implication: keep `push_f64`'s `to_le_bytes` and add a magic and law version before T2, so restore can refuse a foreign snapshot.
4. **`#[derive(Hash)]` feeds 18 bytes on x86_64 and 14 on wasm32; `DefaultHasher` is unspecified across releases.** Rust project 2026 (std::hash::Hash, https://doc.rust-lang.org/stable/std/hash/trait.Hash.html). Implication: hash explicit bytes. The solver's `mix_u64` is not FNV-1a and collides on two half-extent pairs; compare geometry bits instead.
5. **A digest built only from u32 input to the two-lane hasher repeats one 32-bit half.** Noll, Vo, Eastlake, Hansen 2026 (RFC 9923, https://www.rfc-editor.org/rfc/rfc9923.html). Implication: S1 pin 13's lane split moves only the snapshot digests (T3's `52bfc19452bfc194`); both goldens stay.
6. **Rapier keeps one generation counter per set, raised on every removal.** Rapier 2026 (rapier3d-f64 0.35.3 `arena.rs`, https://docs.rs/crate/rapier3d-f64/0.35.3/source/src/data/arena.rs). Implication: removal history reaches the snapshot through `into_raw_parts`; persist the file's ids and sort by the full pair key.
7. **serde_json's float text changed at 1.0.147 (Ryū to Żmij, now `1e+21`); `float_roundtrip` round trips stay exact.** serde-rs 2025 (v1.0.147, https://github.com/serde-rs/json/releases/tag/v1.0.147). Implication: Rust bindings read world files with `float_roundtrip` and `deny_unknown_fields`, and never hash the text.
8. **Behaviour numbers name what a golden hash hides.** Catto 2024 (Determinism, https://box2d.org/posts/2024/08/determinism/). Implication: keep `golden-behaviour.json` checked with both goldens; it already exposed the falling climber (T4 pin 8).
9. **Slot 16 is read two ways, and nothing refuses NaN or infinity.** Rust project 2026 (TryFrom, https://doc.rust-lang.org/stable/std/convert/trait.TryFrom.html). Implication: one `Mode` decoder accepting four bit patterns, refusing with body, slot and bits; `is_finite` everywhere (S1 pins 2, 10, 11).
10. **ECS query order is not guaranteed, and archetype storage swap-removes rows.** Bevy 2026 (bevy_ecs 0.19.1 `Query`, https://docs.rs/bevy_ecs/0.19.1/bevy_ecs/system/struct.Query.html). Implication: no ECS in the law; a host that uses one sorts by stable id and pins a single-threaded executor.

**Thin evidence.** The ECS check models the mechanism; bevy_ecs and hecs are outside the oracle, and "no ECS" is judgment. GGRS and backroll status rests on crates.io and GitHub metadata. The JavaScript `-0` and integer text differences were measured with node, not cited. RFC 9923 prints no test vectors, so the frame-hash port is checked against the engine's own `hash.js`. The "ryu output" item was stale: the pinned serde_json uses zmij.
