## [Rust → WebAssembly without bindgen](wasm-raw-abi.md)

So T3's refusal of relaxed-SIMD and memory.grow must come from the binary lint (solver/lint.mjs), not a target switch; revisit only if parry's indexmap dependency drops its default features.

T2's restore_ptr() should point at a fixed static with an exported capacity (or reserve before returning), and solver_restore should decode with from_le_bytes to match push_f64's to_le_bytes.

## [Floating point & cross-platform determinism](float-determinism.md)

- ✓ **Build hashed math from f64 + - * / and sqrt: the same bits on IEEE CPUs, wasm engines and in const eval** — solver/src/lib.rs states the rule in its header ('No other operation than add, sub, mul, div, and sqrt') for `step` and `resolve_pair`; rapier_law.rs's own arithmetic (`canon_quat`, the collider centres and half-extents in `build_world`) stays inside it apart from min/max on positive half-extents, and CLIMB_ANGLE / SLIDE_ANGLE are const-evaluated basic ops. FLAGS.md's 'Nothing in the flags flushes subnormals, so they stay subnormals' holds on both sides: Rust treats a changed DAZ/FTZ state as UB, and wasm defines no flush mode. This is why V8, SpiderMonkey and JavaScriptCore can print one golden.
- ✓ **Canonicalize -0.0 to +0.0 before to_bits() feeds a hash: equal values, different bits** — rapier_law.rs canonicalizes in `write_body` (every stored field), `canon_quat`, `push_f64` (the snapshot) and the exported `canon_zero`, and Rapier 0.35.3 canonicalizes the warm-start impulses it writes under enhanced-determinism. One path hashes raw bits: `signature()` feeds collider and height values to `mix_f64`, and `same_sig` compares the result, so a quantum whose record writes -0.0 where the previous one wrote +0.0 reloads the world and drops the warm-start cache (build.mjs's `box.qx // 0` canonicalizes only the quaternion's x, y, z). That is a reading of the code, not an observed failure; canon before mix_f64 closes it.
- ✓ **Expect a*b+c to stay unfused: rustc never contracts, mul_add always rounds once, wasm has no scalar fma** — FLAGS.md's 'Fused multiply-add is not in that set. It arrives only with relaxed SIMD, which this build disables' is right about hardware fusion, but an explicit `mul_add` in solver/src or in a dependency still yields a fused result (a deterministic software fma), so the sentence is safest as 'no implicit fusion; mul_add only where written'. solver/src at e5fbcb9 has no mul_add; the rapier3d-f64 0.35.3 and parry3d-f64 0.30.2 sources have none either (grep this session). T3's relaxed-SIMD opcode lint is the gate for the only hardware-dependent fusion path.
- ✓ **Gate toolchain and Cargo.lock bumps on goldens plus a libm canary; keep fixed-point for integer-exact parts** — Mirrors T4 pin 6, which makes any bump of the toolchain or of rapier3d-f64 rerun the course before a golden may move; extend the same rule to libm, simba and glam(x) in Cargo.lock, add the canary as a `cargo test` in solver/, and list toolchain-supplied libm symbols from the built wasm (see the rust-toolchain.toml recipe) so the review sees which pin a change came through.
- ✓ **Hash only IndexMap, BTreeMap or sorted order: a fixed hasher does not fix HashMap order across targets** — solver/src holds no hash map; bodies and colliders are index-ordered static arrays and the snapshot sorts contact pairs by collider handle before hashing (rebuild_snapshot). Rapier's own maps are IndexMap<FxHasher32> under enhanced-determinism. Any map added for mesh collision or host bindings should be a BTreeMap or IndexMap on the hashed path.
- ✓ **Keep std sin, cos, exp, ln, powf, atan2 and hypot out of hashed math; call the Cargo.lock-pinned libm** — solver/src (lib.rs, rapier_law.rs at e5fbcb9) calls only sqrt, min and max, so the crate's own code is clean; mirror T3 pin 7, which refuses Math.sin/cos/tan/atan2/hypot in JS scene builders, with a Rust source test over solver/src. The dependency graph is not clean: parry and glamx reach the toolchain's log2, acos and cos through inherent calls (see the rust-toolchain.toml recipe).
- ✓ **Know what rapier3d-f64 0.35.3's enhanced-determinism switches: libm, IndexMap, canonical zeros, not SIMD** — solver/Cargo.toml enables the feature, and FLAGS.md's 'This version has no simd-stable or simd-nightly feature; wide is still a transitive crate' matches parry 0.30.2. The flag matters most for host bindings: a native Godot/Unreal build keeps equal to the wasm law only where libm_force, glamx/libm and canonicalize_zero reach; `WideF64x4::simd_mul_add` would fuse on a native aarch64 build (no call site at these versions, by grep). The IndexMap order depends on the insert/remove sequence, which T2 restore must replay (restore-internals owns the details).
- ✓ **Refuse NaN or map it to one bit pattern before hashing: its sign and payload are the engine's choice** — rapier_law.rs refuses NaN in `signature`, `write_body`, `canon_quat` and `integrate`, and lib.rs's `step` returns 0 on a NaN pose, so no body NaN is hashed. `push_contact` hashes warm-start impulses through `push_f64`, whose `canon` passes a NaN through with the engine's bits; adding `bad()` there (or the one-pattern map) makes the refusal cover every hashed field before the T3 ARM64 lane compares goldens.
- ✓ **Treat rust-toolchain.toml as part of the law: the solver links the toolchain's own log2, acos, cos and sin** — Measured on a scratch copy of solver/ at e5fbcb9 (cargo +1.98.1 build --release --target wasm32-unknown-unknown --locked): si_solver.wasm's name section lists libm::math::{sin, cos, sqrt, acos, asin, atan, atan2, sincos, floor, ceil, copysign} and compiler_builtins::math::libm_math::{sin, cos, acos, log2}. A wasmparser call graph reaches log2 from `solver_load`/`solver_step` through `BroadPhaseBvh::update` and parry's `Bvh::optimize_incremental`, whose `.log2()` feeds a `.round()` that sets how many subtrees to rebuild; acos/cos are reached from `MassProperties + MassProperties` through glamx `symmetric_eigen`; sin/cos also through the joint builders, which the law does not use. Whether any of these moves the golden is unmeasured; the toolchain pin (1.98.1) is what holds them.
- ✓ **Write the min/max tie rule yourself: f64::max(-0.0, 0.0) changes with context, minimum/maximum are nightly** — lib.rs's `js_min`/`js_max` (the overlap in `resolve_pair`) implement JS's zero ordering explicitly, so the box step does not depend on the tie rule. Their NaN behaviour is asymmetric and unlike Math.min: js_min(1, NaN) = 1 but js_min(NaN, 1) = NaN, harmless while `step` returns 0 on a NaN pose. rapier_law.rs's `half.x.min(half.z)` and `(half.y - radius).max(0.0)` act on strictly positive half-extents, so no zero tie arises there.

## [Rapier 0.35: pipeline, determinism & upgrades](rapier-core.md)

- ✓ **Call PhysicsPipeline::step at 0.35.3 with its 12 arguments and read contacts as start-of-step state** — rapier_law.rs `integrate` calls `loaded.world.step()` (PhysicsWorld: no hooks, no events) after set_next_kinematic_translation and solve_character_collision_impulses, and `rebuild_snapshot` then hashes contact pairs computed before that quantum's integration. `bad()` tests is_nan() only, so an infinite velocity in a body record passes `signature`, reaches Rapier, is quarantined and is written back finite by `write_body`: refuse `!x.is_finite()` and `!loaded.world.quarantine().is_empty()` right after `step()` so that 'NaN aborts a step' also covers what Rapier absorbs.
- ✓ **Collect Rapier 0.35.3 collision events with a Sync EventHandler and ActiveEvents set on a collider** — rapier_law.rs passes no handler (`world.step()`), so no event reaches the hash today. T3's plan to hash collision-event order separately from body state needs ActiveEvents on the tracked colliders and a Sync collector (a Mutex<Vec<_>> or ChannelEventCollector) drained after `step()` in `integrate`; this lane measured delivery, not the order of simultaneous events, so T3 must measure that order before hashing it.
- ✓ **Count Rapier 0.35.3 sleep in quanta: time_until_sleep = 32·dt sleeps after quantum 32, 33 off the origin** — rapier_law.rs `build_world` sets `activation_mut().time_until_sleep = SLEEP_QUANTA * DT` (32/64 s, exact) on dynamic bodies inserted at their record position, so a body at rest from load sleeps after quantum 33, not 32; `rebuild_snapshot` hashes `time_since_can_sleep / DT`, an exact integer while dt = 1/64. A rebuilt world starts every body at sleep_prev_pose = identity, so a restore path (T2, restore-internals) resets each off-origin body's count on its first step; this is inferred from the measured first-quantum loss, not yet run as a restore.
- ✓ **Expect Rapier 0.35.3 body types to gate contacts: kinematic-fixed off, kinematic pushes dynamic one way** — rapier_law.rs `build_world` makes driven bodies kinematic_position_based() with lock_rotations, can_sleep(false), ccd_enabled(false) and additional_mass(1.0), and slabs and the heightfield fixed(); with default ActiveCollisionTypes the walker has active contacts only with dynamic boxes, and `integrate` resolves walls with KinematicCharacterController::move_shape (shape casts, not contacts) and pushes boxes with solve_character_collision_impulses. Two walkers are kinematic-kinematic and get no contacts either, so T4's 'character against a character' case is decided by the controller's casts alone.
- ✓ **Filter Rapier pairs with collision_groups (no contact) or solver_groups (contact, no force); flag the hooks** — rapier_law.rs sets no groups and no hooks and passes `&()`, so every pair interacts. Groups and hooks are law: a filter that reads anything outside the record (host state, time) breaks replay. If the post-Phase-2 mesh slice needs one-way surfaces or character-only walls, store the group bits in the world file and mix them into `signature`'s geometry hash with the shapes.
- ✓ **Govern a rapier3d-f64 bump: pin =0.35.3, read every CHANGELOG entry to the target, rerun course and goldens** — solver/Cargo.toml has `version = "0.35.3"` (caret) with solver/Cargo.lock at 0.35.3; T4 pin 6 adds FLAGS.md's sentence that any rapier3d-f64 or toolchain bump reruns harness/course.test.js before a golden moves. A 0.36 bump rewrites rapier_law.rs `solver_clear_warmstart` (it writes pair.manifolds and pair.solver_clusters, which move to ContactPair::contacts), must recheck `rebuild_snapshot`'s pair.solver_manifolds() against 0.36's accessors, and can replace `warm_broadphase` with PhysicsWorld::detect_collisions.
- ✓ **Hold Rapier to its stated determinism terms: same build and inputs, enhanced-determinism, same insertion order** — si-rpg-engine meets the written terms: enhanced-determinism on, parallel off, f64, block-solver by default, rustc 1.98.1 pinned by solver/rust-toolchain.toml, and `build_world` inserts slabs, the heightfield, then bodies in record order. Rapier's promise covers IEEE 754 CPUs; the three-JS-engine golden is the engine's own evidence for wasm engines. T3's test that insertion order changes the hash should go red, as it does here on a box pile.
- ✓ **Pin rapier3d-f64 0.35.3 features explicitly: block-solver is a default and docs.rs documents other builds** — solver/Cargo.toml declares `rapier3d-f64 = { version = "0.35.3", features = ["enhanced-determinism"] }` with defaults on, and solver/FLAGS.md already records dim3, f64, std, block-solver and parallel off; spelling the list out in Cargo.toml turns that sentence into a pin, and a CI snapshot of `cargo tree -e features -i rapier3d-f64` (ci-reproducible-builds) catches drift. Restore work that uses serde (request 4 in docs/rust-kb-requests.md) is a feature change and a new binary.
- ✓ **Read rapier3d-f64 0.35.3 IntegrationParameters defaults from code: prediction 0.02, slop 0.005, CCD on** — rapier_law.rs `build_world` sets dt = 1/64, contact_clustering = false and warmstart_coefficient = 1.0 (a no-op) and inherits the rest, so the law runs with contact_recycling = true and max_ccd_substeps = 1: dynamic bodies built with ccd_enabled(false) are still swept against fixed slabs and the heightfield. T4 pin 2 assumes the thin fast body 'passes through' today; measured here, a 0.05-half box at 20 u/s with ccd_enabled(false) stops at x 0.921 in front of a 0.02-half slab. Measure the exact T4 scene before moving goldens (the tunnelling numbers belong to binary-and-limits); the recycled pair state is outside the snapshot, a T2 question for restore-internals.
- ✓ **Warm Rapier's broad phase with one CollisionPipeline::step at load, then re-mark bodies with iter_mut** — rapier_law.rs `warm_broadphase` (the E3 fix, commit 39687d9) works, but its comment credits wake_up(true): re-admission comes from `world.bodies.iter_mut()` re-marking every body, and a refactor to `world.wake_up(handle, true)` would freeze every dynamic body. T2's `solver_restore` reruns the load's collision pass on mid-run worlds where bodies touch, so a native debug test of that path panics at manager.rs:140: test it in release or through the wasm build. 0.36.0 adds PhysicsWorld::detect_collisions (collision detection without stepping), a candidate replacement for this pass.

## [Rapier shapes, meshes & the character controller](rapier-shapes-kcc.md)

- ✓ **Bake glTF collision meshes offline with the gltf crate and refuse what the deterministic law cannot reproduce** — The collision-from-meshes slice after Phase 2 (its input is the studio's glb survey) should keep the gltf crate in host tooling: the law is a wasm32-unknown-unknown cdylib with raw extern "C" exports over static f64 buffers and a pinned digest, and at load it already refuses NaN and renormalises quaternions with canon_quat. The world file carries the baked buffers; solver_load validates them like body rows and mixes them into Signature.geom.
- ✓ **Call KinematicCharacterController::move_shape with Absolute lengths and self-exclusion, then apply the result** — rapier_law.rs controller() already sets SKIN 0.01, STEP_HEIGHT 0.3, STEP_MIN_WIDTH 0.2 and SNAP 0.2 as CharacterLength::Absolute with CLIMB_ANGLE pi/4, SLIDE_ANGLE 50 degrees in radians and normal_nudge_factor 1e-4, so character_shape can switch between SharedShape::cuboid and capsule_y without moving those lengths; integrate() excludes the walker's own body, applies the move with set_next_kinematic_translation, zeroes vy on grounded and ignores is_sliding_down_slope. fixtures/shape-traversal.json kept the box (docs/PHASE-1.md: it climbs a step of the maximum height and holds a ledge where the same-size capsule misses the step and drops); below the limit both shapes climbed alike here, feet at step + 0.010. Lifted actions (DRIVEN 2.0) bypass move_shape.
- ✓ **Canonicalise -0.0 and weld vertices offline: MERGE_DUPLICATE_VERTICES keys raw bits and renumbers the mesh** — signature() in rapier_law.rs mixes every geometry f64 with mix_f64 (to_bits), so -0.0 and 0.0 already give different world signatures. The mesh slice's offline tool should apply the same canon() that write_body uses, and the loader should refuse a non-canonical value, which is the pattern T3's load-time refusal of non-finite authored values already follows.
- ✓ **Compute convex hulls and VHACD parts offline with pinned parameters, then load stored buffers with convex_mesh** — The post-Phase-2 slice plans 'hull point sets stored offline for determinism': store try_convex_hull's vertex and triangle-index buffers rather than only the points, load them with ColliderBuilder::convex_mesh, and refuse a mass-0 hull at load. VHACD belongs in the offline tool: its O(resolution^3) voxel grid would be a transient allocation inside a solver binary whose memory T3's lint forbids from growing.
- ✓ **Fill a parry HeightField column-major with scale as the whole extent, and sample it as two triangles per cell** — build_world in rapier_law.rs transposes the row-major HEIGHTS buffer with data[row + col * rows] and passes ((cols - 1) * cell, 1, (rows - 1) * cell) on a fixed body at the origin, which matches parry, and signature() refuses fewer than 2 rows or columns before HeightField's assert can fire; MAX_HEIGHTS 256 caps a field at 256 heights (16 x 16, say). packages/tick/world.js heightfieldSupport, which supportAt hands to the verb predicates, interpolates bilinearly, so on a non-planar cell it reports a height the solver's surface does not have.
- ✓ **Pick parry 0.30.2 shapes by body role: primitives, convex or compound on moving bodies, trimeshes on fixed** — solver/src/rapier_law.rs builds only ColliderBuilder::cuboid colliders (static slabs and every body), one ColliderBuilder::heightfield, and character_shape's SharedShape::cuboid / capsule_y for the controller. The post-Phase-2 collision-from-meshes slice should put TriMesh only on RigidBodyBuilder::fixed() and give dynamic bodies convex_mesh or compound colliders; Signature's geom hash would then have to cover the mesh buffers the way it covers collider rows today.
- ✓ **Push dynamic bodies with solve_character_collision_impulses and plan all walkers against the last step's poses** — integrate() in rapier_law.rs plans every walker with move_shape before any set_next_kinematic_translation, then calls solve_character_collision_impulses with character_mass 1.0 (walkers get additional_mass(1.0)) and include_dynamic_bodies: false. For T4 pin 5's two walkers driven at each other: at the verb speed of 1 u/s (predicates/intents/*.json) they ended 0.0646 apart here; at 8 u/s, above world.js's MAX_SPEED 2, they ended 0.0318 overlapped.
- ✓ **Set FIX_INTERNAL_EDGES on ground dynamic bodies slide over; test heightfield row 0 moving +x on its own** — build_world calls ColliderBuilder::heightfield with no flags, so T4 pin 3's seam test (a box sliding down across a cell boundary with no upward hitch beyond the skin) is where heightfield_with_flags(.., HeightFieldFlags::FIX_INTERNAL_EDGES) gets measured; adopting it changes the binary digest and the goldens once. That test needs a crossing in row 0 moving +x: a 2-row field, which signature() allows and packages/tick/verbs.test.js uses for its sloped case, has no other row.
- ✓ **Test line of sight with an eye-to-target ray at max_toi 1.0 on fixed colliders once the broad phase holds them** — E5 sight runs in the JS tick (distance at most `sight` and a zero-extent swept segment crossing no static collider), and docs/dispatch-e5-minds.md keeps the binary unchanged for it. Once collision-from-meshes adds TriMesh statics, a box-only JS segment test cannot answer; the matching law query is cast_ray(Ray::new(eye, target - eye), 1.0, true) with QueryFilter::only_fixed(), exported like solver_step and run only after solver_load, whose warm_broadphase CollisionPipeline pass is what puts the colliders in the broad phase.

## [Deterministic simulation architecture](sim-architecture.md)

- ✓ **Encode snapshots canonically: to_le_bytes in a fixed field order, sorted pairs, no padding, a version tag** — rapier_law.rs rebuild_snapshot already follows most of this: `push_f64` writes `canon(x).to_le_bytes()` per field in a fixed per-body order (pose, velocity, quaternion, spin, sleep counter in quanta, sleeping flag), then the pair count, then pairs sorted by `(collider1.into_raw_parts(), collider2.into_raw_parts())` with seven warm-start f64s per manifold point; counts and ids go in as f64, exact below 2^53. It has no magic and no version word, which is why T3 records length plus digest to notice a layout change. T2's solver_restore must refuse a foreign snapshot; a version word in the header is the direct way, and adding one moves the product golden once.
- ✓ **Keep the law out of an ECS: archetype tables swap-remove rows and query iteration order is not guaranteed** — The law is solver/src: stride-17 `BODIES`, stride-10 `COLLIDERS` and one Rapier `PhysicsWorld` whose handles follow insertion order (recipe on stable ids). An ECS in the law would add a second storage whose order must be sorted back into record order before every Rapier insert and before the snapshot. The Godot and Unreal hosts after Phase 2 bring their own scene trees; keep them on the presentation side of the boundary. Judgment, not measurement: no ECS in the law; revisit only if the record outgrows fixed strides.
- ✓ **Key records by stable ids, keep insertion and removal history in the record, and sort by a total id key** — rapier_law.rs build_world inserts the static colliders, then the heightfield, then the bodies, in record order; rebuild_snapshot sorts pairs with `sort_by` on `into_raw_parts()` and pushes both colliders' index and generation as f64, so insertion and removal history sit inside the hashed bytes. Today nothing is removed without a reload (a carried body changes the signature and ensure() rebuilds the world), so generations stay 0. S1 pins 6 and 9 keep the stable sort and add a removal-and-reinsertion case to T3's insertion-order test (T3 pin 5); T2's restore must reproduce the removal count as well as the live set.
- ✓ **Parse host-written body slots into a typed record at the boundary, with named refusals for the mode slot** — solver/src/lib.rs step() and resolve_pair() read `*field(bodies, i, DRIVEN) != 0.0`; solver/src/rapier_law.rs signature() reads `b[DRIVEN] == 1.0 // b[DRIVEN] == 2.0`, then `== 3.0`, and integrate() re-reads `b[DRIVEN] == 2.0`; `bad()` is `x.is_nan()`, and canon_quat normalises any finite non-zero quaternion instead of refusing it. solver/build.mjs writeInputs writes `body.solverMode` into slot 16 verbatim whenever it is a JavaScript number. S1 (docs/dispatch-s1-soundness.md) pins 2, 10 and 11 schedule the fixes: one mode function accepting exactly 0 to 3 with the step returning 0, `bad()` becoming `!x.is_finite()`, and canon_quat refusing what it cannot normalise; T2 pin 1 refuses a quaternion not unit within 1e-9 on restore.
- ✓ **Persist hashes of explicit little-endian bytes, never #[derive(Hash)] streams or DefaultHasher output** — rapier_law.rs signature() folds half-extents, collider fields and heights into `geom` with `mix_u64(h, x) = h.wrapping_mul(0x100000001b3).wrapping_add(x)` from basis 0xcbf29ce484222325: FNV-64 constants, not FNV-1a. The check finds half-extents (0.5, 0.5) and (0.5000000000000001, 0.49993896484372585) with the same `geom`, where FNV-1a 64 and xxh3_64 over the same bytes differ. `geom` only decides whether ensure() rebuilds the world, but equal `geom` does not prove equal geometry: keep the canonical geometry values and compare their bits (a few KB at 64 bodies, 64 colliders and 256 heights), or hash their little-endian bytes with FNV-1a 64 or xxh3. The JavaScript frame hash is the next recipe.
- ✓ **Prove the record complete twice: replay seed plus stamped inputs, and save-restore-rerun every quantum** — README: 'Replay is the seed plus the log of what was admitted'; `npx replay` fails on the first differing hash, and T5's nightly bundle (seed, world, log, hash chain) is this record. T2 (docs/dispatch-t2-restore.md pin 5, PR #43) restores once, 'a third of the way', under harness/first-difference.js; the check shows a single point can miss state that is still at its default there, so restore at several points per fixture or run an every-quantum sync test with distance 2, which is cheap at 64 bodies. rapier_law.rs rebuild_snapshot already writes `time_since_can_sleep / DT` and the sleeping flag, the kind of counter the check shows a snapshot can drop.
- ✓ **Read world files with serde_json's float_roundtrip, refuse unknown fields, and hash parsed bits, not text** — World files (worlds/*.json) are parsed by JavaScript today, and the loader refuses unknown fields and non-unit quaternions with reasons (README). The Godot and Unreal bindings planned after Phase 2 will read the same files from Rust: they need `float_roundtrip` to see the bits JavaScript sees, `deny_unknown_fields` for refusal parity, and a rule never to hash the text. fixtures/golden-behaviour.json stores final positions as JavaScript-written numbers (`"x": 2` for the climber); harness/behaviour.mjs compares parsed values with `Object.is`, the right side of this line.
- ✓ **Run the law on integer quanta from a host-owned accumulator; keep render interpolation out of the state** — packages/tick/tick.js runs the 1/64 s quantum in JavaScript and mixes `hasher.u32(tick)`, so time enters the hash as an integer; solver/src/lib.rs and rapier_law.rs hold `DT = 1.0 / 64.0` as a constant and read no clock. README: 'Presentation has no path back into the hash', and packages/frame/frame.js freezes the committed frame the host receives. The gap is the ABI: `bodies_ptr`, `colliders_ptr` and `heights_ptr` hand JavaScript writable f64 views, so on the Rust side the rule rests on signature()'s per-call checks, not on types. A Godot or Unreal host keeps its own accumulator and drives the law by quantum count, never by frame delta.
- ✓ **Stop feeding u32-only streams to both FNV-1a lanes: such a digest repeats one 32-bit half** — packages/frame/hash.js `u32()` and `digest()`; harness/trace-line.mjs `snapshotField`, the T1 trace's `snap <len> <digest>` token; and the behaviour-file digests: the T3 branch (PR #44, head b99a636) records `snapshotDigest` load 52bfc19452bfc194 and last 41b1e63f41b1e63f in fixtures/golden-behaviour.json, both with identical halves. S1 pin 13 (docs/dispatch-s1-soundness.md) takes option A and states that the product golden and every frame hash stay while the behaviour-file digests move once with that reason.
- ✓ **Version the law with golden hashes plus behaviour numbers, so each golden move names what moved** — harness/check.js matches harness/sim.mjs against fixtures/golden.txt (the product golden, fd2f6c03fb982d77 at 0.1.0) and harness/arith.mjs against fixtures/golden-arith.txt (0d38671370d12d1e, unmoved since the first harness), then compares fixtures/golden-behaviour.json — sleep quanta per dynamic body, final positions, the walker's zone, snapshot bytes 848 at load and 1840 after 10,000 quanta — and names every moved number. It has already paid for itself: the file showed `climber` never sleeping and ending near y = -50874, a scene defect the hash hid, which T4 pin 8 fixes; T4 pin 6 makes write-golden refuse to write while the course or an outcome test fails.
