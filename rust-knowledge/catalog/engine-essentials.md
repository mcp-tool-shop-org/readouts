## [Ownership, moves & borrowing](ownership-borrowing.md)

- ✓ **Borrow struct fields directly, not through &mut self getters; edition-2021 closures capture only used fields** — rapier_law.rs `integrate` already uses the destructuring form: `let PhysicsWorld { broad_phase, narrow_phase, bodies, colliders, .. } = world;` lends four disjoint public fields of one `&mut PhysicsWorld` (rapier3d-f64 0.35.3) to `broad_phase.as_query_pipeline_mut(narrow_phase.query_dispatcher(), bodies, colliders, filter)`. Routing the same call through `&mut self` getters on a wrapper struct would be E0499.
- ✓ **Keep one &mut xor any number of & live at once, and end each borrow at its last use (E0499, E0502, E0506)** — `step` and `resolve_pair` in solver/src/lib.rs never keep a reference across a write - each read is copied into a local first - so NLL has nothing to reject; keep that order in Phase-2 code. rapier_law.rs `integrate` already uses the collect-then-apply fix: it builds `plans` in one loop and calls `set_next_kinematic_translation` in a second.
- ✓ **Keep the owner alive past its last borrow: fix E0597, E0716 and E0515 by binding it or returning owned data** — solver/ is edition 2021 (solver/Cargo.toml), so a helper whose tail expression creates a guard that borrows a local (the `RefCell::borrow()` shape) hits the 2021 E0597 rule even though the same code compiles in an edition-2024 crate; bind the value to a local before returning.
- ✓ **Move a value out from behind &mut with mem::take, mem::replace or mem::swap instead of fighting E0507** — The solver's `*field(bodies, i, slot)` reads in solver/src/lib.rs work only because the payload is f64 (Copy); the same accessor over a non-Copy payload is E0507. In rapier_law.rs, `Solver { loaded: Option<Loaded>, snapshot: Vec<u8> }` is the state that `ensure` replaces today with `solver.loaded = Some(loaded)`; if T2 `solver_restore` needs the old world or buffer back, `solver.loaded.replace(new)` or `mem::take(&mut solver.snapshot)` returns it by move, with no clone.
- ✓ **Name lifetimes only where the three elision rules fail: two reference inputs, none, or a struct field (E0106)** — `field` in solver/src/lib.rs is the rule-2 case: one reference input (`&mut [f64]`) and two `usize`s, so the returned `&mut f64` borrows `bodies` and nothing else. The crate is edition 2021 on 1.98.1, so `mismatched_lifetime_syntaxes` fires on any new helper that returns an `Iter<f64>`-style type beside a reference input.
- ✓ **Pass a held &mut to generic parameters as &mut *r: concrete &mut parameters reborrow, generic T moves (E0382)** — `step` in solver/src/lib.rs binds `let bodies = &mut BODIES;` (type `&mut [f64; 1088]`) once and passes it to `field` and `resolve_pair` on every iteration; each call reborrows and unsizes it to `&mut [f64]` because those parameters are concrete. A Phase-2 helper written generically (e.g. `fn apply<B: AsMut<[f64]>>(b: B)`) would move `bodies` on the first call and fail with E0382 on the second - pass `&mut *bodies`.
- ✓ **Split one flat buffer into disjoint &mut with split_at_mut, as_chunks_mut and get_disjoint_mut (1.86+)** — solver/src/lib.rs `resolve_pair(bodies, i, j)` copies every slot it needs into a local through `*field(..)` (7 per body up front, positions re-read before each write), so two `&mut` into the flat `BODIES` buffer (64 bodies x stride 17) never coexist and nothing needs splitting; keep that while the kernel mirrors the JS order. If a rewrite wants both rows mutable at once, use `let (rows, _) = bodies.as_chunks_mut::<BODY_STRIDE>();` then `let Ok([a, b]) = rows.get_disjoint_mut([i, j]) else { return };`, or `bodies.split_at_mut(body_at(j))` with i < j (the only order `step` passes); two `field()` results held together are E0499.
- ✓ **Take &[T], &mut [T] and &str parameters instead of &Vec<T>, &String or &[T; N]** — `field(bodies: &mut [f64], i, slot)` and `resolve_pair(bodies: &mut [f64], i, j)` in solver/src/lib.rs already take slices, and `step` passes `&mut BODIES` (a `[f64; 1088]` static) through an unsize coercion; keep new solver helpers on `&[f64]`/`&mut [f64]` so native tests can call them on a small local array instead of the static buffers.
- ✓ **Treat every by-value use as a move: derive Copy only for plain data, clone on purpose (E0382, E0505, E0204)** — solver/src/lib.rs reads every slot as `let ax = *field(bodies, i, 0);`: f64 is Copy, so the value is copied out and the `&mut f64` from `field` dies in that statement. rapier_law.rs copies whole rows the same way (`body_at(i) -> [f64; BODY_STRIDE]`), and `integrate` copies `loaded.controller` out of `&mut Loaded` because `KinematicCharacterController` derives Copy in rapier3d-f64 0.35.3; a non-Copy field on that line would be E0507.

## [Structs, enums & pattern matching](types-patterns.md)

- ✓ **At the raw extern "C" edge, bounds-check counts and TryFrom each mode number into an enum; refuse the rest** — lib.rs `step()` and rapier_law.rs `signature()` both test `n_bodies as usize > MAX_BODIES` first (e5fbcb9). That test also guards the u64 masks: `signature()` sets `driven /= 1u64 << i` and `carried /= 1u64 << i`, sound only while MAX_BODIES <= 64. With the solver's release settings (`overflow-checks = false`, opt-level 3), `1u64 << 64` evaluates to 1 on the host and on wasm32 (measured), so raising MAX_BODIES without widening the masks would alias body 64 onto body 0 with no error. T2's `solver_restore(world_id, n_bodies, n_colliders, rows, cols, cell, shape, len)` (docs/dispatch-t2-restore.md) adds a byte length and must compare the snapshot's pair and point counts, which `rebuild_snapshot` writes as f64 (`pairs.len() as f64`, `n_points as f64`): bound `len` by the restore buffer before slicing and decode each stored count with the same exact round trip before comparing or using it. `shape: u32` (1 = capsule, any other value = cuboid today) is the next candidate for TryFrom decoding.
- ✓ **Chain Option and Result with map, and_then, filter, ok_or_else and ?; convert between them explicitly** — rapier_law.rs already uses `?` on Option in `quat_from_body` (`let (x, y, z, w) = canon_quat(..)?;`). In `build_world`, which returns Option too, `let Some((qx, qy, qz, qw)) = canon_quat(c[6], c[7], c[8], c[9]) else { return None; };` is equivalent to `let (qx, qy, qz, qw) = canon_quat(c[6], c[7], c[8], c[9])?;`. `solver_load` returns `if ensure(..) { 1 } else { 0 }`; `u32::from(ensure(..))` is the same conversion (From<bool> for integers, 1.28).
- ✓ **Flatten refutable matches with let-else (1.65+); let chains need edition 2024; if-let guards work since 1.95** — rapier_law.rs already uses let-else for its refusal paths (`let Some(sig) = signature(..) else { return false; };` in `ensure`, the canon_quat checks in `build_world`). The crate is edition 2021, so let chains are unavailable until an edition move; the pinned 1.98.1 toolchain does accept if-let guards, which suit a future `match` over decoded modes.
- ✓ **Keep patterns edition-2024 clean: no `mut`, `ref` or `&` inside an implicitly borrowing pattern** — The solver crate is edition 2021 (solver/Cargo.toml). Measured 2026-09-25: a scratch copy of solver/src/lib.rs + rapier_law.rs at e5fbcb9 compiled with rustc 1.98.1 `--edition 2021 -W rust_2024_incompatible_pat` against rapier3d-f64 0.35.3 reports no site, so binding modes will not block a 2024 move; the other edition-2024 changes the solver would meet belong to the rust-currency lane.
- ✓ **List every variant in a match: a `_` arm silently absorbs variants added later** — When the solver matches on its own decoded mode enum (ABI-edge recipe), write every arm: a `_ => dynamic` arm would rebuild today's rapier_law.rs behaviour in which any unknown slot-16 value is dynamic. Matches over Rapier's RigidBodyType can stay `_`-free under the pinned rapier3d-f64 0.35.3, which makes a variant added by a future bump a compile error at each site — one more tripwire beside the golden hashes.
- ✓ **Model a closed set of body states as an enum with per-variant data, not a flag number or parallel vectors** — Body slot 16 (`solverMode`, set by `solverModes` in packages/tick/world.js: 0 undriven, 1 driven, 2 driven and lifted, 3 carried) is an f64 read two ways at e5fbcb9. lib.rs `step()` tests `!= 0.0`: every non-zero value, NaN included, is driven, and there is no lifted or carried case. rapier_law.rs `signature()` tests `== 1.0 // == 2.0` then `== 3.0`: 4.0, 1.5 and NaN all fall through to dynamic. Neither refuses an unknown value, and no NaN check covers slot 16 (step() checks slots 0-5 after stepping; signature() checks 0-15). Inside `Loaded`, `kinematic: Vec<bool>` and `handles: Vec<Option<RigidBodyHandle>>` encode per-body state in parallel, and `integrate()` has to skip the (kinematic, None) combination with `let Some(handle) = .. else { continue; }`. `Face.axis: u8` with `rank()`'s final `else { 2 }` (any byte not b'y' or b'x' ranks as z) is the same pattern in miniature; an `enum Axis` makes the ranking an exhaustive match.
- ✓ **Pick named-field, tuple or unit structs by meaning; hang constructors and constants on impl blocks** — rapier_law.rs builds `Loaded.signature` by copying `Signature` field by field and compares signatures field by field in `same_sig`. `Signature` is a named-field struct of u32/u64 only (the f64 `cell` is stored as `to_bits()`), so derived Clone/Copy/PartialEq/Eq (contracts: traits-generics lane) could replace both hand-written copies. The slot numbers (`HX`..`DRIVEN` in lib.rs, `QX`..`WZ` in rapier_law.rs) are free consts; associated consts on a record type would namespace them without touching the ABI.
- ✓ **Treat `as` as silent truncation or saturation; convert integers with From or TryFrom so a loss is visible** — `snapshot_len()` returns `SOLVER.snapshot.len() as u32`: lossless on wasm32, where usize is 32 bits, but a silent truncation past 4 GiB if the law is ever compiled natively for 64-bit host bindings; `u32::try_from(len)` makes that assumption checked. In `rebuild_snapshot`, `i1 as f64` / `g1 as f64` convert Rapier's u32 handle parts (`into_raw_parts() -> (u32, u32)`) exactly — `f64::from(i1)` says so in the type — while `pairs.len() as f64` and `n_points as f64` are usize-to-f64, exact only below 2^53.
- ✓ **Use slice, @, range and array patterns (and matches!) instead of index arithmetic and comparison chains** — `body_at(i)` in rapier_law.rs returns `[f64; BODY_STRIDE]` and the code indexes it by named consts (b[QX], b[DRIVEN]); `let [x, y, z, vx, vy, vz, qx, qy, qz, qw, wx, wy, wz, hx, hy, hz, mode] = body_at(i);` names every slot once and stops compiling (E0527) if BODY_STRIDE changes. Matching slot 16 directly as `match mode { 0.0 => .., 1.0 / 2.0 => .., 3.0 => .., _ => refuse }` is legal but needs the `_` arm and sends -0.0 to the 0.0 arm — decode it to an enum once instead (ABI-edge recipe).
- ✓ **Wrap units and ids in tuple-struct newtypes; keep type aliases for renames and long names** — `solver_load` and `solver_step` take `(world_id: u32, n_bodies: u32, n_colliders: u32, rows: u32, cols: u32, cell: f64, shape: u32)`: five u32s whose transposition (rows for cols) compiles. Wrapping them in newtypes at the top of the export makes a swap a compile error inside Rust while the wasm signature stays the same. Sleep is counted in quanta (`SLEEP_QUANTA * DT` becomes `time_until_sleep`); a `Quanta` newtype with a single `seconds()` conversion keeps quanta and seconds from mixing.

## [Traits & generics — the working set](traits-generics.md)

- ✓ **Define traits with required and default methods; state generic bounds inline or in a where clause** — solver/src (lib.rs, rapier_law.rs) declares no trait, impl block or derive today (read at origin/main 4782a8a; solver/ is unchanged since 2c2631f): the law is free functions over static f64 buffers. A trait earns a place only where two implementations must be interchangeable; whether the box law and the product law share one is traits-advanced's hook.
- ✓ **Derive Debug, Clone, Copy, PartialEq and Default on plain data; implement Display by hand** — Snapshot bytes in solver/src/rapier_law.rs are written value by value with `push_f64` (`canon(x).to_le_bytes()`), never through Debug formatting. Keep it that way: derived Debug output may change across Rust versions, which would move a golden on a toolchain bump (the toolchain is pinned to 1.98.1 by solver/rust-toolchain.toml).
- ✓ **Derive only PartialEq and PartialOrd on structs with f64 fields; derived Eq, Hash and Ord fail with E0277** — For T2 (`solver_restore`: restore, rerun, require an identical trace), compare restored state with `to_bits()`, not with a derived `==`: derived PartialEq calls 0.0 and -0.0 equal and NaN unequal to itself, while the hashed snapshot compares bits. The law also uses float == on purpose: `canon` in rapier_law.rs (`if x == 0.0 { 0.0 } else { x }`) folds -0.0 into +0.0 because -0.0 == 0.0, and in `signature` each value passes `bad` (`x.is_nan()`) before it is mixed into `geom`.
- ✓ **Implement From for lossless conversions and TryFrom for checked ones; never Into; accept AsRef or Borrow** — rapier_law.rs `signature` turns raw ABI values into refusals by returning None (NaN via `bad`, non-positive half-extents, counts over MAX_BODIES or MAX_COLLIDERS). A `TryFrom<f64>` newtype such as a positive half-extent is the trait-shaped version of that check, done once at the boundary; the #[repr(u8)] mode enum with TryFrom<u32> is types-patterns' hook.
- ✓ **Implement Iterator for your own type with type Item and next(); the adapters and for loops come free** — rapier_law.rs walks bodies by index (`for i in 0..n_bodies as usize { let b = body_at(i); .. }`), where `body_at` copies one 17-slot row out of `static mut BODIES` into a `[f64; BODY_STRIDE]`. An iterator replacing those loops should keep yielding copies (Item = [f64; BODY_STRIDE]) so it holds no reference into the static; static mut rules are the unsafe-ffi lane's.
- ✓ **Key f64 values by their bits: Eq and Hash from to_bits, Ord from total_cmp, never partial_cmp().unwrap()** — `mix_f64(h, x)` in solver/src/rapier_law.rs is `mix_u64(h, x.to_bits())` (multiply by 0x100000001b3, add; seed 0xcbf29ce484222325), so 0.0 and -0.0 feed different words. `push_f64` writes `canon(x).to_le_bytes()` into the snapshot, but `signature` mixes raw collider and height values into `geom`, and `same_sig` compares `geom`: a collider coordinate of -0.0 therefore signs a different world (reload) than 0.0. That is a reading of the code, not a measured failure, and worth one test. `Signature` already keys its float by bits (`cell: u64` = `cell.to_bits()`), so every field is an integer and `#[derive(PartialEq, Eq, Hash)]` would be legal and would replace the hand-written `same_sig`, which silently ignores a field someone forgets to add. The snapshot pair sort keys on pairs of `(u32, u32)` tuples from `into_raw_parts()`; ColliderHandle itself derives Eq and Hash but not Ord in rapier3d-f64 0.35.3, so it cannot be sorted directly, and integer tuples need no float comparator.
- ✓ **Overload vector math with std::ops on a Copy Vec3, or reuse Rapier's glam DVec3 that already has the ops** — rapier_law.rs already does its vector math on Rapier's `Vector` (`Vector::new(b[3], vy, b[5]) * DT`, `pos.translation + Vector::new(..) * DT`), which in rapier3d-f64 0.35.3 is parry's alias for glam `DVec3`; the ABI stays flat f64 slots. A local Vec3 newtype earns its place only for impls Rapier's type cannot carry, such as a bit-exact Eq/Hash key or a JS-compatible Display, not for arithmetic.
- ✓ **Prefer monomorphized generics; use Box<dyn Trait> for mixed-type collections or to cut code size** — The solver's bodies are rows of one flat f64 buffer (`BODIES`, stride 17 in solver/src/lib.rs) and a body's kind is a slot value, so no call site in solver/src needs dyn today; if heterogeneous shapes or laws appear, a generic or an enum plus match (types-patterns) keeps dispatch static.
- ✓ **Satisfy the orphan rule with a local newtype and forward its methods; Deref does not confer trait impls** — Rapier's `Vector` (glam DVec3) and `ColliderHandle` are foreign to si-solver, so any Hash, Ord or Display the law needs on them goes through a local wrapper or a local function. That is what the solver already does: `mix_f64` hashes components one by one, and the pair sort uses `into_raw_parts()` tuples.

## [Errors, panics & arithmetic safety](errors-panics.md)

- ✓ **Derive library error enums with thiserror 2; use anyhow or `Box<dyn Error + Send + Sync>` only in binaries** — Neither crate belongs in `solver/`: its loading and stepping exports report outcomes as `u32` 1/0 and the crate links only `rapier3d-f64`, so any new dependency there is a change to review against the pinned digest in `fixtures/solver.sha256`. thiserror fits a future native crate around the law (a host binding, a scene loader); anyhow fits Rust-side tools.
- ✓ **Give a library one error enum per failure mode and let `?` convert wrapped causes through `From`** — The solver has no error type yet: every refusal in rapier_law.rs (`signature`, `build_world`, `canon_quat`, `write_body`, `integrate`, `rebuild_snapshot`, `ensure`) is an `Option` or a `bool` that collapses into an export's `0`. A fieldless `Refusal` enum returned through `?` is the internal type the export recipe in this lane builds on; being `core`-only, it costs nothing on `wasm32-unknown-unknown`.
- ✓ **Guard invariants the shipped build keeps with `assert!`; `debug_assert!` vanishes without debug-assertions** — The solver's release profile does not set `debug-assertions`, so the pinned wasm takes Cargo's release default (off): any `debug_assert!` added to lib.rs or rapier_law.rs exists in native `cargo test` and not in the shipped module. An invariant the golden hash depends on (a unit quaternion, a non-NaN pose) must be an `assert!` or, at the export, a refusal, and state written under `cfg!(debug_assertions)` would make native runs and the wasm disagree.
- ✓ **Keep panics out of `extern "C"` exports: refuse through an internal `Result` chain mapped to a `u32` status** — The dispatched cleanup item is already fixed: `rebuild_snapshot` did `continue` on a failed `canon_quat` at `c64f67a`, and `6a33297` changed it to `return false` and made `ensure` check the result; `e5fbcb9` and current `origin/main` keep that. The one `continue` left in `rebuild_snapshot` skips carried bodies (`handles[i]` is `None`), which leave the solver by design. What remains is the shape: `ensure -> signature / build_world / rebuild_snapshot` and `solver_step -> integrate -> write_body` pass `bool`s and `Option`s that a future caller can drop without a warning. A `Result<(), Refusal>` chain with `?` keeps every export's 1/0 ABI unchanged and makes 'refuse, never skip' something the compiler checks.
- ✓ **Know what `panic = "abort"` changes: the hook still runs, then no unwinding, no `Drop`, nothing to catch** — `solver/Cargo.toml` sets `panic = "abort"`, which restates the `wasm32-unknown-unknown` default. In that build std's abort is `core::intrinsics::abort()`, which node reports as `WebAssembly.RuntimeError: unreachable` (measured on a 1.98.1 module; the JS API maps a trap to `RuntimeError`). No `Drop` runs, so a panic partway through `solver_step` can leave `SOLVER` and the `static mut` buffers half-written, and the instance still answers later calls (measured), so the JS side must treat any trap as fatal and re-instantiate (depth: wasm-raw-abi). A native build of the law for a Godot or Unreal host under this profile would end the editor process on any panic.
- ✓ **Make refusals impossible to drop silently: `Result` is `#[must_use]`, `Option<()>` and `bool` are not** — Today every caller of `rebuild_snapshot`, `integrate`, `write_body` and `ensure` in rapier_law.rs checks the returned `bool` (`rebuild_snapshot`'s callers since `6a33297`), but nothing makes the next caller check: `rebuild_snapshot(loaded, &mut solver.snapshot);` would compile silently and leave a half-built snapshot (the function clears `out` before it can refuse). `#[must_use]` on those four, or a `Result<(), Refusal>` return, turns that into a warning.
- ✓ **Say the overflow intent in the call: `checked_`, `wrapping_`, `saturating_`, `overflowing_`, `strict_` (1.91+)** — `mix_u64` in rapier_law.rs is `h.wrapping_mul(0x100000001b3).wrapping_add(x)`: the hash wraps by design and gives the same bits under `cargo test` (overflow checks on) as in the pinned wasm (off); written with `*` and `+` it would panic natively (check 5). `(rows as usize).saturating_mul(cols as usize)` in `signature()` is the clamp-then-refuse idiom. Native tests of these pure functions therefore see the release arithmetic.
- ✓ **Under `overflow-checks = false`, `+ - *`, negation, `abs` and shifts wrap; `/ %` and indexing still panic** — `signature()` in rapier_law.rs sets `driven /= 1u64 << i` and `carried /= 1u64 << i` for `i < n_bodies <= MAX_BODIES = 64`, so the largest shift is 63. If MAX_BODIES ever passes 64, the shift by 64 is masked to a shift by 0 under this profile (check 1: `1u64 << 64 == 1`), and body 64 would silently share body 0's bit instead of being refused; `const _: () = assert!(MAX_BODIES <= 64);` next to the constant pins it. Bounds checks stay on regardless: `step()` refuses `n_bodies > MAX_BODIES` before it indexes, so a bad count returns 0 instead of trapping inside `field()`.
- ✓ **Use `expect` with a 'should' message only for invariants the compiler can't see; return `Result` for input** — `integrate` in rapier_law.rs holds the solver's only explicit panic site: `plans.iter().find(/plan/ plan.index == i).unwrap()` (line 561 at `e5fbcb9`). The invariant holds (every kinematic body with a handle either pushes a plan or makes `integrate` return `false` first), so give it a precondition message, or remove the lookup by recording each plan's position when it is pushed; under `panic = "abort"` in wasm a failure is a trap either way.

## [Collections, iterators & closures](collections-iterators.md)

- ✓ **Assert equal lengths before zip, handle chunks_exact remainders, and collect into the target you mean** — solver/src/lib.rs lays bodies out as `[f64; MAX_BODIES * BODY_STRIDE]` with BODY_STRIDE = 17 (colliders: COLLIDER_STRIDE = 10), and `body_at` in rapier_law.rs copies a row with an index loop. Over a `&[f64]` view the same rows are `as_chunks::<17>()` with an empty remainder, which puts the stride in the type; how to obtain that view of a `static mut` soundly belongs to the unsafe-ffi lane.
- ✓ **Choose iter, iter_mut or into_iter by ownership, and consume every adapter chain you build** — solver/Cargo.toml sets `edition = "2021"`, so in the law crate `array.into_iter()` already yields values; the snapshot and step loops walk bodies by index (`for i in 0..loaded.n_bodies`, `while i < n`) rather than through adapters.
- ✓ **Delete from a hashed Vec with remove/retain/drain, not swap_remove; pre-size it with with_capacity/reserve** — Rapier 0.35.3 removes contact-graph edges with `self.edges.swap_remove(e.index())` (src/data/graph.rs `remove_edge_adjust_indices`), and `NarrowPhase::contact_pairs()` walks that edges vec in index order (`interactions()` -> `raw_edges().iter()`), so pair order changes whenever a contact ends. That is why `rebuild_snapshot` in solver/src/rapier_law.rs collects the pairs into a Vec and sorts them before hashing; it also reuses the snapshot buffer with `out.clear()`, which keeps its capacity.
- ✓ **Give every hashed sort a unique total key; if keys can tie, use stable sort_by, not sort_unstable_by** — `rebuild_snapshot` (solver/src/rapier_law.rs, the same at e5fbcb9 and main 4782a8a) sorts `Vec<&ContactPair>` with stable `sort_by` on `(collider1.into_raw_parts(), collider2.into_raw_parts())`. That key cannot tie under Rapier 0.35.3: pair_management.rs adds a contact edge only when the undirected `find_edge(gid1, gid2)` finds none, so each collider pair appears once, and stable or unstable would hash the same bytes. If a later snapshot sorts by a key that can tie (manifold points, a float depth), `sort_unstable_by` would let a move of the 1.98.1 pin reorder tied elements and shift the golden, while `sort_by` would fall back to Rapier's own edge order, which swap_remove rewrites. Extend the key until it is unique instead.
- ✓ **Let only Vec, VecDeque or BTreeMap/BTreeSet order reach an output; HashMap/HashSet order is random per map** — solver/src (e5fbcb9 and main 4782a8a) holds no HashMap, HashSet or BTreeMap: bodies and colliders live in fixed `static mut` arrays walked in index order, plus `Vec<Option<RigidBodyHandle>>`. Rapier's `contact_pairs()` is Vec-backed but not canonical (see the swap_remove recipe), which is why the snapshot sorts it. Any map added for mesh collision or host bindings should stay off the snapshot path or be a BTreeMap.
- ✓ **Sort f64 with sort_by(f64::total_cmp), find first matches with partition_point, and dedup floats by bits** — `rebuild_snapshot` canonicalises -0.0 to +0.0 in `canon()` before `to_le_bytes` (solver/src/rapier_law.rs), and a NaN makes `write_body` / `canon_quat` refuse, so the step returns false. A future sort by an f64 on the snapshot path (contact points by depth, bodies by distance) should compare the canonicalised values with `total_cmp` plus an id tiebreak; on raw values, -0.0 and +0.0 order differently under `total_cmp`, so the same state could sort differently.
- ✓ **Sum floats in one canonical order: iter().sum() is a left fold from -0.0 and reordering changes the bits** — solver/src contains no `.sum()` today (grep at e5fbcb9 and main 4782a8a). `rebuild_snapshot` sends every f64 through `canon()` (rapier_law.rs), so an empty-sum -0.0 would hash as +0.0 there, while `mix_f64`, which feeds `signature()`, hashes `to_bits()` without canonicalising. Any behaviour number the Phase 2 outcome tests total over bodies should be summed in body-index order.

## [Cargo, crates, modules & editions](cargo-modules.md)

- ✓ **Assume a Cargo feature enabled by any dependent is on for all; audit with `cargo tree -e features -i <crate>`** — Measured on a scratch copy of solver/Cargo.toml and solver/Cargo.lock: `cargo tree -e features -i rapier3d-f64 --target wasm32-unknown-unknown --frozen` lists alloc, block-solver, default, dim3, enhanced-determinism, f64 and std (enhanced-determinism from si-solver, the rest through default) and no `parallel`; rapier3d_f64's rustc line carries exactly those seven `--cfg feature=` flags. Any crate later built in one graph with the solver (a host-binding crate in a shared workspace) that enables rapier's `parallel` turns it on for the solver's build as well, so that tree command is the guard whose output must never show `feature "parallel"` (wiring it into CI is the ci lane's).
- ✓ **Choose [lib] crate-type by who loads it: cdylib for the wasm module, rlib for Rust callers, staticlib for C** — solver/Cargo.toml's `[lib] crate-type = ["cdylib"]` is why solver/build.mjs reads solver/target/wasm32-unknown-unknown/release/si_solver.wasm, with rapier3d-f64 and its tree linked in as rlibs. The pure helpers (js_min / js_max in lib.rs; canon, canon_quat, mix_f64 in rapier_law.rs) are private fns, so their native tests belong in in-crate #[cfg(test)] modules, which run under the cdylib-only crate-type (measured); a tests/ directory would need "rlib" plus pub helpers, and adding "rlib" moved the wasm digest in a measured build, so it would re-pin fixtures/solver.sha256 once. The host-binding phase (the law inside Godot, then Unreal) makes this choice again for a native triple: the same export compiles as a host cdylib (a .dll on this Windows rig) and as a staticlib (checks below).
- ✓ **Declare rust-version and choose the resolver: edition 2024 makes resolver "3" lock MSRV-compatible versions** — The solver declares no rust-version and is edition 2021, so solver/Cargo.lock was written by resolver 2 without regard to rust-version. The real floor comes from the graph: rapier3d-f64 0.35.3's own Cargo.toml declares edition = "2024" and rust-version = "1.86" (read in the local registry copy), while solver/rust-toolchain.toml pins the compiler that makes the bytes, 1.98.1. Declaring rust-version in solver/Cargo.toml would turn a too-old toolchain into Cargo's clear refusal; whether that touches the digest was not measured.
- ✓ **Migrate a crate's edition with `cargo fix --edition`, then edit `edition` yourself, then rebuild and test** — solver/Cargo.toml is edition 2021 and every export in lib.rs and rapier_law.rs is written `#[no_mangle] pub extern "C" fn`, which 2021 accepts and 2024 rejects (checks below); `#[unsafe(no_mangle)]` already compiles under 2021 on 1.98.1, so the attribute half of a migration can land before the edition changes. The solver's own graph mixes all four editions (rapier3d-f64 0.35.3 is edition 2024 under the 2021 root, measured), so staying on 2021 costs nothing. The full list of what `cargo fix --edition` would change in the solver, and whether it moves the bytes, is the rust-currency lane's.
- ✓ **Pin the compiler with rust-toolchain.toml and run cargo from that directory: rustup finds it from the cwd** — solver/rust-toolchain.toml (channel "1.98.1", targets ["wasm32-unknown-unknown"], profile "minimal") applies because solver/build.mjs spawns cargo with `cwd: solver`, and that same cwd is what makes solver/.cargo/config.toml apply. `cargo build --manifest-path solver/Cargo.toml` from the repo root gets the default toolchain and no config rustflags (measured on a copy), so builds should go through build.mjs or `cd solver`. A Rust-side clippy or rustfmt job for the solver needs `components = ["rustfmt", "clippy"]` in this file or an explicit install.
- ✓ **Read a bare `"0.35.3"` requirement as >=0.35.3, <0.36: commit Cargo.lock and build the artifact with --locked** — solver/Cargo.toml's `rapier3d-f64 = { version = "0.35.3", ... }` admits any 0.35.x at or above 0.35.3; the committed solver/Cargo.lock (lockfile version 4, 61 packages) is what pins rapier3d-f64 0.35.3 and parry3d-f64 0.30.2, each with a checksum. solver/build.mjs spawns `cargo build --release --target wasm32-unknown-unknown` with no --locked, so CI's `node solver/build.mjs --check` would quietly re-resolve after a manifest edit and only a digest mismatch could notice. Add '--locked' to that argument list; write "=0.35.3" as well if even a deliberate `cargo update` must not move the physics crate.
- ✓ **Set [profile.*] only in the root manifest, and remember config files and CARGO_PROFILE_* env vars override it** — Measured on a scratch copy of the solver: si_solver compiles with `--crate-type cdylib -C opt-level=3 -C panic=abort -C embed-bitcode=no -C codegen-units=1 ... -C strip=debuginfo`, and rapier3d_f64 gets the same opt-level, panic and codegen-units, so solver/Cargo.toml's [profile.release] governs the whole law. Of its five keys only panic = "abort" and codegen-units = 1 change what Cargo emits; opt-level = 3, lto = false and overflow-checks = false restate defaults (useful as a record, silent on the command line). The unpinned settings that decide bytes are strip and debug; writing `debug = false` and `strip = "debuginfo"` would record today's choice (a suggestion, not measured). A [profile.release] in a builder's ~/.cargo/config.toml or a CARGO_PROFILE_RELEASE_* variable changes local bytes, which only the Linux CI digest catches.
- ✓ **Share lock, target dir and lints across crates with [workspace.dependencies] and [workspace.lints]** — solver/ is a standalone package today, with its own Cargo.lock, target/ and .cargo/config.toml. If host-binding crates join it under a root workspace, three things move together: the lock and target/ go to the root (so build.mjs's solver/target/wasm32-unknown-unknown/release/si_solver.wasm path changes), solver/Cargo.toml's [profile.release] is ignored until it moves to the root manifest, and solver/.cargo/config.toml stops being read when cargo runs from the root, which leaves the relaxed-SIMD pin living only in build.mjs's RUSTFLAGS. The solver cannot take unsafe_code = "forbid" (its exports reach static mut buffers inside unsafe blocks, and forbid admits no local allow); deny with a local allow, or narrower lints, fit it.
- ✓ **Split a crate into file modules with `mod name;` and share internals via pub(crate) / pub(super), not pub** — solver/src/lib.rs declares `mod rapier_law;` (solver/src/rapier_law.rs) and shares its ABI constants (`pub(crate) const BODY_STRIDE = 17`, HX..DRIVEN, `COLLIDER_STRIDE = 10`) and `pub(crate) static mut BODIES / COLLIDERS`, which rapier_law.rs imports with `use crate::{BODIES, BODY_STRIDE, COLLIDERS, ...}`; rapier_law.rs keeps its own `pub(crate) static mut HEIGHTS`. That is the right shape for a cdylib with no Rust consumers. T2's `restore_ptr` input buffer and `solver_restore` fit beside the snapshot code in rapier_law.rs with the same pub(crate) scope; if that file is split, `mod snapshot;` inside it loads solver/src/rapier_law/snapshot.rs.
- ✓ **Treat Cargo's rustflags sources as exclusive: any RUSTFLAGS, even empty, drops .cargo/config.toml rustflags** — solver/.cargo/config.toml pins `[target.wasm32-unknown-unknown] rustflags = ["-C", "target-feature=-relaxed-simd"]`, and solver/build.mjs sets RUSTFLAGS for its three --remap-path-prefix flags, which replaces that config; that is why build.mjs repeats `-C target-feature=-relaxed-simd`. Measured on a scratch copy of the real solver source on this rig: dropping the repeat rebuilt to the identical SHA-256 (on 1.98.1 the pin guards a default that could change, it does not move today's bytes), while `+relaxed-simd` produced a different digest; the same flags passed as CARGO_ENCODED_RUSTFLAGS left all 50 units Fresh (no rebuild, same bytes). Two holes remain in build.mjs: an inherited CARGO_ENCODED_RUSTFLAGS outranks its RUSTFLAGS and would drop the pin and the remaps, and a cargo-home or checkout path with a space breaks the RUSTFLAGS split. Setting CARGO_ENCODED_RUSTFLAGS to the flags joined by '\x1f' closes both.

## [Testing, lints & dev tooling](testing-tooling.md)

- ✓ **Add what rustc cannot check: Miri on native tests (nightly only), cargo-deny and cargo-audit on dependencies** — solver/src reaches static mut BODIES, COLLIDERS, HEIGHTS and SOLVER through references (e.g. `&mut *core::ptr::addr_of_mut!(SOLVER)`, `&mut BODIES`) and hands raw pointers to JS (7 static_mut_refs sites on 1.98.1); native tests that call bodies_ptr or step are what Miri can check. solver/Cargo.lock holds the rapier3d-f64 0.35.3 tree that cargo deny check and cargo audit read.
- ✓ **Expect tests/ and doc tests to need an rlib; adding rlib to the solver's crate-type changed its wasm bytes** — solver/Cargo.toml has crate-type = ["cdylib"]: keep it unless a tests/ harness is worth re-pinning fixtures/solver.sha256. The helpers worth testing are private, so unit tests in the same files are the reachable form, and any /// example added to solver/src is never run by cargo test today.
- ✓ **Give lint groups priority = -1 in Cargo's [lints] table; add clippy and rustfmt to the pinned toolchain file** — solver/rust-toolchain.toml pins channel 1.98.1, profile minimal and target wasm32-unknown-unknown with no components, and solver/Cargo.toml has no [lints] table; a lint gate needs both. The 7 static_mut_refs sites (lib.rs lines 28, 33, 183, 184; rapier_law.rs lines 78, 738, 743) belong to the unsafe-ffi rewrite.
- ✓ **Keep wasm evidence in the JS harness: wasm32-unknown-unknown libtest prints nothing and skips should_panic** — The solver has no wasm-bindgen (solver/build.mjs emits raw extern "C" exports), so wasm-bindgen-test would add a toolchain the artifact does not use; the wasm binary is already measured by the JS harness under V8, SpiderMonkey and JavaScriptCore against golden hashes. Keep Rust tests native and let the JS harness own the wasm.
- ✓ **Property-test the solver's float helpers with proptest over prop::num::f64::ANY, not only hand-picked values** — solver/src/rapier_law.rs canon_quat (used by quat_from_body): once the sum of squares overflows (a single component beyond about 1.34e154, less when several are large) it returns Some((0.0, 0.0, 0.0, 0.0)), which quat_from_body hands to Rotation::from_xyzw, and plus or minus infinity yields a NaN component instead of None. T3's planned refusal of non-finite literals would stop infinity but not 1e200; refusing out-of-range values at load or rescaling before squaring is an engine decision.
- ✓ **Prove each Rust harness can go red: cargo-mutants on unit tests, insta goldens that CI cannot auto-accept** — PHASE-2 requires each harness to be shown red; for solver/ that is cargo mutants reporting no missed mutants on the native tests. canon, js_min, js_max and canon_quat encode signed-zero rules that == cannot see, so their tests assert on to_bits.
- ✓ **Rely on rustc for constant overflow and NaN ==, and on Clippy's pedantic float_cmp and cast lints for the rest** — solver/src/lib.rs sizes its buffers from MAX_BODIES = 64 and BODY_STRIDE = 17 (1088 slots): rustc stops a literal or constant expression that overflows, but not an `as` cast that truncates. canon's `if x == 0.0` sits inside float_cmp's zero exemption, so float_cmp says nothing about the rule that makes -0.0 hash like 0.0.
- ✓ **Run cargo test and cargo test --release: the release run wraps integer overflow that the debug run panics on** — solver/Cargo.toml [profile.release] sets overflow-checks = false and panic = "abort". Native tests of the solver run with overflow panics under cargo test and with the artifact's wrapping under cargo test --release; mix_u64 in solver/src/rapier_law.rs already uses wrapping_mul / wrapping_add and is profile-independent.
- ✓ **Suppress lints with #[expect(lint, reason = "...")] (1.81+) instead of #[allow], so a stale suppression warns** — Once native tests exist, solver/src compiles for two targets (the host for cargo test, wasm32-unknown-unknown for the artifact); an #[expect] tied to cfg(target_arch) code holds on one and warns on the other (checks), so scope it with cfg_attr.
- ✓ **Unit-test the cdylib in #[cfg(test)] modules at the end of each file so the wasm bytes stay put** — solver/src/lib.rs (js_min, js_max) and solver/src/rapier_law.rs (canon, canon_quat, mix_f64) have no tests at e5fbcb9. Appended #[cfg(test)] modules built and passed natively with crate-type untouched and left the wasm bytes identical on a Windows copy; the Linux digest in fixtures/solver.sha256 was not rebuilt here.
