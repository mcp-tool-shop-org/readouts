### At the raw extern "C" edge, bounds-check counts and TryFrom each mode number into an enum; refuse the rest
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust any (checked on 1.98.1, host and wasm32-unknown-unknown, edition 2021 like the solver)

**Keep the flat f64/u32 ABI, but turn each raw number into a checked Rust value at the top of the export — counts compared with capacity before they become indices, mode numbers decoded through TryFrom into an enum — and return the export's failure code for anything else.**

- **How:** `#[repr(u8)] enum SolverMode { Dynamic = 0, Kinematic = 1, Lifted = 2, Carried = 3 }` plus `impl TryFrom<u32> for SolverMode` with an exhaustive `match` ending in `other => Err(other)`. Slot 16 is an f64, so decode it as `let n = x as u32; if f64::from(n) != x { refuse }` and then `SolverMode::try_from(n)`: the exact round trip refuses 1.5, -1.0, NaN and 1e10, which `x as u32` alone would turn into 1, 0, 0 and 4294967295. Going out, `mode as u32` is a defined enum cast. For counts, keep `if n_bodies as usize > MAX_BODIES { return 0; }` ahead of every loop that indexes `i * BODY_STRIDE + k`.
- **Gotchas:** `SolverMode::try_from(x as u32)` looks checked but inherits the cast's truncation and saturation (1.5 becomes Kinematic, NaN becomes Dynamic). -0.0 decodes to Dynamic because -0.0 == 0.0. Never transmute a number into an enum (invalid discriminants: unsafe-ffi lane). `u32 as usize` is lossless on wasm32 (usize is 32 bits) and on 64-bit hosts, so the cast is not the hazard; the index is: without the capacity check, body 64 reads index 1,088 of a 1,088-element array and panics inside the export (what a panic does under `panic = "abort"`: errors-panics lane).
- **In si-rpg-engine:** lib.rs `step()` and rapier_law.rs `signature()` both test `n_bodies as usize > MAX_BODIES` first (e5fbcb9). That test also guards the u64 masks: `signature()` sets `driven |= 1u64 << i` and `carried |= 1u64 << i`, sound only while MAX_BODIES <= 64. With the solver's release settings (`overflow-checks = false`, opt-level 3), `1u64 << 64` evaluates to 1 on the host and on wasm32 (measured), so raising MAX_BODIES without widening the masks would alias body 64 onto body 0 with no error. T2's `solver_restore(world_id, n_bodies, n_colliders, rows, cols, cell, shape, len)` (docs/dispatch-t2-restore.md) adds a byte length and must compare the snapshot's pair and point counts, which `rebuild_snapshot` writes as f64 (`pairs.len() as f64`, `n_points as f64`): bound `len` by the restore buffer before slicing and decode each stored count with the same exact round trip before comparing or using it. `shape: u32` (1 = capsule, any other value = cuboid today) is the next candidate for TryFrom decoding.

### Chain Option and Result with map, and_then, filter, ok_or_else and ?; convert between them explicitly
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust any; is_some_and 1.70+, is_none_or 1.82+, Result::flatten 1.89+

**Option<T> and Result<T, E> are plain enums whose combinators and `?` replace nested matches; `?` works on Option only in a function returning Option and on Result only in one returning Result, so crossing needs ok_or / ok_or_else / .ok().**

- **How:** `x.map(f)` transforms the Some/Ok value; `x.and_then(f)` chains a step that can itself fail; `opt.filter(p)` drops values that fail a test; inside a Result fn, `opt.ok_or_else(|| err)?` turns None into an error; `res.ok()` drops the error; `opt.is_some_and(p)` (1.70), `opt.is_none_or(p)` (1.82), `Result::flatten` (1.89). `?` on None returns None; `?` on Err(e) returns Err(From::from(e)). Using `?` on an Option in a Result fn is E0277 ('the `?` operator can only be used on `Result`s, not `Option`s, in a function that returns `Result`'), and rustc suggests `.ok_or(...)?`.
- **Gotchas:** Arguments to ok_or, unwrap_or, map_or and or are evaluated eagerly even on the path that ignores them; std recommends the lazy _else forms when the argument is a function call. `Option<T>` is not `T`: the compiler refuses to use it as the value until it is matched or converted, which is the point. How the error type behind `?` should be designed belongs to the errors-panics lane.
- **In si-rpg-engine:** rapier_law.rs already uses `?` on Option in `quat_from_body` (`let (x, y, z, w) = canon_quat(..)?;`). In `build_world`, which returns Option too, `let Some((qx, qy, qz, qw)) = canon_quat(c[6], c[7], c[8], c[9]) else { return None; };` is equivalent to `let (qx, qy, qz, qw) = canon_quat(c[6], c[7], c[8], c[9])?;`. `solver_load` returns `if ensure(..) { 1 } else { 0 }`; `u32::from(ensure(..))` is the same conversion (From<bool> for integers, 1.28).

### Flatten refutable matches with let-else (1.65+); let chains need edition 2024; if-let guards work since 1.95
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust let-else 1.65+; let chains 1.88+ and edition 2024; if-let guards 1.95+ (any edition)

**let-else (1.65, every edition) binds on match and makes the else block diverge; let chains (`if let .. && let ..`, 1.88) are edition-2024 only; if-let guards on match arms (1.95) work in every edition but never count toward exhaustiveness.**

- **How:** Early exits: `let Some(sig) = signature(..) else { return 0; };` — the else block must diverge (return, break, continue, panic), otherwise E0308 '`else` clause of `let...else` does not diverge'. Drain loops: `while let Some(x) = stack.pop() { .. }`. In edition 2024, chain with `&&` only: `if let Some(inner) = outer && let Some(n) = inner && n == 1 { .. }`; a bare `||` is rejected ('`||` operators are not supported in let chain conditions'), so parenthesise a `||` sub-expression. In a 2021 crate the chain fails with 'let chains are only allowed in Rust 2024 or later'. On 1.95+, `Some(t) if let Ok(n) = t.parse::<i32>() => ..` works in 2021 and 2024 alike.
- **Gotchas:** The let-else initializer may not be a lazy boolean expression or end with `}` (Reference grammar). Measured on 1.98.1: a `&&` chain inside an if-let guard compiles even in edition 2021, while the same chain in a plain `if` does not — do not infer a crate's edition from its guards. A match whose only `Some` arm carries an if-let guard still needs an unguarded `Some(_)` or `_` arm (E0004, 'match arms with guards don't count towards exhaustivity'). The edition-2024 change to if-let temporary scope is covered by the rust-currency lane.
- **In si-rpg-engine:** rapier_law.rs already uses let-else for its refusal paths (`let Some(sig) = signature(..) else { return false; };` in `ensure`, the canon_quat checks in `build_world`). The crate is edition 2021, so let chains are unavailable until an edition move; the pinned 1.98.1 toolchain does accept if-let guards, which suit a future `match` over decoded modes.

### Keep patterns edition-2024 clean: no `mut`, `ref` or `&` inside an implicitly borrowing pattern
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust edition 2024 (errors); the lint runs in edition 2021 on 1.98.1

**Matching a reference with a non-reference pattern switches the default binding mode to ref / ref mut; Rust 2024 makes `mut`, `ref`, `ref mut`, `&` and `&mut` under that implicit mode hard errors, where Rust 2021 accepted them and a `mut` silently reset the binding to a by-value copy.**

- **How:** Either let match ergonomics bind (`let (a, b) = pair;` with `pair: &(u8, u8)` gives `a: &u8, b: &u8`) or make the prefix explicit (`let &(mut a, ref b) = pair;`); do not mix them. Before a 2021 crate changes edition, turn on the allow-by-default lint `#![warn(rust_2024_incompatible_pat)]`; `cargo fix --edition` applies its rewrites (`let [x, mut y] = &[(), ()];` becomes `let &[ref x, mut y] = &[(), ()];`). The three 2024 errors carry no error code: 'cannot mutably bind by value within an implicitly-borrowing pattern', 'cannot explicitly borrow within an implicitly-borrowing pattern', 'cannot explicitly dereference within an implicitly-borrowing pattern'.
- **Gotchas:** The 2021 trap is `mut`: in `let (mut a, b) = &(1u8, 2u8);` `a` is a by-value u8 copy while `b` is `&u8`, so `a += 10` never touches the tuple. A redundant `ref` was harmless in 2021 and is an error in 2024, so code that compiled for years stops compiling on the edition bump. Edition is per crate: a 2021 crate keeps 2021 pattern rules on the 1.98.1 compiler.
- **In si-rpg-engine:** The solver crate is edition 2021 (solver/Cargo.toml). Measured 2026-09-25: a scratch copy of solver/src/lib.rs + rapier_law.rs at e5fbcb9 compiled with rustc 1.98.1 `--edition 2021 -W rust_2024_incompatible_pat` against rapier3d-f64 0.35.3 reports no site, so binding modes will not block a 2024 move; the other edition-2024 changes the solver would meet belong to the rust-currency lane.

### List every variant in a match: a `_` arm silently absorbs variants added later
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust any; if-let guards 1.95+

**match must be exhaustive (E0004 names the missing pattern), which turns 'a variant was added' into a compile error at every match that has to decide about it; a `_` arm switches that off and hands the new variant the default.**

- **How:** For enums you own, name every variant and leave `_` out, so adding `Carried` breaks each match until someone decides what Carried does. Use `_` (or a named catch-all such as `other`) for open domains (integers, floats, strings) and for #[non_exhaustive] enums from another crate, where the compiler requires it (std's `IntErrorKind`). Put a catch-all last: arms after it are unreachable and rustc warns (`unreachable_patterns`). Guards (`if`, and since 1.95 `if let`) never count toward exhaustiveness, so a guarded arm needs an unguarded partner. rapier3d-f64 0.35.3 does not mark RigidBodyType (Dynamic, Fixed, KinematicPositionBased, KinematicVelocityBased) #[non_exhaustive] — a grep of the pinned registry source finds the attribute nowhere in the crate — so a `_`-free match over it compiles.
- **Gotchas:** #[non_exhaustive] has no effect inside the defining crate; outside it, matching needs a wildcard and its structs and variants cannot be constructed. The lint that would warn when a `_` arm covers named variants of a non_exhaustive enum, `non_exhaustive_omitted_patterns`, is unstable: on stable 1.98.1 naming it only produces an unknown-lint warning, so there is no stable compiler help for that case. A catch-all written as a named binding (`other => ..`) is just as silent as `_`.
- **In si-rpg-engine:** When the solver matches on its own decoded mode enum (ABI-edge recipe), write every arm: a `_ => dynamic` arm would rebuild today's rapier_law.rs behaviour in which any unknown slot-16 value is dynamic. Matches over Rapier's RigidBodyType can stay `_`-free under the pinned rapier3d-f64 0.35.3, which makes a variant added by a future bump a compile error at each site — one more tripwire beside the golden hashes.

### Pick named-field, tuple or unit structs by meaning; hang constructors and constants on impl blocks
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust any (checked on 1.98.1)

**Rust has three struct kinds (named-field, tuple, unit-like); every fn in an impl block is an associated function, only those taking self are methods, and an associated const is evaluated only when something references it.**

- **How:** Named fields when fields have distinct roles (`struct Face { axis, pen, dir }`); a tuple struct for a one-field wrapper or a same-shaped but different type (`struct Quanta(u32)`); a unit-like struct (`struct Warm;`) for a type with no data. Constructors are associated functions returning `Self` (`fn new(x: f64, y: f64, z: f64) -> Self { Self { x, y, z } }`), fixed values are associated consts (`const ZERO: Vec3 = ...;`), both called through the type: `Vec3::new(..)`, `Vec3::ZERO`, `Self::PER_SECOND`. A type may have several impl blocks. Calling a self-less fn with method syntax (`v.new(..)`) is E0599 'this is an associated function, not a method'.
- **Gotchas:** An associated const is const-evaluated only when referenced, so `const CHECK: () = assert!(Self::MAX_BODIES <= 32);` inside an impl proves nothing until code names `Self::CHECK`; unreferenced, the false assertion compiles with only a dead_code warning ('associated constant `CHECK` is never used'), referenced it is E0080. Tuple-struct fields are positional (`.0`), so a tuple struct with several fields of one type invites transposition; use named fields there. Field-init shorthand and `..base` update syntax are conveniences, not further struct kinds.
- **In si-rpg-engine:** rapier_law.rs builds `Loaded.signature` by copying `Signature` field by field and compares signatures field by field in `same_sig`. `Signature` is a named-field struct of u32/u64 only (the f64 `cell` is stored as `to_bits()`), so derived Clone/Copy/PartialEq/Eq (contracts: traits-generics lane) could replace both hand-written copies. The slot numbers (`HX`..`DRIVEN` in lib.rs, `QX`..`WZ` in rapier_law.rs) are free consts; associated consts on a record type would namespace them without touching the ABI.

### Treat `as` as silent truncation or saturation; convert integers with From or TryFrom so a loss is visible
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust any; saturating float-to-int since 1.45; bool: TryFrom<{integer}> 1.95+

**`as` never fails: narrowing keeps the low bits, float-to-int rounds toward zero and saturates (NaN -> 0), int-to-float rounds to nearest; std implements From only where no value can be lost and TryFrom returns Err instead of a wrong number.**

- **How:** Widen with From: `u64::from(x_u32)`, `f64::from(x_u32)` (exact), `usize::from(x_u16)`. Narrow or change sign with TryFrom: `u8::try_from(n)?`, `usize::try_from(n_u32)` — std has no `From<u32> for usize` (E0277), only `TryFrom<u32>` (the Reference guarantees usize at least 16 bits, not 32), and f64 has no `From<u64>` or `From<usize>`. Integer to bool: `bool::try_from(n)` (1.95; 0 and 1 only) — `7u8 as bool` is E0054. Keep `as` for intended bit reinterpretation (`-1i32 as u32` is 4294967295), deliberate truncation, or a saturating clamp, and say which in a comment.
- **Gotchas:** All silent: `300i32 as u8` = 44, `1234u16 as u8` = 210, `-1.0 as u8` = 0, `f64::NAN as i32` = 0, `1e20 as i32` = i32::MAX, `1.5 as u32` = 1. u64 to f64 rounds above 2^53, so `(2^53 + 1) as f64 == 2^53 as f64`. Casts are not transitive: `e as U1 as U2` being valid does not make `e as U2` valid (Rustonomicon). Before 1.45 an out-of-range float-to-int cast was undefined behaviour (background source).

### Wrap units and ids in tuple-struct newtypes; keep type aliases for renames and long names
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust any

**A newtype (`struct Quanta(u32)`) is a distinct type the compiler keeps apart (E0308 on a mix-up); a type alias (`type Quanta = u32`) is only another name, so aliased values interconvert with no error.**

- **How:** Declare `#[derive(Clone, Copy, Debug, PartialEq, Eq)] struct BodyIndex(usize);`, `struct Quanta(u32);`, `struct Rows(u32); struct Cols(u32);` and convert at named points (`impl Quanta { fn seconds(self, dt: f64) -> f64 }`). Keep the field private where an invariant must hold and construct through `new` or `TryFrom`. Use `type` to shorten a long type or to keep an old name alive: rapier3d-f64 0.35.3 still exports `pub type BodyStatus = RigidBodyType;`, deprecated with 'renamed as RigidBodyType', and the two names assign to each other freely. An alias of a tuple struct is not its constructor (`type Q = Quanta; Q(32)` is E0423).
- **Gotchas:** Aliases document but do not protect: with `type Seconds = f64; type Quanta = f64;` a seconds value passes a quanta parameter silently. A newtype starts with none of the inner type's operators or trait impls (`Quanta(1) + Quanta(2)` is E0369) until you derive or implement them (ops traits and the orphan-rule workaround: traits-generics lane). Keep the extern "C" signature in plain u32/f64 and wrap on entry; layout attributes for passing wrappers across the boundary belong to the memory-layout lane.
- **In si-rpg-engine:** `solver_load` and `solver_step` take `(world_id: u32, n_bodies: u32, n_colliders: u32, rows: u32, cols: u32, cell: f64, shape: u32)`: five u32s whose transposition (rows for cols) compiles. Wrapping them in newtypes at the top of the export makes a swap a compile error inside Rust while the wasm signature stays the same. Sleep is counted in quanta (`SLEEP_QUANTA * DT` becomes `time_until_sleep`); a `Quanta` newtype with a single `seconds()` conversion keeps quanta and seconds from mixing.
