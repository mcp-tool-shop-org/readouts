### Add what rustc cannot check: Miri on native tests (nightly only), cargo-deny and cargo-audit on dependencies
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust Miri: nightly only

**Miri interprets cargo miri test and reports out-of-bounds access, use-after-free, uninitialised reads, misalignment, invalid values and data races, but it is a nightly component (1.98.1 offers none) with no FFI; cargo-deny lints the dependency graph (advisories, bans, licenses, sources) from deny.toml, and cargo-audit checks dependencies against the RustSec Advisory Database.**

- **How:** Miri: `rustup +nightly component add miri`, then `cargo +nightly miri test`; on Windows add `--target x86_64-unknown-linux-gnu` for better system-API support; mark tests Miri cannot or should not run with `#[cfg_attr(miri, ignore)]` (it is an interpreter, slower than compiled code); `--target` also cross-interprets other architectures. Measured: `rustup component list --toolchain 1.98.1` offers clippy, rustfmt, rust-analyzer and llvm-tools but no miri, and `cargo +1.98.1 miri` answers `the 'miri' component which provides the command 'cargo-miri.exe' is not available for the '1.98.1-x86_64-pc-windows-msvc' toolchain`; under Cargo's check-cfg, cfg(miri) raises nothing while a typo (mirii) warns `unexpected `cfg` condition name: `mirii`` with `there is a config with a similar name: `miri``. cargo-deny: `cargo install --locked cargo-deny && cargo deny init && cargo deny check`; advisories covers vulnerable, unmaintained and yanked crates, bans covers named crates and duplicate versions. cargo-audit: `cargo install cargo-audit`, then `cargo audit` at the top of the project; `--ignore` or audit.toml waives an advisory; `cargo audit bin` audits built binaries.
- **Gotchas:** Miri runs host-compiled tests, not the wasm artifact or its JS boundary. Its aliasing model is the unsafe-ffi lane's subject. None of these tools is installed on this rig (`cargo +1.98.1 deny` and `cargo +1.98.1 audit` answer `no such command`); their commands here come from their documentation.
- **In si-rpg-engine:** solver/src reaches static mut BODIES, COLLIDERS, HEIGHTS and SOLVER through references (e.g. `&mut *core::ptr::addr_of_mut!(SOLVER)`, `&mut BODIES`) and hands raw pointers to JS (7 static_mut_refs sites on 1.98.1); native tests that call bodies_ptr or step are what Miri can check. solver/Cargo.lock holds the rapier3d-f64 0.35.3 tree that cargo deny check and cargo audit read.

### Give lint groups priority = -1 in Cargo's [lints] table; add clippy and rustfmt to the pinned toolchain file
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust 1.74+ for [lints]; clippy lint_groups_priority 1.78+

**Cargo turns [lints] into --allow/--warn/--deny flags ordered by priority, not by position in the file; at equal priority a group can come last and override a member lint (measured), which clippy::lint_groups_priority flags. The pinned 1.98.1 minimal toolchain has neither cargo clippy nor cargo fmt.**

- **How:** [lints] is respected from Cargo 1.74 (announced 2023-11-16): `[lints.clippy] pedantic = { level = "warn", priority = -1 }`, then single-lint overrides at the default priority 0. Measured with `cargo +1.98.1 build -v`: `unused = "deny"` and `unused_variables = "allow"` at equal priority passed `--allow=unused_variables --deny=unused` in either file order and failed with `error: unused variable: `scratch`` and `-D unused-variables implied by -D unused`; with `unused = { level = "deny", priority = -1 }` Cargo passed `--deny=unused --allow=unused_variables` and the build succeeded. On rustc's command line the later flag wins (checks). Clippy's lint_groups_priority (correctness, since 1.78.0): the file order is ignored and without priority the sort order is undefined. Toolchain: add `components = ["clippy", "rustfmt"]` to rust-toolchain.toml (rustup installs listed components on top of the profile; minimal is rustc, rust-std, cargo). Measured: `cargo +1.98.1 fmt --check` -> `error: 'cargo-fmt.exe' is not installed for the toolchain '1.98.1-x86_64-pc-windows-msvc'` (exit 1), `cargo +1.98.1 clippy` -> the same for cargo-clippy.exe; rustup 1.29.1 lists clippy, rustfmt, rust-analyzer and llvm-tools as available for 1.98.1. `cargo fmt --check` exits 0 when rustfmt would change nothing and 1 when it would; config lives in rustfmt.toml or .rustfmt.toml. Warnings gate: build.warnings / CARGO_BUILD_WARNINGS (respected as of Cargo 1.97; warn, allow, deny; local packages only). Measured: `CARGO_BUILD_WARNINGS=deny cargo +1.98.1 build` on a crate with one unused variable -> `error: warnings are denied by `build.warnings` configuration`, exit 101, and the next plain build finished without recompiling. rust-analyzer: `rust-analyzer.check.command` defaults to "check" (set "clippy"); `rust-analyzer.cargo.target` defaults to null, no override (set "wasm32-unknown-unknown" to analyse the artifact's cfgs); `rust-analyzer.cargo.cfgs` defaults to ["debug_assertions", "miri"].
- **Gotchas:** [lints] applies to the current package only, never to dependencies. A -D warnings gate on the solver fails on day one: a copy at e5fbcb9 emits 7 static_mut_refs warnings under 1.98.1 (edition 2021, where the lint is warn-by-default as part of rust_2024_compatibility). Because rust-analyzer turns cfg(miri) on by default, code under cfg(not(miri)) shows as inactive in the editor.
- **In si-rpg-engine:** solver/rust-toolchain.toml pins channel 1.98.1, profile minimal and target wasm32-unknown-unknown with no components, and solver/Cargo.toml has no [lints] table; a lint gate needs both. The 7 static_mut_refs sites (lib.rs lines 28, 33, 183, 184; rapier_law.rs lines 78, 738, 743) belong to the unsafe-ffi rewrite.

### Keep wasm evidence in the JS harness: wasm32-unknown-unknown libtest prints nothing and skips should_panic
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust 1.98.1 (libtest rule read at that tag)

**Cargo has no runner for wasm32-unknown-unknown: it builds the libtest harness as a .wasm and fails to execute it. Given CARGO_TARGET_<TRIPLE>_RUNNER the harness runs, but println! does nothing, a failure is only an unreachable trap, and libtest marks every #[should_panic] test ignored on non-emscripten wasm.**

- **How:** Measured (cargo 1.98.1, Windows host): `cargo test --target wasm32-unknown-unknown` -> `could not execute process `...\cdy2-fb045ff75d8e8ee1.wasm` (never executed)` caused by `%1 is not a valid Win32 application. (os error 193)`. The harness module exports memory, the crate's exports and `main`, and imports nothing. With `CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUNNER="node run-wasm.js"` (instantiate with {} and call main(0, 0)): a passing suite -> main returned 0 and no test lines; a failing assert -> `RuntimeError: unreachable`; a #[should_panic] test that never panics -> FAILED on the host but main returned 0 on wasm. libtest at tag 1.98.1 (library/test/src/lib.rs lines 642-651) sets `ignore_because_no_process_support` for should_panic tests when `cfg!(target_family = "wasm")` and not emscripten. Real options: wasm-bindgen-test (dev-dependency, #[wasm_bindgen_test], runner = 'wasm-bindgen-test-runner' from a wasm-bindgen-cli of the same version, Node.js by default, tests in the crate root or a pub mod), which presumes wasm-bindgen; or a WASI target run by a runtime through the same runner key (the rustc book recommends testing wasm32-wasip1 for WebAssembly compatibility; wasmtime runs a wasm32-wasip2 hello world directly), where should_panic stays ignored because the rule is target_family = "wasm" (`rustc +1.98.1 --print cfg` reports target_family="wasm", target_os="wasi" for wasm32-wasip1 and wasm32-wasip2).
- **Gotchas:** An exit status is all a bare runner gets: no test names, and the first failure traps the whole module. The rustc book: this target is not tested in rust-lang CI, println! does nothing, and it compiles with -Cpanic=abort by default. Neither WASI target is installed on this rig (only wasm32-unknown-unknown and wasm32v1-none), so the WASI route here is from documentation, not measurement.
- **In si-rpg-engine:** The solver has no wasm-bindgen (solver/build.mjs emits raw extern "C" exports), so wasm-bindgen-test would add a toolchain the artifact does not use; the wasm binary is already measured by the JS harness under V8, SpiderMonkey and JavaScriptCore against golden hashes. Keep Rust tests native and let the JS harness own the wasm.

### Property-test the solver's float helpers with proptest over prop::num::f64::ANY, not only hand-picked values
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust proptest 1.11.0 (oracle-pinned)

**A proptest over f64::ANY on a verbatim copy of canon_quat failed in 6 of 6 runs: an infinite component returns Some((NaN, 0.0, 0.0, 0.0)), and a finite one whose square overflows (sqrt(f64::MAX) = 1.3407807929942596e154; measured at 1.4e154 and 1e200) returns Some((0.0, 0.0, 0.0, 0.0)), though its doc comment says unit quaternion. proptest shrinks each failure and replays saved seeds.**

- **How:** `proptest! { #[test] fn name(x in prop::num::f64::ANY, ...) { prop_assert!(...) } }` with proptest 1.11.0. f64::ANY includes infinities and quiet NaNs, not signalling NaNs; ranges such as `0u32..1000` shrink toward their start and never leave the range. Measured: `n in 0u32..1000` against `n <= 64` -> `minimal failing input: n = 65` on three runs; in a crate layout the failure was saved to proptest-regressions/lib.txt as `cc <64 hex digits> # shrinks to n = 65` under a header recommending source control. Commit that directory: saved cases replay before novel ones. Config: cases 256 (PROPTEST_CASES); failure_persistence FileFailurePersistence::SourceParallel("proptest-regressions"); rng_seed random unless RngSeed::Fixed(u64) or PROPTEST_RNG_SEED. The six canon_quat runs shrank to x = -1.1869936194728579e203; x = -inf; z = inf; z = -inf; y = -2.309088135335261e260; z = -inf: the seed differs per run, the defect does not. With `rng_seed: RngSeed::Fixed(20260925)` the shrink landed on `x = 0.0, y = 0.0, z = -inf, w = 0.0` (n2 = NaN) in all three oracle runs. A wasm32-unknown-unknown build of the same code returns the same edge values (checks).
- **Gotchas:** With a random seed a rare failure can pass locally and fail in CI; commit proptest-regressions/ or fix the seed. A test file compiled outside a crate layout prints `FileFailurePersistence::SourceParallel set, but failed to find lib.rs or main.rs` and saves nothing. A property must state the contract: js_min(1.0, NaN) returns 1 while node 22's Math.min(1, NaN) returns NaN, so a property against Math.min either excludes NaN or reports that asymmetry.
- **In si-rpg-engine:** solver/src/rapier_law.rs canon_quat (used by quat_from_body): once the sum of squares overflows (a single component beyond about 1.34e154, less when several are large) it returns Some((0.0, 0.0, 0.0, 0.0)), which quat_from_body hands to Rotation::from_xyzw, and plus or minus infinity yields a NaN component instead of None. T3's planned refusal of non-finite literals would stop infinity but not 1e200; refusing out-of-range values at load or rescaling before squaring is an engine decision.
