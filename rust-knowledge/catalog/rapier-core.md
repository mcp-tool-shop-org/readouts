### Call PhysicsPipeline::step at 0.35.3 with its 12 arguments and read contacts as start-of-step state
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3

**One 0.35.3 step applies queued user changes, runs broad and narrow phase once, solves and integrates per CCD substep, then only refreshes broad-phase AABBs; a non-finite body is quarantined, not reported as an error.**

- **How:** Signature (docs.rs 0.35.3): step(&mut self, gravity: Vector, integration_parameters: &IntegrationParameters, islands: &mut IslandManager, broad_phase: &mut BroadPhaseBvh, narrow_phase: &mut NarrowPhase, bodies: &mut RigidBodySet, colliders: &mut ColliderSet, impulse_joints: &mut ImpulseJointSet, multibody_joints: &mut MultibodyJointSet, ccd_solver: &mut CCDSolver, hooks: &dyn PhysicsHooks, events: &dyn EventHandler). Gravity is a glam Vector by value, the broad phase is the concrete BroadPhaseBvh (alias DefaultBroadPhase), `&()` implements both PhysicsHooks and EventHandler, and PhysicsWorld::step() is step_with_events(&(), &()) over the world's own fields. Order in step_inner (substep.rs): reset counters and the quarantine report; drain joint wake-ups and joins; quarantine non-finite user changes; apply user changes to colliders, then bodies (new bodies join the awake island here); detect_collisions = BroadPhaseBvh::update, then the narrow phase's handle_user_changes, register_pairs, compute_contacts, compute_intersections (filter hooks and collision events run here); clear change flags; then per CCD substep (max_ccd_substeps == 0 means one substep and no CCD): kinematic position-based velocities from their next pose, island update and staged velocity solve with gravity, contact-force events, CCD motion clamping, advance_to_final_positions (pose := next pose, collider poses, fresh AABBs), quarantine; after the last substep only BroadPhaseBvh::set_aabb for moved colliders, no narrow phase. The staged solver runs only for the awake island. The step copies IntegrationParameters and rewrites dt only when CCD splits the step; it mutates the islands, both phases, the bodies and colliders, the joint sets' pending wake-ups and joins, and the CCD solver when CCD runs.
- **Gotchas:** The rapier.rs guide documents 0.36 and its step call passes a 13th argument (&mut soft_body_set): pasted into a 0.35.3 crate it fails with E0433 (no SoftBodySet) and E0061 (12 vs 13 arguments). Older tutorials pass &gravity, a generic broad phase or a QueryPipeline argument; none of those exist at 0.35.3. Because the narrow phase runs before integration, contact_pairs() read after a step describe the poses at the start of that step while scene queries see end-of-step AABBs: measured, a box leaving a wall at 20 u/s is 0.3125 clear after one step yet still has an active contact, and a ray already sees its new face. Non-finite state never panics: since 0.35.0-beta.0 the Quarantine disables the body, keeps its last valid pose, zeroes its velocity and lists it in quarantine() for that step only; measured, an infinite velocity passes an is_nan() guard and leaves an all-finite, disabled body hanging at y = 2 under gravity.
- **In si-rpg-engine:** rapier_law.rs `integrate` calls `loaded.world.step()` (PhysicsWorld: no hooks, no events) after set_next_kinematic_translation and solve_character_collision_impulses, and `rebuild_snapshot` then hashes contact pairs computed before that quantum's integration. `bad()` tests is_nan() only, so an infinite velocity in a body record passes `signature`, reaches Rapier, is quarantined and is written back finite by `write_body`: refuse `!x.is_finite()` and `!loaded.world.quarantine().is_empty()` right after `step()` so that 'NaN aborts a step' also covers what Rapier absorbs.

### Collect Rapier 0.35.3 collision events with a Sync EventHandler and ActiveEvents set on a collider
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3

**Collision and contact-force events are opt-in per collider (ActiveEvents, empty by default) and are delivered during the step to an EventHandler, which must be Sync unless the unsync-callbacks feature is on.**

- **How:** Give at least one collider of the pair `.active_events(ActiveEvents::COLLISION_EVENTS)` (or CONTACT_FORCE_EVENTS with a contact_force_event_threshold) and pass a handler as the step's events argument (PhysicsWorld::step_with_events(&(), &handler)). ChannelEventCollector::new(collision_sender, contact_force_sender) takes two std::sync::mpsc::Sender values; drain the receivers after the step. A custom handler implements handle_collision_event(&self, bodies, colliders, event: CollisionEvent, contact_pair: Option<&ContactPair>) and handle_contact_force_event(&self, dt, bodies, colliders, contact_pair, total_force_magnitude), keeping state in atomics or a Mutex because EventHandler: MaybeSync and MaybeSync = Sync. Measured: a box dropped on a floor and then lifted clear yields exactly one Started and one Stopped, through a counter or the channel collector; with ActiveEvents::empty() it yields none. Which body-type pairs produce contacts at all is ActiveCollisionTypes.
- **Gotchas:** A Cell or RefCell counter fails with E0277 ('`Cell<u32>` cannot be shared between threads safely … required for `Counter` to implement `MaybeSync`'); 0.35.0-beta.0 relaxed the bound from Send + Sync to Sync. Contact-force totals changed in the 0.35.2 patch (the step's total impulse, one substep fewer). 0.36.0 adds a required handle_soft_body_tear_event and a third ChannelEventCollector sender, so every custom handler breaks on that bump.
- **In si-rpg-engine:** rapier_law.rs passes no handler (`world.step()`), so no event reaches the hash today. T3's plan to hash collision-event order separately from body state needs ActiveEvents on the tracked colliders and a Sync collector (a Mutex<Vec<_>> or ChannelEventCollector) drained after `step()` in `integrate`; this lane measured delivery, not the order of simultaneous events, so T3 must measure that order before hashing it.

### Count Rapier 0.35.3 sleep in quanta: time_until_sleep = 32·dt sleeps after quantum 32, 33 off the origin
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3

**Sleep is judged on displacement: each step a dynamic body whose half per-step drift is below normalized_linear_threshold·length_unit·dt adds dt to time_since_can_sleep (any other step resets it), and its island sleeps once time_since_can_sleep ≥ time_until_sleep.**

- **How:** Configure per body: `rb.activation_mut().time_until_sleep = 32.0 * dt` (seconds, default 0.5); normalized_linear_threshold (default 0.05 u/s, negative = never sleeps); angular_threshold (default 0.5 rad/s; only collider-less bodies compare against it, bodies with colliders use only its sign plus a fixed π/2 rad/s gate); RigidBodyBuilder::can_sleep(false) = RigidBodyActivation::cannot_sleep(). With dt = 1/64 the timer counts exactly: a body at rest from its first step sleeps after quantum 32 with time_since_can_sleep = 0.5. The first check compares against sleep_prev_pose = Pose::IDENTITY, so a body inserted farther than 2·threshold·dt from the identity pose loses its first quantum (measured: at (3, 1, 0) it sleeps after 33). The test is drift·0.5 < threshold·dt, so pure translation sleeps under twice the threshold (measured: 0.08 u/s sleeps, 0.12 u/s never), and sleeping zeroes the velocity.
- **Gotchas:** The field doc says the threshold is compared against the farthest-point speed; since 0.35.0 the code uses the pose displacement and ignores the velocities of dynamic bodies (the changelog says so), so a slow drift under 0.1 u/s is frozen after time_until_sleep. The 0.35.0-beta.0 defaults (0.05 u/s, 0.5 s) replaced 0.4 u/s and 2.0 s: numbers from older posts are wrong for 0.35. Islands sleep and wake as a unit, so a body touching an awake body stays awake past its own timer. sleep_prev_pose is pub(crate) and cannot be set from outside the crate.
- **In si-rpg-engine:** rapier_law.rs `build_world` sets `activation_mut().time_until_sleep = SLEEP_QUANTA * DT` (32/64 s, exact) on dynamic bodies inserted at their record position, so a body at rest from load sleeps after quantum 33, not 32; `rebuild_snapshot` hashes `time_since_can_sleep / DT`, an exact integer while dt = 1/64. A rebuilt world starts every body at sleep_prev_pose = identity, so a restore path (T2, restore-internals) resets each off-origin body's count on its first step; this is inferred from the measured first-quantum loss, not yet run as a restore.

### Expect Rapier 0.35.3 body types to gate contacts: kinematic-fixed off, kinematic pushes dynamic one way
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3

**By default only pairs involving a dynamic body get contacts; kinematic bodies follow their next pose (position-based) or their velocity (velocity-based) and push dynamic bodies without being pushed; fixed bodies never move.**

- **How:** RigidBodyType: Dynamic = 0 (forces, gravity, contacts), Fixed = 1 (infinite mass, never moves), KinematicPositionBased = 2 (set_next_kinematic_translation / rotation; the step derives the velocity: measured 0.1 in one 1/64 s step gives vx 6.4), KinematicVelocityBased = 3 (set linvel / angvel; the pose integrates: 6.4 u/s gives x 0.1 after one step). ActiveCollisionTypes::default() = DYNAMIC_DYNAMIC | DYNAMIC_KINEMATIC | DYNAMIC_FIXED; OR in KINEMATIC_FIXED, KINEMATIC_KINEMATIC or FIXED_FIXED per collider when those pairs must produce contacts or events (measured: setting KINEMATIC_FIXED on the kinematic collider alone was enough). A kinematic body's trajectory ignores what it hits: measured, 64 steps at 2 u/s end at exactly x = 2 while pushing a box ahead of it.
- **Gotchas:** A kinematic body overlapping a fixed wall has no active contact by default, so contacts never tell a kinematic character that it is blocked: the character controller's shape casts do. Enabling KINEMATIC_FIXED creates contacts and events, not a push-back. Kinematic bodies sleep only when both velocities are exactly zero (0.30.1).
- **In si-rpg-engine:** rapier_law.rs `build_world` makes driven bodies kinematic_position_based() with lock_rotations, can_sleep(false), ccd_enabled(false) and additional_mass(1.0), and slabs and the heightfield fixed(); with default ActiveCollisionTypes the walker has active contacts only with dynamic boxes, and `integrate` resolves walls with KinematicCharacterController::move_shape (shape casts, not contacts) and pushes boxes with solve_character_collision_impulses. Two walkers are kinematic-kinematic and get no contacts either, so T4's 'character against a character' case is decided by the controller's casts alone.

### Filter Rapier pairs with collision_groups (no contact) or solver_groups (contact, no force); flag the hooks
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3

**collision_groups stop a pair before the narrow phase (no contacts, no events); solver_groups keep contacts and events but drop the forces; PhysicsHooks run only for pairs where a collider carries the matching ActiveHooks flag.**

- **How:** InteractionGroups::new(memberships: Group, filter: Group, test_mode: InteractionTestMode): And passes when (a.memberships & b.filter) != 0 && (b.memberships & a.filter) != 0, Or when either holds; the default is InteractionGroups::all(). Set them with ColliderBuilder::collision_groups and solver_groups. Measured with the floor in GROUP_1 and a box in GROUP_2 filtering GROUP_3: excluded by collision_groups, the box falls through with no contact and no event; excluded by solver_groups it falls identically (y −3.016) yet the contact exists and a Started event fires. Hooks: implement PhysicsHooks (filter_contact_pair(&self, &PairFilterContext) -> Option<SolverFlags>, filter_intersection_pair, modify_solver_contacts) and set `.active_hooks(ActiveHooks::FILTER_CONTACT_PAIRS)` (or FILTER_INTERSECTION_PAIR, MODIFY_SOLVER_CONTACTS); None drops the pair, Some(SolverFlags::empty()) keeps contacts without forces; the filter runs after collision groups and replaces the default non-dynamic filtering.
- **Gotchas:** The ColliderBuilder::collision_groups doc example calls InteractionGroups::new with two arguments: E0061 since 0.31 added the test mode. The guide's prose spells ActiveHooks::FILTER_CONTACT_PAIR; the constant is FILTER_CONTACT_PAIRS (E0599). A hook whose flag is not set on a collider is never called (measured: the same refusing hook leaves the box resting at 0.350). Under And both sides must accept each other, so a floor left at InteractionGroups::all() interacts with every box whose membership and filter are non-empty: design both colliders' groups together. Since 0.35.0 the broad phase itself filters by collision groups.
- **In si-rpg-engine:** rapier_law.rs sets no groups and no hooks and passes `&()`, so every pair interacts. Groups and hooks are law: a filter that reads anything outside the record (host state, time) breaks replay. If the post-Phase-2 mesh slice needs one-way surfaces or character-only walls, store the group bits in the world file and mix them into `signature`'s geometry hash with the shapes.
