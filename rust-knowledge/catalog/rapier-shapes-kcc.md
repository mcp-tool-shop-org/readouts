### Bake glTF collision meshes offline with the gltf crate and refuse what the deterministic law cannot reproduce
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust gltf 1.4.1 (host tool); parry3d-f64 0.30.2 at load

**The glTF 2.0 spec fixes meters, radians, +Y up, float32 POSITION with min/max, unit quaternions and in-range indices, but files can still break it; the gltf crate (1.4.1) exposes f32 transforms, Mode, positions, indices and skins. Converting belongs in a host tool that writes baked f64 triangles, not in the wasm law.**

- **How:** Tool: gltf::import the file, walk the scene's nodes and compose each Transform in f64 (matrix() or decomposed()). Refuse a primitive unless mode() == Mode::Triangles, every position is finite, and every index (reader indices, ReadIndices::into_u32) is below the position count and not 255/65535/4294967295 for its width; refuse skins (node.skin()), animations and morph weights on collision nodes. Refuse a rotation with |q.q - 1| above a stated tolerance (1e-6 suits f32 input), refuse zero or non-finite scale, and when the scale's determinant is negative swap two indices per triangle. Write units ('m') and up axis ('+Y') into the record and refuse records without them, then canonicalise -0.0, weld, and store f64 vertex and u32 index buffers (and offline hulls).
- **Gotchas:** gltf's Transform holds f32 arrays: widening to f64 is exact, but composing in f32 is not, so compose in f64 once and store the result so the law never multiplies transforms. f32 sqrt(1/2) quaternions miss unit length by 3.4e-8 (measured), so an exact == 1.0 test refuses valid files. A mirrored node, scale (-1, 1, 1), flips a floor triangle's normal from +Y to -Y and swapping two indices restores it (measured). The spec says a skinned mesh's node transform MUST be ignored, so skinned geometry has no single static shape, and degenerate triangles are only SHOULD NOT. The gltf crate is outside this KB's oracle set: its API was checked on docs.rs, not compiled.
- **In si-rpg-engine:** The collision-from-meshes slice after Phase 2 (its input is the studio's glb survey) should keep the gltf crate in host tooling: the law is a wasm32-unknown-unknown cdylib with raw extern "C" exports over static f64 buffers and a pinned digest, and at load it already refuses NaN and renormalises quaternions with canon_quat. The world file carries the baked buffers; solver_load validates them like body rows and mixes them into Signature.geom.

### Call KinematicCharacterController::move_shape with Absolute lengths and self-exclusion, then apply the result
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3

**move_shape sweeps the shape (at most 20 casts, each stopping offset short of obstacles), tries a stair step on every wall hit and otherwise slides, snaps down only if the call started grounded, and returns EffectiveCharacterMovement { translation, grounded, is_sliding_down_slope }; it moves nothing, the caller applies translation.**

Per quantum: let pos = *world.bodies[h].position(); let q = world.query_pipeline_with_filter(QueryFilter::new().exclude_rigid_body(h)); let mv = ctl.move_shape(dt, &q, &*shape, &pos, desired, |c| collisions.push(c)); world.bodies[h].set_next_kinematic_translation(pos.translation + mv.translation); then step. Pass the shape the body's collider uses, zero vertical velocity on mv.grounded, and read is_sliding_down_slope as advisory.

Depenetration runs only when the desired translation is (near) zero, so a walker with any intent is never pushed out that way. is_sliding_down_slope was true on flat ground whenever the move had a downward part. An airborne character stepped up a 0.2 rise (dy 0.2101); the 0.36 guide says autostep needs floor contact first, which the pinned code does not check. ### Canonicalise -0.0 and weld vertices offline: MERGE_DUPLICATE_VERTICES keys raw bits and renumbers the mesh
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust parry3d-f64 0.30.2 (enhanced-determinism)

**MERGE_DUPLICATE_VERTICES (and FIX_INTERNAL_EDGES, whose bits 144 include it) keys vertices by raw bytes but compares with ==, so (-0.0, 0, 0) welds to (0, 0, 0) in a 4- or 16-vertex mesh and not in a 64-vertex one; merging also renumbers and drops unreferenced vertices, and DELETE_DEGENERATE_TRIANGLES only removes repeated-index triangles.**

- **How:** In the offline tool: pass every coordinate through canon() (x == 0.0 -> 0.0), refuse NaN, weld exact duplicates yourself, drop zero-area triangles by computing their area, and write the vertex buffer in first-reference order with every vertex referenced. Such buffers pass through FIX_INTERNAL_EDGES unchanged (measured), so the stored bytes are the bytes parry uses. Never keep outside references to input vertex indices across a merging flag.
- **Gotchas:** TriMeshFlags documents MERGE as joining 'vertices with the exact same coordinates' and TriMesh documents vertices() as keeping construction order; signed zero breaks the first, and any merging flag breaks the second (7 vertices in, 4 out, (9, 9, 9) dropped). The ±0 result depends on hash-table probing: the key hashes the raw bytes, equality is ==, and under enhanced-determinism the map is an IndexMap with FxHasher32. Whether the flip point differs on wasm32 was not measured. A mesh whose every triangle repeats an index comes back with 0 triangles, not EmptyIndices, because the emptiness check runs before the deletion. A zero-area triangle with three distinct indices is kept.
- **In si-rpg-engine:** signature() in rapier_law.rs mixes every geometry f64 with mix_f64 (to_bits), so -0.0 and 0.0 already give different world signatures. The mesh slice's offline tool should apply the same canon() that write_body uses, and the loader should refuse a non-canonical value, which is the pattern T3's load-time refusal of non-finite authored values already follows.

### Compute convex hulls and VHACD parts offline with pinned parameters, then load stored buffers with convex_mesh
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust parry3d-f64 0.30.2, rapier3d-f64 0.35.3

**SharedShape::convex_hull is None for fewer than 3 points, NaN, coincident or collinear points, but Some for coplanar points: a flat polyhedron of mass 0. VHACD output follows its parameters: a two-box mesh of volume 2 became 2 parts (mass 2.0000) at resolution 64 and 13 parts (summed mass 3.1227) at resolution 16.**

- **How:** Offline: parry3d_f64::transformation::try_convex_hull(&points) -> (vertices, indices); refuse Err and refuse a hull whose mass_properties(1.0).mass() is 0. For concave parts call SharedShape::convex_decomposition_with_params(&v, &idx, &VHACDParameters { .. }) with every field written out (0.30.2 defaults: resolution 64, concavity 0.01, alpha 0.05, beta 0.05, plane_downsampling 4, convex_hull_downsampling 4, convex_hull_approximation true, max_convex_hulls 1024) and store each part's vertex and index buffers. At load: ColliderBuilder::convex_mesh(points, &indices) per part, which skips the hull computation and gave the same mass bits as convex_hull, then ColliderBuilder::compound.
- **Gotchas:** ConvexHullError's docs say nearly coplanar 3D input gives MissingSupportPoint; the pinned code triangulates coplanar input as a flat hull and from_convex_mesh accepts it (measured Some, mass 0), and ColliderBuilder::convex_hull ('None if the points don't form a valid convex shape') and MeshConverter::ConvexHull pass it too (both returned a mass-0 shape). The hull code counts dimensions with a 1.0e-7 eigenvalue threshold, so a nearly flat cloud can land on either side. VHACD memory grows as O(resolution^3) and convex_hull_approximation = false costs 2-5x time (VHACDParameters docs). A summed compound mass above the source volume means overlapping parts.
- **In si-rpg-engine:** The post-Phase-2 slice plans 'hull point sets stored offline for determinism': store try_convex_hull's vertex and triangle-index buffers rather than only the points, load them with ColliderBuilder::convex_mesh, and refuse a mass-0 hull at load. VHACD belongs in the offline tool: its O(resolution^3) voxel grid would be a transient allocation inside a solver binary whose memory T3's lint forbids from growing.

### Set FIX_INTERNAL_EDGES on ground dynamic bodies slide over; test heightfield row 0 moving +x on its own
`▸ plausible` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3, parry3d-f64 0.30.2

**Without the flag, a frictionless box sliding flat at 2 u/s stopped dead at the first internal edge of a trimesh or heightfield (0.25 of 2.00 travelled in 64 quanta) because the edge adds a sideways contact normal. TriMeshFlags::FIX_INTERNAL_EDGES removed the snag; on a 9 x 9 heightfield, HeightFieldFlags::FIX_INTERNAL_EDGES removed it for every row and column in both directions except moving +x in row 0, the lowest-z row of cells.**

- **How:** ColliderBuilder::trimesh_with_flags(v, idx, TriMeshFlags::FIX_INTERNAL_EDGES) and ColliderBuilder::heightfield_with_flags(heights, scale, HeightFieldFlags::FIX_INTERNAL_EDGES) for any ground a dynamic body slides or rolls on; triangle_normal_constraints(id).is_some() confirms the pseudo-normals exist. Keep an outcome test per direction that crosses a seam in row 0 and in an interior row. Padding a field with one extra row on its low-z side, so nothing moves in row 0, is a workaround inferred from the measurement, not from any source.
- **Gotchas:** The snag is a solver-contact effect: with max_ccd_substeps = 0 it was unchanged, and the kinematic controller walked the same seams with or without the flag (1.985 on a 2-row field, 2.000 on 3 rows, never airborne). A 2-row heightfield is all row 0. TriMeshFlags::FIX_INTERNAL_EDGES also merges duplicate vertices (see the weld recipe). parry's heightfield triangle_normal_constraints says its edge pseudo-normals are 'given in no particular order'; whether that explains the row-0 case is a guess.
- **In si-rpg-engine:** build_world calls ColliderBuilder::heightfield with no flags, so T4 pin 3's seam test (a box sliding down across a cell boundary with no upward hitch beyond the skin) is where heightfield_with_flags(.., HeightFieldFlags::FIX_INTERNAL_EDGES) gets measured; adopting it changes the binary digest and the goldens once. That test needs a crossing in row 0 moving +x: a 2-row field, which signature() allows and packages/tick/verbs.test.js uses for its sloped case, has no other row.
