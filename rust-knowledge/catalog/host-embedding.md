### Accept a new host only when its T1 trace equals node's in 16-hex-digit IEEE bits, never in decimals
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust any: to_bits / from_bits are stable since 1.20; trace format fixed by T1

**solver/build.mjs under node is the reference binding: a Godot or Unreal host proves it runs the same law by printing the T1 trace for the same seed and log and passing harness/first-difference.js against node's trace, which writes every body field as its IEEE bit pattern.**

- **How:** Print each float as `format!("{:016x}", x.to_bits())`: sixteen lowercase hex digits, zero-padded, high word first, the same string trace-line.mjs's bits() builds from two DataView words; parse node's tokens with `f64::from_bits(u64::from_str_radix(tok, 16)?)`. Keep PHASE-2's line grammar (tick, hash, body id and 13 fields, zone, links, snap length and digest, minds, `end <lines>`), drive the host with the same seed and admitted log, and require an empty diff for the product scene and every fixture on each platform the host ships on (T3's ARM64 lane is the pattern).
- **Gotchas:** Decimal renderings hide what matters: at six decimals 0.1 + 0.2 and 0.3 print alike while their bits differ in the last place (the check), and JavaScript prints negative zero as "0" (measured on this rig with node v22.22.3: String(-0), (-0).toFixed(3) and JSON.stringify(-0)). PHASE-2 rules out error thresholds in place of bit-exact agreement. to_bits is a raw transmutation and std says floats and integers share endianness on all supported platforms, so the token is portable. The hash column comes from the JavaScript frame hash, so a host that runs only the .wasm can match the body fields while its hash column must come from the same packages/frame code or from a port that passes this diff first.
- **In si-rpg-engine:** harness/trace-line.mjs bits() and the format in docs/PHASE-2.md (T1) are the conformance contract; harness/first-difference.js names the first differing quantum, body and field; solver/build.mjs is the reference binding and packages/frame computes the frame hash in JavaScript, so each host plan must say where its hash column comes from.

### Bind the law natively in Godot with gdext 0.5.5: a cdylib entry point, api-4-N no newer than the running Godot

Enable at most one of `api-4-2` ... `api-4-7` (with none, the current Godot minor at patch 0 is used) and keep runtime version >= API version. Hand Godot copies of the f64 state: its `real` is f32 unless gdext's `double-precision` feature is on and Godot itself is built with `precision=double`.

A pose narrowed to f32 cannot be widened back to the committed f64 (the check shows 0.1 + 0.2 losing its low bits), so nothing read from a Node3D or Vector3 may be written into the law's buffers: only intents cross back, and the admitted log records the f64 the law received.

### Build wasmtime's Config for the law by hand and pin an LTS line; defaults and fuel costs move between releases
`✅ solid` · ✓ verified · · no code check · Rust wasmtime 49.0.1 (2026-09-24) or LTS 48.0.3; building wasmtime 49 needs Rust 1.96+

**Wasmtime 49.0.1's defaults are not a determinism profile (NaN canonicalization off, relaxed SIMD on with the fastest per-CPU lowering, the threads proposal on through a default crate feature), and releases move them: 49.0.0 turned wide-arithmetic on and changed fuel charges, and the 49.0.1 / 48.0.3 security patches changed fuel spend again.**

- **How:** Set every knob in code: `config.cranelift_nan_canonicalization(true)` (replaces NaNs with one canonical value; not enabled by default because the spec does not require it), `config.wasm_relaxed_simd(false)` (or `relaxed_simd_deterministic(true)`), `config.wasm_threads(false)`. For a watchdog use `config.consume_fuel(true)` plus `store.set_fuel(n)`: fuel is the deterministic interruption, and `epoch_interruption` is documented as not deterministic. Make memory growth deterministic the ways the determinism page lists (a store limiter, a memory creator that reserves the maximum up front, or a wasmparser check that refuses growable memories). C API equivalents: `wasmtime_config_cranelift_nan_canonicalization_set`, `wasmtime_config_wasm_relaxed_simd_set`, `wasmtime_config_wasm_relaxed_simd_deterministic_set`, `wasmtime_config_wasm_threads_set`, `wasmtime_config_consume_fuel_set`. Pin the runtime beside the solver pins: a new major ships on the 20th of each month and may break behaviour; majors divisible by 12 are LTS for 24 months (48.0.3, 2026-09-24), the rest are supported for 2 months.
- **Gotchas:** Fuel counts are not portable across Wasmtime versions: 49.0.0 began charging Config::operator_cost inside constant expressions and the start call (previously 1 fuel each), and 49.0.1 / 48.0.3 fixed dropped fuel-spend for call_ref callees and exception returns. Running out of fuel is therefore a host failure to report, never an outcome written to the admitted log or folded into a hash. NaN canonicalization adds checks after f32/f64/v128 operations; the law already aborts a step on NaN, so the knob protects only a NaN's bits between its creation and that abort (the spec leaves the sign of an arithmetic NaN nondeterministic). Patch releases promise unchanged behaviour, yet these fuel fixes shipped as patches: pin the exact version, not a range.
- **In si-rpg-engine:** solver/.cargo/config.toml and solver/build.mjs already pass -C target-feature=-relaxed-simd, and T3's lint will refuse relaxed-SIMD opcodes and growable memory; the host Config is the second gate for the same properties. lib.rs step() and rapier_law.rs solver_step() return 0 on NaN, so canonicalization is belt and braces there. Any fuel budget belongs to the host harness (T5's replay bundles), never to the frame hash in packages/frame.

### Choose the runtime per platform by tier: Cranelift needs executable pages at run time, interpreters do not
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust wasm32-unknown-unknown on rustc 1.98.1 (default target features exclude simd128 and relaxed-simd)

**Four runtimes can execute the law's core module natively, at different maturity: Wasmtime 49.0.1 (Cranelift or Winch compilers, Pulley interpreter), Wasmer 7.4.2, WAMR 2.4.5 and wasm3 0.9.0. Because the law uses no SIMD, even the SIMD-less wasm3 can load it.**

- **How:** Wasmtime tiers: Tier 1 = x86_64-pc-windows-msvc, x86_64-unknown-linux-gnu, x86_64-apple-darwin, the Cranelift and Winch compilers, the Rust and C embedding APIs; Tier 2 = aarch64 Linux and macOS, the Pulley interpreter, #![no_std] support, the C++ API; Tier 3 = aarch64-pc-windows-msvc, iOS, Android, i686. Cranelift and Winch need an OS that can create executable pages on the fly and cannot statically link a precompiled module; a no_std build runs AOT-precompiled modules; where Cranelift has no backend Wasmtime uses Pulley, which runs wherever Wasmtime compiles, with a performance penalty. Wasmer 7.4.2 (2026-09-16): Singlepass, Cranelift (the default) and LLVM compilers; NaN canonicalization is `Cranelift::canonicalize_nans(true)`, default false. WAMR-2.4.5 (2026-06-29, three CVE fixes; the project now lives at github.com/wasm-micro-runtime): interpreter, AOT through wamrc, Fast JIT and LLVM JIT; x86-64, x86-32, ARM, AArch64, RISC-V, Xtensa, MIPS, ARC. wasm3 0.9.0 (2026-08-24, its first release after v0.5.0): an interpreter that now fully validates modules; its README lists the deterministic profile as ready and fixed-width SIMD and threads as not available.

### Drive one law instance per world from one thread; collect Rapier events in a Sync buffer the host drains
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3; wasmtime 49.0.1; bytemuck 1.25.2; Godot 4.7

**The law holds one Rapier world in static mut SOLVER and silently rebuilds it when the call signature changes, so a host needs one module instance per world, called from one thread; host callbacks cannot go into Rapier (its EventHandler must be Sync), so events belong in a law-owned Sync buffer drained after each step; and the buffer traffic is small, 22,528 bytes per quantum at the engine's maxima.**

- **How:** Per world, one wasmtime Store and Instance called from the simulation thread: `TypedFunc::call` takes `impl AsContextMut`, so a Store serves one call at a time, whereas a native build's `static mut` has no such guard (serialize it or never share it). In Godot keep scene-tree access on the main thread (the docs: interacting with the active scene tree is not thread-safe; from another thread publish with call_deferred / set_deferred) and do not lean on gdext's experimental-threads. For events, hand Rapier a law-owned handler (`EventHandler: MaybeSync`, which is Sync unless rapier's unsync-callbacks feature is on), e.g. a `Mutex<Vec<_>>` or Rapier's ChannelEventCollector, drain it after each step, and expose the drained list through a buffer the host reads like the bodies. Copies: bodies 8,704 B, colliders 5,120 B and heights 2,048 B in, 6,656 B out (13 fields x 64 bodies) = 22,528 B per quantum, 1,441,792 B/s at 64 Hz, plus the snapshot; a `#[repr(C)] #[derive(Pod, Zeroable)]` record array becomes the byte slice `Memory::write` takes through `bytemuck::cast_slice`.
- **Gotchas:** Interleaving two worlds through one instance never errors: ensure() rebuilds the world on each switch and reports success, so warm-start and sleep state are dropped and the run can diverge from a dedicated instance without a signal. A host object handle captured in a handler is refused at compile time (an Rc<RefCell<...>> sink: E0277, 'required for HostSink to implement MaybeSync'); switching on unsync-callbacks to allow it changes the solver's feature set, and with it the artifact. derive(Pod) refuses a record with padding (16 f64 plus a u32 flag: E0080, 'derive(Pod) was applied to a type with padding'), which keeps uninitialized bytes out of the law's buffers.

### Treat the component model as a new target and ABI: WIT values are copied across and memory is never shared
`✅ solid` · ✓ verified · · no code check · Rust wasm32-wasip2 (Tier 2) on rustc 1.98.1; wit-bindgen 0.62.0; wasmtime 49.0.1; jco 1.35.0

**Option C replaces raw pointers with a typed WIT interface, but it is a different artifact and contract: wasm32-wasip2 emits a component, a component may not export a memory, values cross by a lift/lower copy, and floats loaded across the boundary lose their NaN sign and payload.**

- **How:** Write the law's interface in WIT (a world exporting a step function over list<f64> bodies), generate guest bindings with `wit_bindgen::generate!({ path: "wit/world.wit" })` (wit-bindgen 0.62.0, 2026-09-10), build with `cargo build --target wasm32-wasip2` (Tier 2, outputs a component; the component-model book says cargo-component is being deprecated), host it natively with wasmtime's `component::bindgen!` (the component model is Tier 1), and in JavaScript with jco 1.35.0 (2026-09-24), which transpiles a component into ES modules for Node and browsers. What the raw ABI keeps by convention, strides 17 and 10 and pointer/offset pairs, becomes a checked type.
- **Gotchas:** The engine's zero-copy contract cannot carry over: a component may not export a memory, and the Canonical ABI explainer says an implementation can at best fuse lifting and lowering into one direct copy, so up to 8,704 bytes of bodies cross by copy on every call. A wasm32-wasip2 runtime 'should support the wasi preview 2 API set', so the component can import WASI interfaces the current module never needed, and Wasmtime's determinism page says to virtualize nondeterministic WASI APIs. Browsers run it only through jco's output. Dropping NaN sign and payload is harmless for a law that aborts on NaN, but any design that hashes NaN bits breaks at the boundary.
- **In si-rpg-engine:** solver/build.mjs hard-codes strides 17 and 10 against lib.rs BODY_STRIDE and COLLIDER_STRIDE with nothing checking the pair; a WIT record would. But fixtures/solver.sha256, solver/rust-toolchain.toml (target wasm32-unknown-unknown) and the three-engine goldens describe the core module, so option C is a new artifact and a new T1 baseline, not a re-wrap of the pinned binary.
