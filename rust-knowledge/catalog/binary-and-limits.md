### Allow ~1,200 quanta for a walker started 0.1 inside the floor: Rapier depenetrates only on a zero desired move
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3

**move_shape runs its depenetration pass only for a zero desired translation, and the engine always passes gravity, so a walker started 0.1 inside the floor rises only by the 1e-4 normal nudge per quantum and stands after about 1,200 quanta.**

- **How:** Assert the recovery over a stated run instead of an instant fix: over at least 1,300 quanta the feet end at the floor plus the offset and never go below their start (measured -0.0936 at quantum 64, -0.0360 at 640, +0.0101 at 1,280).
- **Gotchas:** The depenetration pass, when it does run, is capped at a quarter of the character's height per call. With normal_nudge_factor = 0 the walker stays 0.1 inside indefinitely. The trace was the same at vx 0 and 0.4.
- **In si-rpg-engine:** harness/course.test.js, T4 pin 5 ('a walker starting with its centre inside the floor by 0.1 ends standing on the floor'): rapier_law.rs integrate() always passes (vx, vy + G*DT, vz) * DT, so the depenetration branch never runs for a driven walker.

### Don't rely on -C target-feature=-relaxed-simd: a #[target_feature] fn or a relaxed intrinsic still emits
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust 1.82+ (relaxed intrinsics stable); checked on 1.98.1

**Under -C target-feature=-relaxed-simd a #[target_feature(enable = "relaxed-simd")] function and a plain call to core::arch::wasm32::f32x4_relaxed_madd both compile without unsafe and emit f32x4.relaxed_madd (fd 85 02).**

- **How:** Keep the crate-level -C target-feature=-relaxed-simd: it sets cfg(target_feature = "relaxed-simd") for every crate built, which is what gates the relaxed paths in matrixmultiply 0.3.11 (sgemm muladd becomes f32x4_relaxed_madd) and wide 1.7.1 (u8x16::shuffle becomes u8x16_relaxed_swizzle). Make the binary lint the guarantee, and when adding a dependency grep it for target_feature(enable and for *_relaxed_* intrinsics.
- **Gotchas:** The rustc book: there is no compiler flag that disables SIMD emission once a function enables it with #[target_feature]. On Wasm a safe #[target_feature] fn is callable from safe code, so the call site carries no unsafe marker. The precompiled std is built with the target's default features and ignores -C target-feature. relaxed-simd implies simd128. relaxed_madd may round once or twice depending on the host.
- **In si-rpg-engine:** solver/.cargo/config.toml, solver/build.mjs and FLAGS.md: the flag holds for today's graph (0 SIMD instructions in the binary) but is not the guarantee; T3 pin 2's lint is. PR #44's config.toml comment already says this.

### Expect Rapier 0.35.3 to stop T4's fast box at a fixed slab with ccd_enabled(false); max_ccd_substeps 0 tunnels
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3 (behaviour since 0.35.0)

**In rapier3d-f64 0.35.3 every dynamic body moving more than half its thinnest half-extent per step is swept against fixed colliders even with ccd_enabled(false); ccd_enabled(true) only adds kinematic and dynamic targets.**

- **How:** IntegrationParameters::max_ccd_substeps is the switch: 1 (the default) sweeps fast dynamic bodies against fixed colliders and clamps next_position to the first time of impact, 0 disables all CCD. RigidBodyBuilder::ccd_enabled(true) makes a bullet that also sweeps kinematic and dynamic bodies, never another bullet. Fast means max point velocity * dt > 0.5 * ccd_thickness, and a cuboid's ccd_thickness is its smallest half-extent: a 0.05 box at dt = 1/64 is fast above 1.6 u/s. To show a tunnelling test failing, run it with max_ccd_substeps = 0.
- **Gotchas:** The clamp moves the pose only; velocities are kept and the next step's speculative contacts absorb the approach. A body already overlapping a target is not clamped in 3D (only fractions > 0 are accepted). Non-bullets never sweep moving bodies, bullets never sweep bullets, heightfield targets are one-sided, and mesh-shaped fast bodies are never swept. Linear speed is capped at 400 u/s per substep. Pre-0.35 advice that CCD is off unless ccd_enabled no longer holds. Measured envelope at dt 1/64: no tunnelling for 1 to 1,000 u/s against fixed slabs of half-thickness 0.02 to 0.0001.
- **In si-rpg-engine:** T4 pin 2 and its acceptance line: rapier_law.rs build_world makes dynamic bodies with ccd_enabled(false) and inherits max_ccd_substeps = 1, so the fast-body test already passes. Through solver_step 14/14 start phases stay on the near side, a copy with max_ccd_substeps = 0 tunnels in 10/14, and ccd_enabled(true) left every result identical; it only adds sweeps against the kinematic walker.

### Fix wasm32 memory with -C link-arg=--no-growable-memory or equal, page-aligned --initial-memory/--max-memory
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rustc 1.98.1 (LLD 22.1.8), wasm32-unknown-unknown

**On rustc 1.98.1 (rust-lld, LLD 22.1.8) two stable link args make a wasm32 module's maximum equal its initial size; memory.grow of one page then returns -1 on every host.**

- **How:** Pass -C link-arg=--no-growable-memory (the maximum becomes the initial size wasm-ld computes: 1 MiB stack, data, statics, rounded up to pages) or -C link-arg=--initial-memory=N -C link-arg=--max-memory=N with N a multiple of 65,536 and at least the bytes wasm-ld reports. RUSTFLAGS replaces the [target] rustflags of .cargo/config.toml, so put the argument where it survives: a build.rs printing cargo::rustc-link-arg-cdylib=--no-growable-memory (measured: still 18/18 pages with RUSTFLAGS set), or repeat it in every RUSTFLAGS. Check the result with a decoder: memory limits flag 0x01 with max == min. From Rust, core::arch::wasm32::memory_grow(0, n) returns usize::MAX (-1 as i32) once the maximum would be exceeded.
- **Gotchas:** wasm-ld refuses, verbatim: 'initial memory must be aligned to the page size (65536 bytes)', 'initial memory too small, 1117808 bytes needed' (for the solver), 'maximum memory too small, 4194304 bytes needed' (max below initial). --no-growable-memory alone fixes the memory at the linker's minimum (18 pages for the solver), leaving std's allocator about 60 KB of heap: the product golden printed NAN and 32 of 73 tests failed. The link args change only the memory section; std's allocator keeps its memory.grow instruction (see the fixed-arena allocator recipe). No -Z flag is needed.
- **In si-rpg-engine:** solver/build.mjs (RUSTFLAGS) and solver/.cargo/config.toml, T3 pin 2. Measured on a copy of solver/: no args gives initial 18 pages and no maximum; --no-growable-memory gives 18/18; --initial-memory = --max-memory = 4194304 gives 64/64; the memory.grow count stays 1 in all three. PR #44 fixes 256 pages with the two explicit args in both config.toml and build.mjs.

### Keep T4 slope and ledge cases off the controller's comparisons: >= at 45 degrees, nudge creep, speed-set snap
`✅ solid` · ✓ verified · ✔ compiles as claimed · Rust rapier3d-f64 0.35.3

**is_wall is angle >= max_slope_climb_angle and is_nonslip_slope is angle <= min_slope_slide_angle; snap needs a grounded start and translation.up <= 0; the 1e-4 normal nudge lifts a walker blocked on a 46 degree slope by about 6e-5 per quantum; the snap-or-fall threshold moves with speed (0.2105, 0.2097, 0.2058 at 0.4, 1, 2 u/s).**

Past a ramp's top the walker walks off and its end height drops back to the floor, so assert the maximum height or give the ramp a landing.
