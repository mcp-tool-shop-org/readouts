## New: agent-tooling-knowledge

AI agents now do real work in the studio's pipelines, and the tools that run them have behaviour you only learn by
measuring. This new knowledge base records it. It's public from wave 1, and nothing loads without a re-check: every
finding was re-checked on 2026-10-20, most by a live re-probe in a Docker sandbox, so the wave is smaller than the bench
notes it comes from.

**A deny rule isn't a wall** (Claude Code 2.1.197). With reading a folder denied, direct reads are refused, but a Grep
started one folder up still lists the names of the files inside. Which starting points leak depends on how the rule is
written:
- `Read(~/**)`: a search at the home folder itself leaks too;
- `Read(//X/**)`, an absolute path: a search at X is refused;
- `Read(/X/**)`, with one leading slash: the rule is read relative to the settings source, so it protected nothing.

On 2.1.280, the search from above came back empty for the absolute form, the only one tested there. Claude Code's
permissions page already calls these rules "best-effort", so this is documented behaviour, measured. What did keep the
agent out was the operating system. In the harness's own containment probe of 2026-10-13 and 10-14, whose reports were
recovered and re-checked on 10-20, a separate user with the private folders closed to it reached nothing: 29 of 29
attempts, 0 leaks.

**The first headless turn can start before an MCP server connects** (2.1.197). Sent at once, the first message found
the server still `pending` and got none of its tools; after a 10-second hold, all 7. On 2.1.280 the server was
connected at the first turn in 3 of 3 starts.

**Docker Sandboxes keep the plan's sign-in on the host.** Inside the sandbox there are only placeholder tokens, and a
sandbox can reach a host Ollama listening on 127.0.0.1 through `host.docker.internal`.

**NeMo Relay's local traces carry identity.** Its event file held the signed-in account's email address even with full
payloads switched off. Treat trace files as private.

The newsletter of the studio's research bench tells the deny-rule story at length, including the two times it was read
wrong before both rule forms were measured side by side:
[rnd issue 17](https://mcp-tool-shop-org.github.io/rnd/newsletter/issue-17/).

## Promoted from the research bench

Each of these came from [rnd](https://github.com/mcp-tool-shop-org/rnd) through the promotion queue, and each was
re-read against its own receipts on the way in.

### training-knowledge: a critic's seed variance, and a judge scored both ways (wave 18)

- **A learned critic is mostly seed.** One seed suggested that a fine-tuning step before ASPIRE badly hurt the critic.
  Under the three-seed rule set in advance, the effect wasn't reliable, and the control critic itself ranged from
  0.425 to 0.866 across seeds. Training loss didn't predict accuracy. Use three seeds per arm, and never pick a critic
  by its loss.
- **Read a judge from both orders.** Qwen2.5-32B, as a single A/B choice, picked A on all 127 pairs when the strong
  answer was A. Averaging its option probabilities over both orders lifted it to 0.886 on 149 fresh pairs and 0.898 on
  the 127, from 0.685 and 0.701 as single choices.
- **A correction on the way in:** the bench copy gave 0.685 as the single-choice baseline for both sets. It's 0.701 on
  the 127; the bench is fixed too.

### tensor-engine-knowledge: CUDA 13.4, from NVIDIA's own pages (wave 19)

The bench entry rested on a slide from NVIDIA's livestream. A slide previews a release; it isn't one. So each row here
comes from the CUDA Toolkit 13.4 release notes or the nvcc documentation:
- memory-pool IPC on Windows WDDM for stream-ordered allocations, which matters to a WDDM card like the studio's;
- the driver no longer bundled with the toolkit: on Windows since 13.1, on Linux since 13.4;
- cuda-checkpoint writing to persistent storage;
- nvcc's `--fmax-errors` and `--Wconversion`.

Eight items that only the slide states stay on the bench.

[Wave 19's record](https://github.com/mcp-tool-shop-org/readouts/blob/main/tensor-engine-knowledge/waves/wave-19-rnd-cuda-13-4/dispatch.md)

### model-knowledge: give a local model room under Claude Code (wave 19)

Claude Code's own system prompt and tools take about 25,000 to 28,000 tokens of Ollama's default 32,768-token
context, leaving a local model almost nothing to work with. nemotron-3.5-lightning, in a derived model with
`num_ctx 131072`, answered 11 of 12 on a small code-reading set in its best round, and 9 of 12 in each of two later rounds; at the default context, a halted early run got 1 of 4.
It's four tasks, one CLI version and one model: a practical note, not a benchmark. The memory figure, near 28 GB on
the RTX 5090, is marked unverified, because its log wasn't kept.
