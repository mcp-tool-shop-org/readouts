## Promoted from the research bench

Two promotions today, both into xrpl-knowledge, from [rnd](https://github.com/mcp-tool-shop-org/rnd). Each loads only
what was read against its source.

### xrpl-knowledge: what live Testnet runs teach about AMMs (wave 11)

The studio's [xrpl-lab](https://github.com/mcp-tool-shop-org/xrpl-lab) teaches the XRP Ledger by having learners send
real transactions on the public Testnet. Running its 2.6.0 AMM lessons live, four times, turned up four things the
documentation alone doesn't make obvious. Each is added as a gotcha to a row the knowledge base already had; there are
no new rows.

- **AMMCreate's fee is the owner reserve increment, 200,000 drops (0.2 XRP) on Testnet at the time.** That's in
  xrpl.org's reference, but its consequence is easy to miss. A pool funded from a single 100 XRP faucet grant failed
  with `tecUNFUNDED_AMM`: after the base reserve, the trust line's reserve and that fee, only about 98.6 XRP was
  spendable. The lesson succeeded with a 25/25 pool.
- **When the only liquidity provider withdraws everything, the AMM is gone.** After a full withdrawal
  (`tfWithdrawAll`), `amm_info` answered `actNotFound`: the pool had been deleted, not emptied.
- **A short client timeout can lose a transaction's hash.** When a result is held (a `ter` code), xrpl-py's
  `submit_and_wait` keeps waiting until the transaction's `LastLedgerSequence` passes, about 20 ledgers or 80 seconds.
  A timeout shorter than that throws away the hash and the preliminary result, so there's nothing left to look up.
  Signing the transaction before submitting it keeps the hash.
- **A faucet reply isn't proof of funding.** An issuer's AccountSet sent before the funded account was on a validated
  ledger never validated, and the AMM steps after it were held (`terNO_RIPPLE`, `terNO_AMM`). Wait for the validated
  balance before the next transaction.

These were measured on Testnet, against the network as it was on 2026-10-20. The fixes xrpl-lab made between runs are
in its pull request #19; the outcomes come from the run receipts.

### xrpl-knowledge: paying from AI agents over XRPL (wave 12)

Three new rows on tools for software agents that pay over the XRP Ledger. Each was read at its own source. None of
them has been run on the studio's rig.

- **x402's exact payment scheme for XRPL.** x402 is an open protocol for paying for a web request over HTTP. Its specification has had an XRPL scheme since 2026-07-03: the payer signs an XRPL Payment, and a
  facilitator submits it.
  - **The gotcha:** the scheme can't sponsor fees. A design where the server or the facilitator pays the network fee
    doesn't fit it.
  - The protocol is now stewarded by the x402 Foundation at the Linux Foundation. The launch was announced on
    2026-04-02, and the Foundation began operating on 2026-07-14.
- **Ripple's XRPL AI Starter Kit.** MCP servers and Claude skills for building on the XRPL with AI assistants.
  - **The gotcha:** the kit has grown since Ripple's 2026-06-09 post. The post names one docs MCP server and two
    skills; xrpl.org's AI-tools page now lists two MCP servers (the docs server and one at xrpl.org) and three skills
    (wallet, payments and trading). Treat that page as the current list.
- **Ripple's xrpl-mpp-sdk, in beta.** It adds the XRPL as a payment method for the Machine Payments Protocol (MPP),
  which Stripe announced with Tempo on 2026-03-18.
  - **The gotchas:** it's a beta (0.1.0-beta.4 when read), so expect breaking changes. And Stripe's announcement doesn't
    mention the XRPL: the XRPL support comes from Ripple's SDK.
  - The SDK is Apache-2.0. The MPP specs are CC0; the rest of that repository has its own licence.

Left out on purpose: adoption figures for x402 on the XRPL. The ones reported so far come from secondary outlets, and
no primary source confirms them yet.
