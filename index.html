How each KB decides — the decisive axis per knowledge base

  • blender-knowledge — currency — the Blender-4.x verdict (solid / plausible / shaky / blender3_stale / wrong).
  • docker-knowledge — The knowledge base behind the gpu-container product — how to package, measure, and place models honestly on one GPU.
  • godot-knowledge — currency — the adversarial Godot-4 verdict (solid / plausible / shaky / godot3_stale / wrong).
  • model-knowledge — commercial license (a LoRA/asset inherits its base model's license) + fits 32 GB VRAM.
  • rust-knowledge — two verdicts: currency against Rust 1.98.1 / edition 2024 / the pinned crates (adversarial retrieval verifier), and every code check compiled and run by the pinned compiler (a non-model verifier).
  • sprite-motion-knowledge — how do I make an approved 2.5D JRPG sprite walk, swing, idle, and die — without melting the character or detaching the weapon — and how well does this exact approach hold up?
  • sprites-knowledge — how do I turn a concept-art frame into a finished game sprite, and how well does this exact approach work on this exact rig?
  • tensor-engine-knowledge — native-Windows Blackwell survivability + commercial license (a LoRA/app inherits its engine's license).
  • training-knowledge — single-RTX-5090 training viability + reproducibility (fits 32 GB, commercial-clean output, complete replay provenance) — which method/recipe/data/eval you feed the engine and why, not which weights or which software.
  • vocology-knowledge — score-lock — honor MIDI notes + lyrics as hard constraint vs mixed-song generator; secondary commercial-safe weights
  • xrpl-knowledge — network_status — is this feature ACTUALLY enabled on XRPL mainnet right now (vs amendment-pending / devnet-only / deprecated), and which standard/library is current — plus which of the four build-focus tracks (game economies / NFT assets / payments / identity-compliance) it serves.
Every fact in every KB carries a wave id and a verified flag; sources retrieval-checked against the live page. Cross-family seats are per-wave — see each wave's receipt.
