### Armature setup — adding bones and structuring a character rig · `✅ solid` · Blender 4.x (stable across 4.0–4.4+)
**An Armature object holds bones; bones define the skeleton hierarchy. In Edit mode you add, extrude, and parent bones. Bone roll, head/tail position, and the Connected flag control how bones chain. Rest pose is set in Edit mode; Pose mode is where animation and constraints live.**
- **How:** 1. Add → Armature (single bone) in Object mode; Tab into Edit mode to shape it. 2. Select bone tip, E to extrude a child bone; bones auto-connect (Connected). 3. Name each bone in the Bone properties panel. 4. Use Ctrl+R to roll a bone so its local Y aligns with the limb axis. 5. Mirror-edit with X-Axis Mirror enabled (Armature header toggle) — bones named Bone.L are mirrored as Bone.R. 6. Parent without Connect (uncheck Connected) for floating control bones (IK targets, root). 7. In Object mode Ctrl+A → Apply All Transforms on the armature and mesh BEFORE skinning so rest-pose transform is clean. 8. In Pose mode Alt+G / Alt+R / Alt+S clears pose back to rest; Ctrl+A applies pose as new rest pose if needed.
- **Gotchas:** Do NOT apply scale or rotation after skinning — vertex weights are bound to the rest pose; applying transforms post-skinning shifts the mesh.; Bone naming convention Bone.L / Bone.R enables symmetry operations and correct glTF left/right bone recognition in some engines.; Connected bones cannot be freely repositioned at the head; uncheck Connected if the bone needs to be a floating target.; Always build the rig in a neutral T-pose or A-pose; Automatic Weights fails badly if bones overlap or are inside geometry.
- **For Studio:** Build a humanoid rig for a 2.5D RPG character: spine chain, limbs with IK, face bones. The clean armature hierarchy is what glTF exports as the skeleton — naming and hierarchy here determines bone names in Godot/UE5.

### Bone Collections (Blender 4.0+) — replace bone layers · `✅ solid` · Blender 4.0+ (nested collections: 4.1+)
**Blender 4.0 replaced the old 32-layer system and Bone Groups with named Bone Collections owned by the Armature. Collections support nesting (4.1+), show/hide per-collection, solo visibility, and per-bone custom colors. This is the current organization system; tutorials referencing 'armature layers' or 'layer buttons' are pre-4.0 and stale.**
- **How:** 1. In Edit or Pose mode, select bones, press M to open the Assign to Collection menu or create a new collection on the spot. 2. Shift+M assigns a bone to multiple collections simultaneously. 3. Manage collections in the Armature Properties → Bone Collections panel: rename by double-clicking, reorder by drag. 4. Eye icon = toggle visibility; star icon = solo that collection. 5. Nest a collection by right-clicking → 'Add Child Collection', or drag the name onto another collection (Blender 4.1+). 6. Bone colors: select bone(s) → Bone tab → Viewport Display → Bone Color (Edit mode) or Pose Bone Color (Pose mode); pick a palette color or set a custom color. Colors replace the deprecated Bone Groups color system. 7. Old.blend files opened in 4.0+ auto-convert layers to collections named 'Layer 1' … 'Layer 32'.
- **Gotchas:** Any Python script or addon that calls armature.layers or bone.layers will break in 4.0+; the API moved to armature.collections and bone.collections.; Bone Groups are removed; their per-group colors are replaced by per-bone Bone Colors. If you open a 3.x file, Bone Groups are silently dropped — re-apply colors after upgrade.; Collections are visible in all modes (Edit, Pose, Object) unlike old layers which had separate visibility states per mode in some addons.; The show-only-selected-collection feature is the Eye icon per row; there is no longer a single 'all-layers visible' toggle — use the armature header visibility instead.
- **For Studio:** Organize a game character rig: collections for DEF (deform), CTR (controls), IK targets, face bones, root. Toggle visibility during weight painting to isolate deform bones. Use bone colors to color-code limb sides (left=blue, right=red) for fast pose-mode selection.

### Drivers — basics and bone-rotation-to-shape-key example · `✅ solid` · Blender 4.x (drivers API stable; no breaking changes in 4.0–4.4)
**Drivers attach an F-Curve expression to any property, making one value automatically control another. The canonical game-rig use case is a bone rotation controlling a shape key (corrective morph for elbows/shoulders, or facial expression). Drivers live in Graph Editor → Drivers mode and can reference bone transforms, object properties, or custom properties.**
- **How:** BASIC DRIVER SETUP: 1. Right-click any property in the Properties panel → Add Driver (or Ctrl+D on compatible fields). The property turns purple. 2. In the Driver Editor (Graph Editor header → switch to Drivers), select the driven property. In the sidebar Driver tab: set Type = 'Averaged Value'; add a Variable. 3. Variable Type = 'Transform Channel'; Object = your armature; Bone = the controlling bone; Type = 'X Rotation'; Space = Local Space. 4. The driver expression `var` now passes the raw bone rotation value (in radians) to the driven property. BONE-TO-SHAPE-KEY EXAMPLE: Drive a shape key value from a forearm bone X rotation. Target property = shape key value (0.0–1.0). Driver variable = forearm bone local X rotation. Set expression = `var / (pi/2)` to map 0°→0 and 90°→1. Or add a modifier curve in the Driver Editor to remap the range non-linearly for corrective shapes. CUSTOM PROPERTIES: In Pose mode, select a bone, Object Data Properties → Custom Properties → New. Name it 'ik_fk_switch' (float 0–1). Then use this property as a driver variable to blend constraint influences — a common IK/FK switch pattern.
- **Gotchas:** Rotation values in drivers are always in RADIANS, not degrees. 90 degrees = pi/2 ≈ 1.5708. Use the constant `pi` in driver expressions or use Scripted Expression type to import math.; Drivers that reference bone local rotation must set Space = 'Local Space'; 'World Space' includes the armature's object transform and gives wrong values if the armature is moved.; Shape key drivers referencing a bone from a DIFFERENT object (e.g. mesh drives from armature) need the variable Object set to the armature object, not the mesh.; Cyclic drivers (A drives B drives A) cause a red 'Cyclic Dependency' warning and break. IK + driver combinations can trigger this; reorganize the dependency chain.
- **For Studio:** Corrective shape keys (elbow and shoulder collapse fixes) are critical for game characters visible in close-up. Bone-to-shape-key drivers make these automatic during animation. Custom property sliders on control bones give animators IK/FK blend and face pose controls inside a single rig.

### Exporting a rigged + animated character to glTF for a game engine · `✅ solid` · Blender 4.x (exporter is built-in; settings have been stable across 4.0–4.4)
**The built-in glTF 2.0 exporter (File → Export → glTF 2.0) handles skinned meshes and skeletal animations. Correct settings are essential: skinning, animations, and sampling must all be enabled; IK must be baked; deformation-only bones should be filtered. The result is a.glb (binary, preferred) or.gltf +.bin + textures.**
- **How:** PRE-EXPORT CHECKLIST: 1. Apply All Transforms to mesh and armature (Ctrl+A → All Transforms) — unexplained root-level scaling/rotation causes misalignment in engines. 2. Check Armature modifier stack: Armature modifier must be FIRST (above Subdivision Surface etc.). 3. Uncheck 'Preserve Volume' on the Armature modifier — game engines use linear blend skinning, not dual quaternion; Preserve Volume causes visible mesh divergence. 4. Every vertex must be assigned to at least one bone vertex group. Run Weights → Clean to remove near-zero weights; run Weights → Limit Total (4) for the 4-bone-per-vertex max. 5. Push all animation Actions to NLA tracks; rename tracks to desired clip names. EXPORT SETTINGS (File → Export → glTF 2.0 →.glb): Include section: check 'Skinning'. Animation section: check 'Animations'; sampling: leave 'Always Sample Animations' ON (converts IK/drivers to baked keyframes per frame — required if you use IK constraints); set Sampling Rate (default 1 = every frame; set to 2 for 30fps animations exported from 60fps projects). Check 'Export Deformation Bones Only' to strip IK targets and pole-target bones from the skeleton. Choose 'Export' mode = 'Scene' or per-object depending on your pipeline. POST-EXPORT VERIFY: Import the.glb into Godot 4 or UE5 and check bone names, animation clip list, and skinning deformation. Animation clip names in the engine should match your NLA track names.
- **Gotchas:** Objects parented to bones via 'Object offset' (not vertex skinning) have their rotation/scale offset dropped in glTF. Use vertex-group skinning for all deforming meshes.; Drivers that control bone positions are NOT automatically baked by 'Always Sample Animations' in all cases — test export and verify driven bones animate correctly. May need a manual Bake Action step first.; glTF stores animation at 1000 ticks/second internally, but Blender re-samples from your scene frame rate. If the engine shows slightly off-timing, check that your scene FPS matches the engine target (24, 30, or 60).; Multiple NLA tracks on the SAME armature are each exported as separate named glTF animations. Muted tracks still export; delete strips you do not want in the final file.; The 'Export Deformation Bones Only' option bakes the IK at export time, so the game engine receives pure FK data — no IK runtime needed in the engine.
- **For Studio:** Final step in the RPG character pipeline: Blender.blend →.glb → Godot 4 AnimationTree or UE5 AnimBP. A clean export has: one.glb per character, named animation clips (Idle, Walk_N, Walk_S, Attack_Melee, Hit_Flinch, Death), deform-only skeleton (~40–60 bones for humanoid), and a 4-influence-max skin.

Preserve Volume = dual quaternion point confirmed by multiple game engine export guides. | cross-family (deepseek-v3.1): confirmed — glTF export workflow and settings are correct and stable across Blender 4.x, including deformation bones filtering and animation baking. ### Rig constraints: IK, Copy Rotation/Location, Track To, Child Of · `✅ solid` · Blender 4.x (stable API; no breaking changes to these constraints in 4.0–4.4)
**Constraints drive bone behavior procedurally in Pose mode. IK (Inverse Kinematics) is the core constraint for limb rigs — it rotates a chain of bones to reach a target point. Copy Rotation/Location, Track To, and Child Of handle control hierarchies, look-at rigs, and dynamic parent relationships. All live on the Bone Constraint Properties panel in Pose mode.**
- **How:** IK SETUP: 1. Create a chain of bones (e.g. thigh → shin → foot). Slightly bend the chain in the knee direction in Edit mode — a perfectly straight chain causes IK solver ambiguity. 2. Add a separate IK target bone (a non-connected, non-deforming CTR bone) positioned at the foot. 3. In Pose mode select the shin bone (last bone before the end effector), Bone Constraint Properties → Add Constraint → Inverse Kinematics. Set Target = the armature, Bone = the IK target bone. Set Chain Length = 2 (thigh + shin). 4. Add a Pole Target bone at the knee front position; in the IK constraint set Pole Target = armature, Pole Bone = that bone. Adjust Pole Angle (usually -90° or 90°) until the knee points the right direction. COPY ROTATION: Select the bone that should follow, Add Constraint → Copy Rotation, target the driver bone. Use Space = Pose Space for predictable local-relative behavior. TRACK TO: Used for look-at rigs (eyes). Select eye bone, Track To constraint, Target Object = pupil target, Track Axis = -Z (or Y depending on bone orientation), Up = X. CHILD OF: Creates a dynamic parent switch; useful for held objects. Add Child Of on the prop bone, set Influence to 0 (not parented) or 1 (parented). Set Inverse button bakes the current offset as the 'rest' relationship.
- **Gotchas:** IK chains with a length of 0 run the solver up the ENTIRE parent chain to the root — almost never what you want for limbs. Always set Chain Length explicitly.; Pole Target Pole Angle is in degrees; common values are 0, 90, -90, 180. If the knee/elbow flips on the wrong side, flip the Pole Angle by 180.; IK constraints do NOT export directly to glTF — the game engine handles IK internally. You must bake the IK animation to FK keyframes before glTF export (Object → Animation → Bake Action, or enable 'Export Deformation Bones Only' + sampling in the glTF exporter).; Child Of constraint requires clicking 'Set Inverse' after setting the target to correctly offset the parent relationship, otherwise the bone jumps to the target's origin.
- **For Studio:** All humanoid game characters need IK legs and arms. Copy Rotation is used for foot roll setups. Track To handles eye rigs. Child Of allows a sword to snap to a hand bone vs. a scabbard bone via driver-controlled influence.

### Skinning: Automatic Weights + weight painting cleanup · `✅ solid` · Blender 4.0+ (keymap changed from 3.x)
**Skinning binds a mesh to an armature so bones deform it. 'Parent With Automatic Weights' (Ctrl+P) runs Blender's bone heat algorithm to assign vertex weights to vertex groups named after bones. Weight painting then cleans up bad influences. This is the standard game-character skinning path.**
- **How:** 1. In Object mode select the MESH first, then Shift-click the ARMATURE (armature must be active/orange). 2. Ctrl+P → 'With Automatic Weights'. Blender creates one vertex group per bone and fills weights automatically. 3. If you get 'Bone Heat Weighting: failed to find solution for one or more bones': scale the mesh/armature up (models that are too small or have interior overlapping geo cause this), fix ngons/non-manifold edges, or manually assign those bones. 4. Enter Weight Paint mode (Tab from object mode with mesh selected, or switch from header). 5. In Blender 4.0+: select bones with Alt+Click (changed from Ctrl+Click in 3.x); Ctrl+Click now removes weight; Shift+Click blurs. 6. Paint with Draw brush to add weight, Ctrl+draw to remove. Enable Auto Normalize (sidebar → Options → Auto Normalize) so weights always sum to 1. 7. Useful cleanup operators in Weight Paint mode: Weights → Smooth (blur across surface), Normalize All, Clean (remove near-zero weights). 8. For a game character, keep max 4 bone influences per vertex (Weights → Limit Total, set to 4). glTF supports max 4 influences per vertex by default.
- **Gotchas:** Blender 4.0 changed weight paint bone selection from Ctrl+Click to Alt+Click. Old tutorials using Ctrl+Click workflow will confuse newcomers on 4.x.; Auto Normalize must be ON during painting for glTF skinning; engines expect weights summing to 1.0 per vertex.; Automatic Weights creates groups for ALL bones including IK targets and pole targets. These get empty weights but if you export with 'Export Deformation Bones Only' you can strip them at export time rather than manually deleting groups.; The Armature modifier must be above the Subdivision Surface modifier in the stack, otherwise subdivision changes the vertex count after weighting.
- **For Studio:** Standard path for all game characters: auto-weight provides 80% of the work; weight paint cleans up elbow/shoulder collapsing, hip bleed, and finger separation. The Limit Total step enforces the 4-bone-per-vertex cap required for most game engines.

### Slotted Actions (Blender 4.4) — new animation data model · `✅ solid` · Blender 4.4+ (this feature does NOT exist in 4.3 or earlier)
**Blender 4.4 introduced Slotted Actions, a fundamental change to how animation data is stored. Previously one Action stored F-Curves for exactly one data-block (one armature, one object). In 4.4, a single Action can hold multiple 'slots' — each slot is an independent bag of F-Curves — so one Action can simultaneously animate an armature, its object transform, and a material. Old files are auto-migrated to 'Legacy Slots'. This is the current animation data model in 4.4+.**
- **How:** WHAT CHANGED: In 4.4 the Action Editor shows a Slots panel (usually a small header area). Every animatable data-block that references an action is assigned to a specific slot within it. When you key a bone, the F-curves go into the slot assigned to that armature data-block. WORKFLOW FOR A CHARACTER: For typical character animation (just animating bones), you get one slot per armature — the experience is nearly identical to pre-4.4 except there's a visible slot name. No workflow change is required for single-armature single-action animations. MULTI-OBJECT ACTIONS: New capability: assign multiple objects to different slots of the same Action via the Action Editor → Action → Merge Animation (merges selected objects' active actions into one). Or manually: in the Action Editor, select an action in one object, then assign the same action to another object and choose a different slot. SEPARATING SLOTS: Action Editor → Action → Separate Slots splits all slots of an Action into individual Actions. Useful if you accidentally merged or want to split a combined action back out. LEGACY FILES: Opening a 3.x or 4.3.blend in 4.4+ auto-creates a 'Legacy Slot' per action. These work identically to old actions.
- **Gotchas:** CRITICAL BACKWARD COMPAT: Saving a file with multiple-slot Actions in 4.4 and opening it in Blender 4.3 or earlier: only the FIRST slot is visible; all other slots and their F-curves are LOST when the older Blender saves the file. Do not round-trip multi-slot Actions through Blender < 4.4.; Slotted Actions change some Python API paths — addon code that directly manipulates action.fcurves may need updates if it was written for pre-4.4.; For glTF export in 4.4: slots within a single action are NOT exported as separate glTF animations. The glTF exporter still operates at the NLA-track/action level. If you want separate glTF clips, you still need separate Actions (or separate NLA tracks), same as before.; The automatic migration to Legacy Slots is lossless — legacy-slot actions behave exactly as old-style actions. No manual intervention required when upgrading projects.
- **For Studio:** For a game studio: the practical impact is minimal for single-armature character animation. Most value comes when animating a character + their equipment (sword, shield) in one Action using separate slots. Be aware of the Blender-version lock: any collaborators must use 4.4+ once multi-slot Actions are used.

### Animation system: keyframes, Action Editor, NLA editor · `▸ plausible` · Blender 4.0–4.3 (pre-slotted-actions; see recipe 'slotted-actions-4-4' for 4.4 changes)
**Blender's animation system centers on Actions (collections of F-Curves). You create keyframes in Pose mode; they are stored in the active Action. The Action Editor (Dope Sheet → Action) shows timing. The NLA (Non-Linear Animation) editor lets you layer and blend multiple actions, and is the mechanism by which glTF exports multiple named clips from one armature.**
- **How:** KEYFRAMING: In Pose mode, pose the character; press I → Rotation (or Location/Scale/LocRotScale) to insert keyframes on selected bones. Keyframes appear as yellow diamonds in the timeline. Alt+I removes a keyframe on the current frame. Auto-keying (the red dot in the timeline header) automatically keys any changed property when playback is stopped. ACTION EDITOR: Open a Dope Sheet editor, switch to Action mode from the header. The current action is shown in the action name field. Click the + to create a new action, or the datablock dropdown to switch. Each named action = one animation clip (Idle, Walk, Attack, etc.). Push Down button moves the current action to an NLA strip and frees the action slot (so you can start a new one). NLA EDITOR: Each action pushed down appears as a strip on a track. Strips can be scaled (length), offset (start frame), blended. For glTF multi-animation export: push down ALL actions to NLA tracks via Action Editor → Push Down (or Stash). The glTF exporter exports each NLA track as a separate named glTF animation. Rename NLA tracks to control exported clip names. CLIP ORGANIZATION: Use start/end frame ranges per action; keep actions on clean frame ranges starting at 0 or 1.
- **Gotchas:** An action that is NOT pushed down to an NLA track and is NOT the active action will NOT be exported by the glTF exporter. Always push down or stash every action you want in the export.; NLA track names become the glTF animation names. Default names are 'NLATrack' or '[Action Stash]'; rename them to 'Idle', 'Walk', etc. before export.; Muting an NLA track (M key in NLA editor) prevents it from playing in Blender but it still exports. To exclude from export, delete the strip.; The Action Editor 'Fake User' button (shield icon) prevents an unused action from being deleted on file save — use it for actions not yet pushed to NLA.
