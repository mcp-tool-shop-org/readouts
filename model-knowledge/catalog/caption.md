### JoyCaption Beta One · `recommended` · frontier
The de-facto community captioner purpose-built for diffusion training sets. 8B LLaVA-style VLM (Llama 3.1 LLM + SigLIP2-so400m vision encoder) that writes natural-language captions in multiple selectable modes (Descriptive, Straightforward, Training Prompt, Booru-tag-list, Social-media). Uncensored and explicitly built to NOT refuse, which is the decisive practical advantage over corporate VLMs when captioning stylized/edgy game art or NSFW reference. ComfyUI: 1038lab/ComfyUI-JoyCaption (batch + GGUF) is the standard node; also runs in LM Studio/Ollama/llama.cpp via GGUF. ~17 GB VRAM in BF16, runs with huge headroom on 32 GB; 8-bit/4-bit/GGUF quants exist for batch throughput.
- **Dev:** fpgaminer (fancyfeast) · **Arch:** LLaVA (Llama 3.1 8B + SigLIP2-so400m-patch14-384) · **Params:** 8B · **Released:** 2025-05 · **Disk:** 17.0 GB · **VRAM:** min 8.0 GB / rec 18.0 GB
- **License:** Apache-2.0 — commercial: **yes**. Confirmed Apache-2.0 on the GitHub repo. Author's stated mission is a free, open, unrestricted model for training diffusion models — captions it produces carry no usage strings. Best commercial-safety profile of any natural-language captioner here.
- **Best for:** dataset captioning (both, fit 5) ; training-prompt generation for SDXL/Flux LoRA (game-asset, fit 5) ; uncensored captioning of stylized/mature art (game-asset, fit 5)
- **Speed/notes:** BF16 ~1-3 s/image on a 5090; use the 8-bit/nf4/GGUF quants for large-batch dataset runs. vLLM serve with prefix caching for bulk captioning.

### Camie-Tagger v2 · `recommended` · strong
A genuinely-new (2025) booru tagger that meaningfully out-scopes the WD family: 70,527 supported tags (vs ~10k for WD), spanning general (30.8k), character (27k), copyright (5.4k), artist (7k), meta, rating and year. Trained on a filtered Danbooru-2024 subset, micro-F1 67.3% / macro-F1 50.6% — both above the WD v3 numbers, partly because many counted 'false positives' are actually correct tags missing from Danbooru ground truth. v2 switched to a ViT backbone and cut params 66% (424M->143M) while improving accuracy. The reach-for-it case is fine-grained artist/copyright/character tagging on Illustrious / NoobAI LoRA sets where WD's vocabulary runs out. The one caveat in this lane: weights are GPL-3.0 (copyleft), so it's 'conditional' rather than cleanly permissive.
- **Dev:** Camais03 · **Arch:** Vision Transformer backbone (86.4M) + cross-attention refined-prediction head · **Params:** 143M · **Released:** 2025 · **Disk:** 0.6 GB · **VRAM:** min 1.0 GB / rec 2.0 GB
- **License:** GPL-3.0 — commercial: **conditional**. Weights are GPL-3.0 (copyleft). The copyleft obligation attaches to redistributing or modifying the MODEL, not to its tag output — running it as an inference tool to caption your own images does not make the dataset or the trained LoRA a GPL derivative (mere program output is not a derivative work). So it is practically safe for commercial game-asset tagging; the 'conditional' flag exists only because bundling/shipping/modifying the weights themselves would trigger GPL obligations.
- **Best for:** Fine-grained booru tagging for Illustrious/NoobAI LoRAs where WD's ~10k vocab is too coarse (needs artist/copyright/character breadth — 70k tags) (game-asset, fit 5) ; High-recall tag indexing of a large anime/illustration reference library (both, fit 4) ; Commercial pipeline where you must redistribute the tagger weights (GPL-3.0 copyleft applies) (game-asset, fit 2)
- **Speed/notes:** 143M ViT with gradient-checkpointing support; <2 GB VRAM, fast batched inference. safetensors + ONNX. Heavier tag head than WD but still classifier-speed (well under a second/image batched).

### CapRL-InternVL3.5-8B · `recommended` · strong
An RL-tuned dense-caption specialist and a strong genuinely-new (Oct 2025) addition to this lane. CapRL is the first application of Reinforcement Learning with Verifiable Rewards to open-ended captioning: captions are rewarded by how well a text-only model can answer visual questions using ONLY the generated caption, which pushes the model toward comprehensive, low-hallucination, structured prose (fine-grained objects, attributes, OCR, relations, events). Built on InternVL3.5-8B as policy; reported to beat Qwen2.5-VL-72B on captioning quality at 8B. This is the PROSE/natural-language captioner for Flux / Qwen-Image LoRA datasets (and excellent for marketing alt-text and product descriptions) — the complement to the WD/Camie booru taggers. ICLR 2026 paper. Confirmed downloadable safetensors at internlm/CapRL-InternVL3.5-8B.
- **Dev:** InternLM (Shanghai AI Lab / OpenGVLab) · **Arch:** InternVL3.5-8B (ViT vision encoder + Qwen3 LLM), RLVR-tuned · **Params:** 8B · **Released:** 2025-10-15 · **Disk:** 9.0 GB · **VRAM:** min 18.0 GB / rec 24.0 GB
- **License:** Apache-2.0 — commercial: **yes**. Model WEIGHTS are Apache-2.0 (verified: the InternVL3.5-8B base uses Qwen3, also Apache-2.0, so there is NO Qwen-license inheritance problem on this variant — unlike Qwen2.5-based models). Fully commercial-safe for both game-asset captioning and marketing. Caveat to note: the CapRL training datasets (CapRL-2M, CapRL-QA-75K) are CC-BY-NC-4.0, but a dataset license does not bind users of the released weights or the captions you generate — only someone re-training on those specific datasets is affected.
- **Best for:** Dense prose captioning for Flux / Qwen-Image / SD3-style LoRAs that train on natural-language captions (not booru tags) (game-asset, fit 5) ; Marketing alt-text, product descriptions, detailed image descriptions with OCR + structured detail (marketing, fit 5) ; Booru-tag string output for SDXL/Illustrious (wrong tool — use WD or Camie for tags) (game-asset, fit 1)
- **Speed/notes:** Full 8B VLM, ~9 GB weights at BF16 + KV cache; runs comfortably on the 5090's 32 GB via vLLM (--gpu_memory_utilization=0.95). Prose-caption throughput is on the order of ~1-3 s/image (VLM generation, not classifier-speed) — slower than the taggers but vLLM batching helps for dataset-scale jobs.
